# 追踪卡流转与终检入库操作手册

适用实验分支的批量生产与研发产出。业务规则见[生产执行](../../apps/api/src/modules/production/docs/database/execution-traceability-quality.md)，验收状态见[路线图](../roadmap.md#追踪卡工作台实验待验收)。

## 准备与日常流转

1. 在系统管理的“现场人员”维护登记人员，选择产线 production 或质检 quality 分组。现场人员无需登录账号；操作账号仍需相应页面和写入权限。
2. 批量任务选择路线，最后启用步骤作为终检；中间需要检查时直接加入检查工序。任务明确开工后，在工序追踪创建追踪卡，登记该盘数量并打印标签。
3. 员工工作台选择任务、当前工序与登记人员，扫码记录到站。首站只记到站，下一站扫码时记录上一站完成；中间检查同样办理，无需另点“检查完成”。
4. 数量改变时在追踪卡更正数量并填写原因，先前工序记录的数量不改写。发现问题可登记到该盘已到过的工序；普通异常可继续流转，暂停异常先处理再继续。

## 终检与结束

末道到站后，由质检组人员核对该盘的全部异常及实际可用数量。可先新增终检发现的异常，处理完全部异常后再确认最终产出。每盘只确认一次，不支持分批放行。正数即时成为可用库存，零只完成该盘；提交前核对数量，重复点击不会重复入库。

研发没有追踪卡及工序，在任务中一次确认产出。全部工作处理完后明确结束任务；未完成卡和未履约资源按[结束规则](../../apps/api/src/modules/production/docs/database/production-termination.md)处理，已产出及库存事实保留。

## 追溯与补差

工序追踪统一查看任务各站、追踪卡到站及数量变化、异常处理和最终产出；成品库存的入库来源可查看对应任务、入库单和原始流水。任务详情通过同一追踪入口查看执行，不维护第二套报工详情。

入库后发现数量错误，用“其他入库／其他出库”在相应成品批次记录补差及原因。库存反映调整后的实际量，历史产出仍是终检当时确认量。现有盘点管理只支持物料，成品数量修正使用其他出入库。
