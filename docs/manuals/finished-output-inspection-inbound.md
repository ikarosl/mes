# 追踪卡流转与终检入库操作手册

适用实验分支的批量生产与研发产出。业务规则见[生产执行](../../apps/api/src/modules/production/docs/database/execution-traceability-quality.md)，验收状态见[路线图](../roadmap.md#追踪卡工作台实验待验收)。

## 准备与日常流转

1. 在系统管理的“现场人员”维护统一的登记人员列表，无需设置产线或质检分组。现场人员无需登录账号；操作账号仍需相应页面和写入权限。
2. 批量任务选择路线，最后启用步骤作为终检；中间需要检查时直接加入检查工序。任务明确开工后，在员工工作台首工序创建追踪卡，登记该盘数量并打印标签。
3. 员工工作台选择任务、当前工序与登记人员，扫码记录到站。首站只记到站，下一站扫码时记录上一站完成；中间检查同样办理，无需另点“检查完成”。
4. 登记数量有误时在追踪卡更正数量并填写原因，先前工序记录的数量不改写。实际报废通过下述异常处理扣量，不能把报废登记为数量纠错。

## 异常登记与数量结算

发现问题时选择涉及工序，填写影响数量和说明。每条异常立即暂停整盘，允许继续登记不同问题；全部异常处理完成前不能交接至下一站或完成终检。

每条异常只确认一次最终结果：填写返修成功数量、本次新增报废数量，涉及已报废工件时选择同盘原报废处理记录和关联数量。三类数量之和须等于该问题的影响数量；仅本次新增报废扣减当前盘量。比如影响 3 件，返修成功 1 件、新增报废 2 件，本盘只减 2 件。

同一工件有多个问题时，其余问题关联已有报废记录，不能再次填为新增报废；不同问题可关联同一来源。关联关系由现场人员核对，影响数量不能直接跨问题相加作为实际不良品数量。这里只登记最终结果，不记录返修动作或分次结算。盘量已减为零但仍有问题未结时，继续完成这些问题的关联处理；全部处理完后该盘标记为整盘报废，不再流转、不入库。

## 终检与结束

末道到站后，选择启用登记人员，核对该盘剩余数量及全部异常。可先新增终检发现的异常，处理完全部异常后点击完成终检；界面只读展示本次入库数量，服务端按当时盘量生成产出并入库，不再填写产出数量。每盘只确认一次，不支持分批放行；重复点击不会重复入库。

研发没有追踪卡及工序，仍在任务中手填一次实际产出，零产出不产生入库。全部工作处理完后明确结束任务；未完成卡和未履约资源按[结束规则](../../apps/api/src/modules/production/docs/database/production-termination.md)处理，已产出及库存事实保留。

## 追溯与补差

工序追踪统一查看任务各站、追踪卡到站及数量变化、异常处理和最终产出；成品库存的入库来源可查看对应任务、入库单和原始流水。任务详情通过同一追踪入口查看执行，不维护第二套报工详情。

入库后发现数量错误，用“其他入库／其他出库”在相应成品批次记录补差及原因。库存反映调整后的实际量，历史产出仍是终检当时确认量。现有盘点管理只支持物料，成品数量修正使用其他出入库。
