# 系统使用断言

本文归纳会直接影响业务操作的强制规则，作为系统使用手册和验收依据。规则按模块维护；新增模块断言时，应同时说明触发条件、允许操作、拒绝操作和历史数据口径。数据库设计细节仍以 [数据库设计总览](database/README.md) 为准。

## Product：产品、物料清单与工艺路线

### 产品身份

- `products.id` 与产品编码共同表达稳定业务身份；产品编码创建后不可修改、不可复用。
- 基础单位创建后不可修改，系统不提供单位换算。需要改变编码、单位或产品原则身份时，必须新建产品。
- 规范化名称、展示说明和备注等不改变物料实质的字段可以修改；历史库存批次和业务单据继续显示各自已经冻结的名称快照。
- 管理员负责判断一次变化是否改变产品原则身份，但管理员权限不能绕过已经生效的系统锁定。

### 单一 BOM 与永久锁定

- 每个自制产品只维护一份 `product_materials` BOM，不建立 BOM 版本头、版本行、当前版本指针或双套兼容读写。
- BOM 在首次被生产任务引用前可以整体编辑；创建首个生产任务时，Product 与 Production 在同一事务内写入 `products.bom_locked_at/bom_locked_by`。
- “被引用过”表示该产品曾经存在生产任务。任务后来取消或删除测试数据、库存归零、需求完成、路线停用，均不得解除 BOM 锁定。
- 锁定后，BOM 行新增、更新、删除、停用、恢复和批量替换全部拒绝。系统不提供解锁接口。
- BOM 锁定后仍可查看。需要改变投入物料、单位用量、关键物料或批次追溯原则时，必须新建产品和新编码，再按需复制 BOM 与路线。
- 创建生产任务前，BOM 至少包含一条启用明细；投入物料必须可用，BOM 用量单位必须等于投入物料固定基础单位。

### 路线边界

- 工艺路线仍属于具体产品；路线自己的 `draft/enabled/disabled/archived` 生命周期不等于 BOM 生命周期。
- 创建任务时只允许使用同产品、已启用且包含有效工序的路线；任务继续冻结路线、工序和 SOP 快照。
- 修改产品名称不会破坏 BOM 或路线 ID 映射。原则性 BOM 变化使用新产品后，旧产品的路线不得直接转移为新产品路线，应通过显式复制和复核产生新路线。

## Production：生产

本节后续按已落地的工单、任务、报工和短批开工规则继续补充。当前与 Product 的关键断言是：生产任务创建成功与 BOM 首次锁定必须同事务提交；任一环节失败时两者同时回滚。

## Warehouse：仓储

本节预留给库存、分配、出入库和供需预警的操作断言。

## Quality：质量

本节预留给异常处置、返工和检验的操作断言。
