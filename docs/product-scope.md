# 当前产品范围

本文件定义当前提供什么、暂不提供什么；具体规则由[所属模块](README.md#应用与模块)维护，未完成实施、验收与测试集中在[路线图](roadmap.md)。实现存在不代表用户已验收。

| 模块 | 当前范围 |
| --- | --- |
| Identity／平台 | 认证、RBAC、操作日志、管理端权限及多标签页基础设施 |
| Product | 成品、物料及精确版本、分类、BOM、技术文件、工序与工艺路线 |
| Production | 工单与任务、批量工序派工／开工／报工、异常返工及工序报废补料、需求与更正、分配／领退料、损耗事实、研发任务执行、逐项收尾、结案及产出清单更正 |
| Procurement | 简单供应商名称目录、单工单按需采购／独立备料、逐行供应商、多次到货与实收修订、未入库整批处理、实际退回、独立补单及人工逐行关闭 |
| Quality | 来料全检／抽检及复核，成品质检／复检／零产出核实，不可变检查事实与明确结论 |
| Inventory | 唯一库存账本与余额投影、外购物料及批准成品入库、库存批次与现有物料盘点；通过公开能力承接生产领退料 |
| Approval | BOM、需求更正、任务结案与清单更正；顺序节点支持角色、指定用户及场景业务人员，工单下达审批未接入 |
| Notification | 审批事件的站内消息、本人收件及点击已读、角标轮询；未接外部渠道 |

批量以已批准 BOM 为任务依据，按任务初配锁定物料版本；研发不要求 BOM 或工序，手工提需并按任务开始／结束。领料损坏只留事实，额外物料独立提需；完整语义见[任务与需求](../apps/api/src/modules/production/docs/database/work-orders-and-batches.md)。

采购至入库期间，实物由 Procurement 管理，检查由 Quality 记录，库管实际确认后才写 Inventory；来料允许按有效正式分配分次入库。生产需求、订购数量和库存分别保有事实。当前不接采购在线审批。

## 研发结束及后续成品流转

研发与批量共用产出草稿、独立检验、管理员核对、工单负责人审批及仓管入库。成品限 `self_made/production_extra` 两类，每类收齐批准量后一次确认；已入类别锁量，零量不建入库。研发可关联新成品和新工单继续下一轮，旧轮需求、物料、产出及待入库事实不转移。

成品质检计算提供数量建议，明确放行后由产线核对、负责人批准；剩余复检的固定已入基准、范围快照和开始冻结已确认但仍待实施，见 [CQ-01](documentation-conflicts.md#cq-01)。当前规则与目标分别维护在[成品检验](../apps/api/src/modules/quality/docs/finished-inspections.md)，不得把目标视为已实现。

## 明确排除与后置范围

- 外购入库限 `purchased`；生产退料限已确认领料回公共可用库存；盘点限现有物料库存批次与库存状态。成品身份不进入物料分配或现有物料盘点。
- 不提供完整 ERP、财务、销售、委外、项目级隔离、供应商评审、通用其他出入库、库存报废／销毁管理、废品库、待判库存、完整在线质量或全链路追溯。
- 不开放成品同类分次收货、已入库质量冲销、仓管拒收／差异账本；结案报废与领料损耗不自动生成库存、补料或补产。
- 工单提前采购、混合来源单、跨到货合并检验、供应商打印、门口拒收登记、抽样分档配置及外部通知均另行安排。补料管理、后续废品入库及其他方向见[路线图](roadmap.md)，按各自前置条件和批准状态推进。

已有 UI、预留字段或状态值不扩大以上范围；新增场景先明确业务所有者和公开边界。
