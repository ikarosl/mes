# 当前产品范围

本文件定义当前提供什么、暂不提供什么；具体规则由[所属模块](README.md#应用与模块)维护，未完成实施、验收与测试集中在[路线图](roadmap.md)。实现存在不代表用户已验收。

| 模块 | 当前范围 |
| --- | --- |
| Identity／平台 | 认证、RBAC、按业务场景配置角色人员候选、操作日志、管理端权限及多标签页基础设施 |
| Product | 成品、物料及精确版本、分类、BOM、技术文件、成品与物料精确版本规格书、工序与工艺路线 |
| Template | 系统管理下独立维护 JSON 表格模板，配置列名与预设行，支持查询、编辑和启停；业务资料复制并保存独立表格，不绑定业务场景 |
| Production | 工单与任务、批量工序派工／开工／报工、异常返工及工序报废补料、需求与更正、分配／领退料、损耗事实、研发任务执行、管理员任务开工、逐项收尾及批准前撤回结束、结案及产出清单更正 |
| Procurement | 简单供应商名称目录、单工单按需采购／独立备料、主单唯一供应商、明细无税／含税单价与逐行税率、含税总额推算及手填更正、多次到货与实收修订、未入库整批处理、实际退回、独立补单、人工结束／恢复采购跟进及无实际执行的到货整单作废 |
| Quality | 来料按完整到货可调整分组、逐来源全检／抽检及复核，成品质检／复检／零产出核实，按任务工序登记现场专检及冲销更正；不可变检查事实与明确结论 |
| Inventory | 唯一库存账本与余额投影、公共出入库主从、外购物料及批准成品入库、物料／成品其他出入库、库存批次与现有物料盘点；通过公开能力承接生产领退料 |
| Approval | BOM、需求更正、任务结案与清单更正；顺序节点支持角色、指定用户及场景业务人员，工单下达审批未接入 |
| Notification | 审批事件的站内消息、本人收件及点击已读、角标轮询；未接外部渠道 |

批量与研发使用不同的物料和执行方式，见[任务与需求](../apps/api/src/modules/production/docs/database/work-orders-and-batches.md)。两者共用产出核对、独立检验、负责人审批及分次入库；研发可关联下一轮新工单，旧轮事实不转移。

工序专检独立于具体报工，通过既有异常处置承接已核实的不合格量；不扩展为在线工序质量门禁或自动修正报工，边界见 [ADR-0021](adr/0021-process-inspection-and-abnormal-disposition.md)。

采购、检验、正式授权与实际库存分工见[采购入库流程](procurement-inbound-design.md)。来料质检主单只组织完整到货，不合并逐来源检查；实际入库的合单范围也不改变来源身份。

采购金额限本行价款记录、总额推算及后续更正；不提供税务申报、结算、付款、财务或库存成本，完整输入语义见[采购金额契约](../apps/api/src/modules/procurement/docs/purchase-orders.md#明细采购单位单价)。

## 研发结束及后续成品流转

成品检验只记录检查事实与结论，产出由产线核对、负责人批准。剩余实物复检和清单更正已纳入范围，数量及授权规则见[成品质检](../apps/api/src/modules/quality/docs/finished-inspections.md)与[结案设计](../apps/api/src/modules/production/docs/database/production-termination.md)。

生产退料使用公共入库；其他入出库可独立办理物料和成品，支持草稿、整单确认及取消，不附带生产／采购履约、质检定稿或审批。具体规则见 [Inventory](../apps/api/src/modules/inventory/docs/database.md)。

## 明确排除与后置范围

- 外购入库限 `purchased`；生产退料限已确认领料回公共可用库存；盘点限现有物料库存批次与库存状态。成品身份不进入物料分配或现有物料盘点。
- 不提供完整 ERP、财务、销售、委外、项目级隔离、供应商评审、库存报废／销毁管理、废品库、待判库存、完整在线质量或全链路追溯。
- 不开放已入库批次之间的事后合并／转移、已入库质量冲销、仓管拒收／差异账本；结案报废与领料损耗不自动生成库存、补料或补产。
- 工单提前采购、混合来源单（已批准的外购物料跨供应商入库除外）、跨到货合并检验、供应商打印、门口拒收登记、抽样分档配置及外部通知均另行安排。补料管理、后续废品入库及其他方向见[路线图](roadmap.md)，按各自前置条件和批准状态推进。

已有 UI、预留字段或状态值不扩大以上范围；新增场景先明确业务所有者和公开边界。
