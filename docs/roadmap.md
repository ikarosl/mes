- [ ] 完成全仓库验证：执行 `corepack pnpm verify` 及 `corepack pnpm --filter @company/api typecheck:test`，处理剩余失败并核对最终结果。测试覆盖与执行边界见[测试策略](testing-strategy.md)及 Notification 所有者文档。
- [ ] 在独立测试库完成 `corepack pnpm test:production:mysql` 全量回归，核对通知并发去重与首次已读、审批通知联动、事务及钩子隔离、迁移 up/down/up 与非空回滚保护；修复失败后取得完整通过结果。环境门禁见[跨模块测试](../tests/README.md)。
- 公告发布入口、独立中心页、人工定向发布的收件范围，以及非 Approval 的实际通知场景未批准；首期仅保留通用纯文本发布能力，不预建公告管理、定时提醒、全部已读、多标签页同步或清理归档。

### 实际接入外部渠道时再设计

- 可靠投递：是否要求宕机补发、可接受延迟与重复；据此定义同事务持久化投递记录或 outbox、幂等、重试退避、失败人工处置、多实例领取和顺序要求。不能只依赖提交后的内存钩子承诺送达。
- 渠道与账号：渠道适配端口、用户与外部账号绑定、凭证配置及脱敏、渠道停用或账号解绑后的处理、送达回执的含义；外部送达不自动变成站内已读。
- 消息量与打扰：超时、并发和积压上限、速率限制、过载策略、去重合并；按实际需求决定优先级、订阅偏好、免打扰、摘要和催办，不能让可关闭提醒影响业务待办本身。
- 运维与内容：失败/积压指标和关联追踪、重发权限及审计；渠道文案和模板版本仅在实际需要时设计，不复制完整业务单据，不预建通用模板平台。

## 最低优先级优化（当前不实施）

### F9：数据库表与字段中文 COMMENT

- 这是数据库客户端可读性的优化项，不属于当前功能缺陷修复。当前开发阶段数据库结构仍不稳定，暂不实施中文 COMMENT 补充，也不为此追加 migration。
- 待结构稳定后再安排：依据各表所有者文档核对中文表注释和字段说明，通过追加 migration 落地，并确保不改变字段类型、NULL、默认值、生成表达式及约束；不得修改已执行迁移。
- 优先级最低，不阻塞当前业务开发、数据库设计文档维护或黑盒验收。

## 已确认缺陷：待修复

以下为已确认但尚未修复的缺陷，完成后按统一交付顺序验证。

- [ ] AuthClient会话竞态：按会话版本约束refresh成功／失败清理、401重试及me用户资料回写，finally仅清理自身持有的刷新Promise。验收退出A并登录B后，A旧刷新成功／失败、旧401或用户资料晚到均不修改B，也不使用B凭证重试旧请求；同会话合法并发继续可用。
- [ ] 缓存任务页未消费新定位：从出库阻断跳转时，ProductionTasksPage需应用新的route.query.keyword、重置分页并查询，不能仅在onMounted处理；保留尚未提交草稿，当前可手动搜索。
- [ ] HTTP超时提示优先级：`handleHttpError`先判status=0，ECONNABORTED被提示为普通网络错误；按[错误处理边界](../apps/admin-web/docs/http-error-handling.md#121-超时当前会优先被识别为网络错误)区分超时，验收后补相邻用例。
- [ ] 生产写意图恢复：工单／任务创建和物料分配仍可能在重放前被当前候选或余量校验阻断；领料损耗申报／确认未完整保留首次载荷及版本，未知结果后的编辑、关闭和重开保护不足。按[写意图边界](../apps/admin-web/docs/architecture.md#5-写意图与错误)补首次请求快照、未知状态保护及可达的原请求恢复入口，验收响应丢失后候选／版本变化、改输入和关闭重开。取消前端自动写重试不代表这些存量缺口已修复。
