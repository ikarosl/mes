# ADR-0013：采购来源、检验后入库与事实边界

本文仅被部分取代：[ADR-0014](0014-task-material-policy-and-output-inspection.md)确定成品质检归 Quality；[ADR-0015](0015-unified-quality-quantity-semantics.md)取代独立剔除量、检验直接生成可入范围、检前按采购拆批、来料部分复检和 QC 数量硬上限，并统一正式分配及补发依据。单工单采购、逐行供应商、需求独立、实收纠错、实际物流不可改写及唯一库存账本继续有效。

状态：Accepted。当前完整规则从 [Procurement 采购订单](../../apps/api/src/modules/procurement/docs/purchase-orders.md)、[到货处置](../../apps/api/src/modules/procurement/docs/receipts.md)、[正式清单与分配](../../apps/api/src/modules/procurement/docs/receipt-acceptance.md)读取；跨模块协作见[采购技术设计](../procurement-inbound-technical-design.md)。本文保留业务选择和不可越过的事实边界，验收与正式测试见[路线图](../roadmap.md)。

## 背景

采购必须区分“为什么买”“实际买多少”“收到什么”“允许如何处置”和“实际进了多少库存”。生产需求变化不能改写已订购事实，检验样本也不能直接代表物流交接。

此前外购手工入库直接形成可用库存，待检状态字典不代表已有待检业务。选择以采购到货保管入库前实物、强制检验并在实际确认时才记库存，避免同时维护收货即入待检库存的第二条链路。

## 决策

1. **需求来源与备料分开。** 按需采购以具体正式 `production_item_demand.id` 为来源，保持物料精确版本；一单限单一工单，可跨该工单任务。仅有 BOM 或已下达工单不足以下单。独立备料不依赖工单、任务、需求或 BOM，也不自动回绑未来需求。普通草稿保存和下单均通过 Production／Product 公开能力重核资格，不能把已选中当作仍合格，也不能仅按“未领料任务”过滤新增需求。
2. **供应商逐行决定，采购量独立。** 采购选择已维护的供应商稳定身份，不用自由文本、不从主单继承、不建立物料供应商绑定。生产供应商提示不限制实际采购或库存供应商。同物料版本不同供应商拆行；同三元身份可明确归并。需求来源逐条关联，不用 ID 数组替代关系，不保存分摊量。同需求可关联多采购行／单，查询展示采购行数量而非本需求已采购量。供应商仅名称及身份，不扩展评审、联系人或附件。
3. **订购、库存与需求各保事实。** 下单不预留库存，到货及入库不减少需求；来源关闭、更正、换版或任务终态不自动改量、取消或改绑既有采购。在途采购由人员明确继续或结束，公共库存后续由生产独立分配与领用。
4. **正式下单冻结身份和计划。** 一期不接采购在线审批；草稿可编辑，正式下单后所属工单、逐行供应商、精确身份、来源映射和计划量不可直接改写。录错按无到货取消或已有到货结束办理后重建，原到货、检验、退回和入库历史不覆盖、不转移。
5. **按真实到货登记，不按计划封顶。** 普通采购和新到货补单均保留实际交接量，计划只用于差异与关闭资格；仍校验正整数、存储上限、身份、可收货状态和防重。同次实物先完整登记和检验，再分原单／补单归属；不能为了采购份额虚构多次到货。现场接收前拒收的部分不算已收到，已确认接收后退回必须另留真实交接，不改小实收掩盖物流。
6. **检验、正式授权和执行分开。** 所有外购来料必须检验，无免检；Quality 保存不可变事实和明确结论，不直接授予库存。库管核实本轮实物并形成去向授权，实际入库才调用 Inventory 记账。不合格不等于实际退回或报废，待复检／不放行不能以数量说明绕过。最新整批轮次与正式分配规则由 ADR-0015 确定，不恢复部分范围复检或 QC 硬上限。
7. **真实补发和超量承接采用独立补单。** 新单有独立身份及履约，不改原单计划、事实或状态，不把补单数量累加回原单。质量补发关联有效正式质量退回分配及供应商约定，可先补后退、无需原单先关；新实物重新到货和检验。超量承接引用同次既有到货，不重复检验或入库身份。免费超量可明确归原单，额外购买由采购明确决定；两类原因不得混用，超发、采购终止或人工拒收不能冒充质量补发。
8. **补单继承原身份，人工核实真实依据。** 补单锁定原行供应商、物料版本、来源类型及工单，保留原需求映射与独立异常来源；原需求失效不要求重开。创建和下单重核当前异常依据，复核中或被取消的处置不能新办；已下单历史不随依据更正自动改写。不设置累计补购额度或次数上限，但每次必须对应真实补发／额外购买；关联历史只供核对，不宣称自动识别同一实物重复补购。数量、幂等、真实来源和库存防重仍执行。
9. **逐行人工结束采购，不替代实物处置。** 达到计划的正式可入量可提供达标关闭资格；实收已齐、质量退回处置完成而合格量不足也可关闭，不必补购凑足原计划。两者均无需等待全部可入实物入库，具体公式由采购订单文档维护；其他短收或终止须人工留原因，不冒充质量达标。状态不随到货或质检自动结束，原单与补单互不代办关闭。关闭只停止新到货，既有检验、更正、入退继续；关闭证据保留，后续差异不静默改写历史或重开采购。
10. **入库和退回均为实际交接。** 外购可分次入库，每次消费当前正式可入余量；首次实际入库创建到货对应的唯一内部批次，后续沿用，不加第二套批号。不同到货／供应商不凭供应商批号相同合并内部批次。每个待退分配收齐后一次真实退回，不能只用检验结论扣保管量；采购终止与质量退回分别保留，旧无采购来源的手工外购写入口不恢复。
11. **纠错保留已发生事实。** 实收录错追加带原因、人员和时间的修订，不能覆盖原量、借纠错登记新货或隐藏损耗；更正量不得小于真实已入及已退。独立更正使未处置部分重新办理，同轮定稿核实则按现行正式清单规则形成依据；更正到零不造零检验。主动复检须明确开始，替代旧剩余授权并与入退互斥；只打开页面不影响资格。已入、已退及关闭事实不回写，一期不开放已入库采购退货或已执行事实的质量冲销。
12. **采购与生产使用不同版本资格。** 停用精确版本可办理采购、补购、到货、检验和合格入库，不能生产领用，也不计可领齐套量。只放宽精确版本启停，不放宽基础物料／分类启用、软删除、库存批次冻结等条件；生产新选版规则不随采购放宽。
13. **保持一期边界。** 来料到货至入库期间不建设破坏性抽样、损坏或遗失损耗流程，不把差额自动当损耗；需要时必须另行明确事实和关闭方式。完整质量、ERP、财务、供应商评审及打印不纳入。工单提前采购、混合来源、跨到货合并检验、门口拒收登记与抽样分档配置等后续事项以[路线图](../roadmap.md)为准，不能因已有字段提前实现。后续抽样分档应可配置而非写死，保存实际检查数及当时规则参数；配置变化不得重算历史检验或已确认入库额度。

## 技术定稿与实施边界

Procurement 所有供应商、采购、到货、数量修订、处理轮次、正式分配与实际退回；Quality 所有来料及成品检查；Production 所有生产需求、结案和批准清单；Inventory 所有批次、实际入库及唯一库存账本。成品每类一次入库不因外购可分次入库而改变。

当前模块文档完整维护各自状态、字段、命令和资格；[采购跨模块设计](../procurement-inbound-technical-design.md)维护协作关系。[管理端采购文档](../../apps/admin-web/docs/procurement-inbound.md)维护候选分页、切换工单保护、来源编辑及展示，不在 ADR 重复页面操作。

采购表按 Procurement 命名，Quality／Inventory 表不因被采购调用改变归属。当前表结构见[采购数据库](../../apps/api/src/modules/procurement/docs/database.md)，不以新旧文件顺序改变所有权或恢复被取代流程。

## 实施约束

业务、库存及成功审计在同池事务通过各所有者公开能力协作；登记的展示读取不代替业务资格、锁定或写入。数据库迁移遵守[迁移安全](../../packages/database/docs/migration-safety.md)及仓库公共规则，不建设兼容双写或第二套事实。不用实现存在代替业务批准或用户验收。
