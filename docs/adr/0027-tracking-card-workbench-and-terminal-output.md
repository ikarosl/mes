# ADR-0027：追踪卡工作台与终检产出

> 仓库简化实验中的来料数量、放行、处置授权与补单门槛按 [ADR-0028](0028-independent-warehouse-receipt-and-inspection.md#取代范围) 的明确范围取代。以下保留本决策的历史理由与其余有效边界。


状态：Accepted，实验分支。只在独立空库实施，不转换旧生产执行及结案历史；设计获批不代表用户验收或正式测试通过。

## 选择与理由

面向小规模产线，以追踪卡组织每盘流转，统一工序到站、人员登记与异常记录。中间检验配置为普通路线工序，下一站扫码自然完成上一站，不增加确认检查动作。批量任务末道完成时按当前剩余盘量确认产出并同步入库，不再另填产出数量，省去独立成品质检、产出清单、负责人审批及仓管二次确认。扫码到达末站不等于检验完成，仍需登记人员显式确认完成。

每条异常登记影响数量并暂停整盘；只记录一次最终数量结算，不记录返修过程。返修成功不增量，新增报废扣减盘量，已在其他异常中报废的数量关联原报废记录且不重复扣减。不同问题的影响数量可能重叠，不能相加作为实际不良品数量；是否同一实物由现场人员判断，系统不提供单件识别。各异常可分别引用同一报废来源解释重叠问题，不在不同异常之间消耗引用额度。所有异常处理完成后恢复流转，全部报废的盘直接结束且不形成终检产出或库存。

本次接受的取舍是：批量产出依赖建卡数量、过程报废扣减与有原因的数量纠错，不再由末道独立填写实物数量；终检确认即视为可用库存，系统不再表达等待实物交仓的状态；入库后数量差异通过通用其他出入库调整库存，历史产出保持当时确认值，不要求两者长期相等。现有盘点仍限物料，成品盘点扩展另行决定。

现场人员独立于登录账号，使用统一目录，不按产线与质检岗位分组，以适应现场人员兼岗。流转、异常和终检均可选择任一启用人员；切换登记人员不改变账号权限和审计身份，登录账号仍须具备对应操作权限。研发无追踪卡，仍在任务内手填一次实际产出。任务仍需明确结束，可短产或零产出；结束释放未履约生产资源，不通过复杂结案审批。

## 所有者与边界

- Identity 维护现场人员，Product 维护路线；路线最后启用步骤承担终检，任务创建冻结路线与 SOP。
- Production 拥有追踪卡、到站及历史数量快照、异常与处理、一次性产出、任务结束和剩余资源处理。细节及数据库结构见[生产执行](../../apps/api/src/modules/production/docs/database/execution-traceability-quality.md)与[任务结束](../../apps/api/src/modules/production/docs/database/production-termination.md)。
- Inventory 唯一记账，正产出与实际入库同事务；研发零产出只留 Production 事实，整盘报废不产生库存。公开协作见[库存协议](../inventory-extraction-design.md)。
- Quality 保留来料检验；Approval 保留 BOM、需求更正。采购来料的轮次、明确放行、分次入库与归批不受本决定影响。

## 取代范围

本决定在实验分支取代 ADR-0009、ADR-0011 的研发结束／生产结案／产出清单链，ADR-0014 的生产产出独立检验及收尾部分，ADR-0015、ADR-0016 的成品检验数量／成品授权与分次入库部分，ADR-0019 和 ADR-0021 的生产成品质检及工序专检方案。ADR-0006、ADR-0008 的通用审批框架保留，生产结案和动态工单负责人审批场景退出。ADR-0014 的任务用料规则、ADR-0016 的采购授权与库存批次分离、其他来料和采购规则继续有效。

## 数据与验证

用户授权本次破坏性实验不保留数据库数据，采用新库隔离；增量 migration 仍成对追加且不改基线。旧生产执行与成品质检数据非空时迁移拒绝，避免误连原业务库。旧实验异常缺少影响数量及数量结算事实，不能猜造历史返修／报废结果；数量结算方案也只在空追踪数据上实施。实验库失败可另建空库，旧业务库不会由脚本自动删除。已应用迁移保持不可变。

先完成类型、构建、迁移及启动验证供手工验收，正式测试须用户另行通知；旧高重要性用例仅留下原位文字 TODO，后续按新模型恢复覆盖。整体待验收与覆盖缺口归[路线图](../roadmap.md)。
