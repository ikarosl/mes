# ADR-0028：仓库收货、来料报告与补单独立办理

状态：Accepted，仓库简化实验分支。用户接受各环节独立、可先入库后登记检查；只使用新建独立空库，不保留或转换旧采购到货、处置及质检数据。设计获批不表示手工验收或正式测试通过。

## 选择与理由

小团队由仓库决定实际接收数量，来料检查用于保存检查信息并形成进料检验报告。将质检、处置授权和实际入库串成必须依次完成的流程，会重复录入数量并增加交接。取消实收总量、整批轮次、明确放行、定稿分配及供应商退回交接链；到货只保留一次真实来货的采购物料来源。

到货建立后，仓库实际入库、到货行其他处理说明、来料检查报告及采购补单分别办理，不互相要求完成。入库只提交实际正数量及目标批次，同事务形成公共入库单、明细和唯一库存流水。其他处理在到货物料行独立追加，描述该次到货的问题或大致去向，不填写入库数量、不关联本次入库，也不声明线下安排或执行已完成；它不产生退回／报废库存事实。没有独立可入库授权及剩余额度。

来料检查记录实际全检／抽检、合格与不合格数、异常及报告内容。检查人员可以由具备对应权限的仓管兼任；不新增岗位审批或质量放行门槛。报告的编制、审核、批准栏用于打印签字，不代表系统已完成审核批准。检查数量不能推算成到货总量，后补报告不会追溯修改实际入库。

补单关联有效到货明细和原采购行，数量及商业约定由采购确认。额外收费实物以 existing_receipt 补记采购，不重复到货或库存；免费接受按实际数量入库，无需补购，可在到货行记录赠送说明。new_arrival 补发约定以后产生独立到货。两者均不依赖检验、仓库授权、实际入库或退回事实。

## 所有权与接受的边界

Procurement 拥有采购、到货来源和其他处理记录，Quality 拥有不可变检查报告，Inventory 拥有实际入库和库存。来源关系、权限、同源校验、版本、幂等及事务审计继续生效；各模块公开边界见[协作设计](../procurement-inbound-design.md)和[库存协议](../inventory-extraction-design.md)。

系统不再提供到货总量与全部实物去向守恒、剩余可入量、真实已退量或质量放行拦截。采购计划、检查数量与实际入库允许不同；人员对本次实际入库负责。系统显示各自已登记的记录，不把缺失检查当合格，不把处理说明当线下完成事实。采购跟进仍由人员结束或恢复。

## 取代范围

本决定在实验分支取代 ADR-0013 的检验后才允许入库门槛，ADR-0015 的来料整批数量和明确放行，ADR-0016 的采购正式授权消费，ADR-0018 保留的质量门槛、轮次、实收修订及正式分配引用和余量约束，ADR-0019 保留的来料整批核实，以及 ADR-0022／0023／0025 中依赖轮次、正式去向或实际退回的办理条件。ADR-0027 的生产模型继续有效，其保留的采购旧链由本决定取代。

原采购来源、单供应商、金额、人工结束／恢复、补单固定到货身份及两类物流含义继续有效；跨供应商合单、目标库存批次选择、唯一库存账本和公共出入库结构继续适用 ADR-0018、0020、0026。不扩展财务结算、供应商退货执行、废品库存或质量审批。

## 数据与验证

新建实验库使用完整不可变迁移链并追加成对迁移；退役结构在非空业务数据下拒绝执行，不建立影子表或双写兼容。旧库保持隔离，不因实验授权自动清空其他环境。失败初始化按[迁移安全](../../packages/database/docs/migration-safety.md)保留诊断并另建空库。

先完成类型、构建、空库迁移和 API／管理端启动验证，再交用户黑盒与 UI 验收。废弃代码以当前业务调用为依据，只有历史测试引用同样退役；高重要性覆盖原位置仅保留文字 TODO，正式新测试等待用户另行通知。整体待验收与测试缺口由[路线图](../roadmap.md)维护。
