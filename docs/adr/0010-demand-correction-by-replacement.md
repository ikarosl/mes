# ADR-0010：通过关闭与替代纠正正式需求

状态：Accepted。当前数量口径、状态、字段、命令及事务完整维护于 [Production 需求设计](../../apps/api/src/modules/production/docs/database/demand-allocation-and-outbound.md#正式需求更正与替代)；本 ADR 记录为什么采用关闭与替代。

## 背景

正式补料方案、需求、领料及补产授权保存不同阶段的事实。用新数量覆盖旧需求会破坏已确认方案、需求快照与历史履约的解释；审批记录也不能替代这些事实。

## 决策

1. 未确认方案可编辑；正式需求更正采用“审批通过 → 关闭旧未履约部分 → 按需创建替代需求”，不覆盖原数量、身份及来源快照。替代只承载批准后仍需领用的数量，已领事实仍归旧需求。
2. 补料来源链与更正替代链分别保存。替代需求保留原补料单、需求类型与来源，新旧需求和审批结构化关联；同一旧需求最多一个生效后继，连续更正不删除中间历史。
3. 适用范围为同任务、同物料、同精确版本、同单位的活动人工追加，以及尚未齐套工序补料的活动需求。正常 BOM 需求不开放日常改量，已履约／已关闭需求不重开；换料换版、停止生产及损耗事实分别办理。
4. 当前履约按已批准生效的更正链计算，不叠加新旧原始需求量；退料不冲回历史履约。新目标不得低于链上已领量，剩余为零只关闭、不创建零量替代需求。
5. 只冻结正在更正的旧需求，其他需求及已有生产额度按原规则继续。在审需求仍是未解决要求；驳回或撤回只解除本申请冻结，不改变正式需求事实。任务结束与在途更正互斥，迟到批准不得在已结束任务中创建需求。
6. 普通关闭／取消不等于补料齐套。免除剩余要求必须保留已批准且生效的证据；首期不开放整单零领料、全部免除后自动补产。普通短批授权不能绕过补产物料条件。

## 所有权与生效边界

Production 所有需求、更正关系和履约判定，Approval 所有流程与决定；仍只以 `production_item_demand` 作为执行需求事实，不建立第二份需求表或库存账本。

批准时重核需求、已领、预留、来源和版本证据，关闭、替代、解除冻结、计划版本、补料齐套及其补产影响、审批生效与审计原子提交。失败整体回滚，不暴露“旧需求关闭而替代尚未建立”的执行窗口，也不重建报废或补产授权。

更正批准与出库确认共用受控补料履约判定；工序消费该结果并保留自身资格校验。字段指针、唯一性、防分叉及锁序由上述所有者文档维护，未完成事项见[路线图](../roadmap.md)。
