# ADR-0010：通过关闭与替代纠正正式需求

状态：Accepted（决策已确认，代码待实施）

## 背景

正式补料方案、生产需求、领料及补产授权分别保存不同阶段的来源与数量事实。用审批后的新数量覆盖旧需求，会使已确认方案、需求快照和后续履约失去一致的历史解释。审批记录不能替代这些事实，也不得通过回改旧快照消除差异。

## 决策

1. 未确认的补料方案仍可编辑主单及明细；正式确认后的方案、需求原始数量和来源快照保留。正式需求纠错采用“提交更正申请 → 审批通过 → 关闭旧需求未履约部分 → 创建替代需求”，不原位改量。
2. 旧需求的已确认领料仍属于旧需求；剩余部分通过带原因、操作人、时间及审批依据的关闭结束。替代需求只承载批准后仍需履约的数量，不重新领用已经履约的部分，不改写原出库明细、库存流水、报废事实或补产授权。
3. `parent_demand_id` 保留既有业务来源含义：补料关联其原始需求，人工追加为空。直接替代关系另行表达，不把这个字段改成多义指针。重复更正沿替代关系追溯，不能破坏原补料来源链。
4. 新旧需求及每次更正申请、审批实例须有结构化关联。工序报废补料的替代需求继续归属原补料单，保留原需求类型及来源关系；不能创建无关联的普通人工追加来代替补料。审批依据和生效结果不可覆盖，查询可以沿任一需求查看完整更正历史。
5. 当前可执行需求与历史需求分别按语义查询。只有已批准且已生效的更正才能改变该需求的后续履约要求；存在替代需求时，旧领料仍计入对应业务履约，替代需求负责剩余部分。无替代需求的剩余要求解除遵守第 7 项。禁止直接叠加新旧 `need_number`，禁止将所有 `cancelled/closed` 需求一律视为补料已经齐套。
6. 首期数量纠错限定于同批次、同基础物料、同精确版本、同单位的活动人工追加需求，以及尚未齐套的工序报废补料单下的活动需求。正常 BOM 需求不开放日常数量纠错；生产领料损耗补料数量仍由损耗事实决定，不能单独任意修改。已履约、已关闭需求不重新打开；改变物料身份、版本或已确认损耗事实须另行定义来源业务的更正命令。
7. 不再需要任何剩余数量时，只关闭，不创建零数量替代需求。更正后的总需求不得少于该替代链累计已确认领料量；退料不减少已确认履约事实。补料项无替代需求时，须有批准解除剩余要求及新目标已由历史领料满足的生效证据，不能仅凭没有活动需求判为齐套；首期不开放整单零领料、全部要求免除后的补产放行。单纯决定停止生产属于批次收尾，不能包装成需求录入错误。
8. 单条需求纠错与批次收尾分别处理：纠错需审批后才使关闭和替代生效；批次收尾的逐项操作及最终结案审批规则由 ADR-0009 与批次结束所有者设计承载，不能据此允许短批开工后绕过管理决策关闭全部剩余需求。
9. 新增需求 `closed` 终态表示主动结束剩余要求，关闭原因区分更正替代、更正后无剩余、单条关闭和随批次终止关闭；`cancelled` 留给未执行任务取消。新需求的直接替代指针必须对应旧需求的更正关闭及同一生效审批，但关闭需求不一定有后继，连续替代也不清除中间需求原来的替代指针。
10. 单条纠错只冻结旧需求。页面显示“更正审批中”，以需求表的可空 `pending_correction_id` 关联当前在审更正申请，履约状态仍为 `active`；草稿不设置该指针。所有需求操作候选及写命令排除在审需求，齐套和正常完工仍把它视为未解决；其他需求及原有生产额度按原规则继续。正式送审同事务绑定指针，审批通过同事务关闭旧需求并清空指针；驳回/撤回只清除仍属于该申请的指针，历史申请及新需求的永久替代关联保留。批次终止前先处理在途更正，不能由迟到批准在已结束任务中创建需求。

## 所有权与生效边界

Production 所有更正申请、替代关系及需求写入；Approval 所有审批流程、节点与决定，通过公开处理器协作。有效需求仍只存于 `production_item_demand`，不建立另一份执行需求表或库存账本。

审批证据包含旧需求及版本、原数量、已领量、关闭余量、新需求量、来源关系、相关待出库单及预留处理。送审期间限制影响本次证据的需求履约操作。最终批准重新锁定并校验范围及数量，关闭旧需求、创建替代需求、推进物料计划版本、更新受影响的补料履约状态、记录审批生效与成功审计必须同事务；失败整体回滚，驳回/撤回不改变正式需求事实。

补料齐套可能使既有补产授权进入可执行状态或重开工序，该影响必须包含在审批依据与生效记录内；更正不得生成第二份报废事实或重复补产授权。

需求更正最终批准与出库确认复用同一补料履约判定及状态推进能力。该能力识别生效更正链与当前要求：被批准替代的旧需求不再阻断，替代需求未领齐仍阻断，普通取消不代表满足。工序只消费补料单的履约结果，并保留自身状态和前置条件校验；普通短批授权不绕过补产额度的物料条件。旧需求关闭、新需求生成与齐套重算同事务提交，不暴露“旧需求已关闭、新需求尚未建立”的可执行窗口。

现有 `UNIQUE (supplement_id,parent_demand_id)` 及按来源生成的幂等键尚不能容纳同来源的历史需求与替代需求。实现时须追加 migration 调整约束及生成策略，保证一个旧需求至多有一次生效替代、同一替代链无环且不并行分叉；不得通过改写 `parent_demand_id`、删除历史行或复用旧幂等键绕过限制。
