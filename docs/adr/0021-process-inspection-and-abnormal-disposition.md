# ADR-0021：工序专检与异常处置承接

状态：Accepted。用户确认按任务工序记录现场专检，复用现有异常处置表承接不合格量，并将累计已承接数量内化到专检单。取代范围仅为 [Production 生产执行](../../apps/api/src/modules/production/docs/database/execution-traceability-quality.md)中暂不实施工序独立检查的范围限制；不取代 CP-01 的独立报工、执行状态与数量上限，不改变来料、成品质检及库存规则。实施、验收和正式测试分别由[路线图](../roadmap.md)登记。

## 决定与理由

专检对象是任务下具体工序的现场实物范围，不是某一笔报工。多次报工、历史更正和抽检并存时，无法可靠分配每次检查到具体报工；因此 Quality 保留独立检查范围、方式、时间、G/F 和凭据，报工更正不改写检验历史。抽检不外推整批，重复检查数量不解释为唯一实物覆盖量。新增问题与已有问题复查必须区分，复查不重复产生可承接额度。

专检工作台以任务下的具体工序为持续办理入口，历次检查分别留存。逐次检查身份不能代替工序工作台身份，否则冲销一次检查会让办理入口终止，后续登记又生成独立列表行。工序汇总由服务端从有效检查与承接投影读取，复用既有工序身份，不新增可写汇总表；逐次承接来源与更正下限仍然独立，不能通过其他检查的余额补足原来源。

已提交检查事实不可覆盖。更正以同一事务追加完整冲销和完整替代，稳定专检单身份不变；单独撤销要求没有已承接数量。质检单的累计已承接量是 Production 异常处置明细的同事务维护投影，不能通过用户输入修改。当前有效不合格量不得小于该下限，待承接量由两者相减。

任务进入结案或已结案后，质检仍可对已有检查记录作历史更正及合法冲销，继续校验原任务工序身份、版本和已承接下限；该权限不恢复任务执行、新增检查或生产承接资格，不改写批准产出和库存。新增检查与生产承接按当前执行阶段办理。

Production 直接以既有异常处置单承载每次正式承接，不另建承接单据或影子事实表。处置单保存来源专检单、承接时具体结果记录及本次数量，后续检查更正不改绑历史依据。生产创建处置单与 Quality 累计增加共享同一事务和固定锁序；处理完成、返工完成或收尾终止均不释放历史承接量。本期不提供专检承接撤销，质检来源不适用报工错误驳回命令。

承接是产线核实并接入生产异常处置的动作，办理入口归生产执行页的具体工序；质检工作台负责检查记录及历史更正。Production 在本任务工序范围内通过 Quality 公开查询能力读取待承接来源，产线办理不依赖质检页面权限；Quality 页面读取权限不因此开放给生产角色。

## 生产计数与边界

专检发现不合格和承接处理不自动减少正常报工，也不增加直接投入。专检返工沿现有结果事实保留正常恢复／残余异常，但由服务端来源标识与普通生产计数区分；残余异常的后继返工保持同一计数范围，不能重新进入普通报工汇总。报废、补料与补产授权继续由 Production 的既有规则办理。

本期不引入工序质量放行门禁、逐件实物追踪、抽样统计推断或在库质量处置。Production 的业务资格由其公开能力核验，Quality 的事实和承接下限由其公开能力维护，不通过跨模块写表实现。
