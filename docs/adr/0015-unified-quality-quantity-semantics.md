# ADR-0015：统一质检数量与放行语义

状态：Accepted。本文保留检验事实、来源数量授权与实际入库分离的跨模块决策及取代关系。当前完整规则分别由 [Quality 成品检验](../../apps/api/src/modules/quality/docs/finished-inspections.md)、[Procurement 来料正式清单](../../apps/api/src/modules/procurement/docs/receipt-acceptance.md)和 [Production 结案](../../apps/api/src/modules/production/docs/database/production-termination.md)维护，统一事实结构见 [Quality 模型](../../apps/api/src/modules/quality/docs/unified-inspection-model.md)。未完成验收及正式测试见[路线图](../roadmap.md)。

## 统一职责与数量定义

数量草稿 → 质检记录 → 对应负责人引用有效记录并核对 → 正式依据 → 实际入库。

- `D`：发起检查时的申报数量快照，不自动等于现场实物量。
- `G / F`：本次检查的合格／不合格数，互斥且完整覆盖检查样本。
- `N=G+F`：实际检查数。抽检的 N 仅为样本，不能反推出整批数量。
- `C`：本次核实的整批未处置实物量，不是检后可用量。
- `A`：本次正式清单分配的可入数量；不是本次实际入库量。

**成品数量及范围裁决 [CQ-01](../documentation-conflicts.md#cq-01)**：部分类别已入库后，新复检覆盖全部剩余送检实物，已入部分不计入新C/G/F。发起复检时固定历史已入基准I₀并冻结剩余入库资格；新记录形成剩余实物的建议量R，累计建议S=I₀＋R仅供定稿核对，差异不阻止保存、送审或批准。首次I₀=0时同样只提供建议。保留检查事实、当时建议及最终清单的可追溯关联。当前定稿采用非阻断数量建议；固定I₀、剩余范围快照和复检开始冻结尚未实施，已有入库时只分列当前已入与本次建议，不用动态值补造累计建议。具体定义见[Quality已确认目标](../../apps/api/src/modules/quality/docs/finished-inspections.md#部分已入后的复检已确认目标待实施)。

质量检查样本不自动证明整批数量；来源原报D必须独立核实，不能直接替代C。不按样本合格率外推整批。不合格不自动代表已报废或已退货，实际处置分别留事实。来料与成品的数量建议、输入职责和依据要求分别维护在两侧所有者文档，不因公式一致而互换办理人员。

## 来料职责与数量授权

来料采用整批处理轮次与不可变执行分配。选择这一模型是为了把实物身份、办理资格、正式授权和实际处置分别保留，避免复检或更正改写已执行事实；不维护旧范围树或兼容双写。成品的审批、计划内上限及已入类别锁量独立保留。

### 来料数量授权

来料质检只填写全检／抽检、G/F、结论、检查时间及依据，N 自动计算，不再要求质检填写 C，也不展示零数量核实。普通检查 N 必须大于 0，数值及合计遵守存储上限。

库管定稿核实 C、分配可入／待退／待处理，并保存核对说明；系统提供数量建议 R。

来料可入数量由库管核实并负责，不把检查样本机械当成整批可入额度。库管有依据可确认超出检查建议的可入量，但所有正式分配必须完整覆盖本次核实量；数量差异说明不能推翻待复检／不放行结论，也不能改写原 G/F。

首次建议、同 QC 更正时已处置量的扣除、抽样异常以及必须留依据的条件，统一见[正式清单：数量与建议](../../apps/api/src/modules/procurement/docs/receipt-acceptance.md#数量与建议)。不累计历史质量结果或清单重新授予已消费数量；入库仍要求当前有效轮、明确放行和正式分配余量。

### 整批处理轮次

`receipt_line` 对应一次到货的精确物料与批次身份。`procurement_receipt_round` 表达该批未处置实物当前办理资格；不可变 `allocation` 表达去向授权，实际入退直接引用它，不再维护 scope 范围树。

轮次状态与换轮继承条件由[来料正式清单](../../apps/api/src/modules/procurement/docs/receipt-acceptance.md#整批换轮与继承)和[到货处置](../../apps/api/src/modules/procurement/docs/receipts.md)维护。

全检／抽检都对整批未处置实物判断资格；抽查100中的20不会拆成80继续可入、20检查。发起复检时，当前轮 superseded，使其可入／待退／待处理分配的全部剩余资格失效，分配事实不改写，创建新 reviewing 轮。新结果放行后重新整批定稿；已入库、已实际退回保持原事实，旧正式清单和旧质量记录也不删除。

新旧轮通过 previous_round_id 关联，source_allocation_round_id 只保留需要核对的既有采购归属／终止约束。旧分配不可变，按当前轮判断执行资格；部分入库直接新增实际明细，不拆父子行。已定稿无分配的零剩余轮清空继承来源，后续不得复活更早授权。

本次到货核实总量 T、实际已入 I、实际已退 B，当前未处置量 U=T−I−B。独立更正只输入本次到货 T，不能小于 I+B。原误登记可有依据归零，不创建零量检验或零量分配。真实新来货或损耗不能冒充实收更正。

库管本轮定稿校准 C 时，同事务追加必要实收修订并完成定稿，不重新回待检。只更正业务分配时，新定稿轮继承现有效 QC，不能任选较高的历史结果或重新授予已消费数量。

### 人工拒收与迟到提交

库管可在任一尚有未处置实物的阶段填写原因，拒收整批剩余。新 manual_rejection/finalized 轮生成 return/manual_rejection 分配，acceptance 可空，拒收人、时间和原因固定。当前拒收不能直接普通复检／定稿。部分人工拒收及已入库退货仍不在此入口。

允许显式“撤销人工拒收并重新办理”：原因必填，仅当前拒收且有剩余时追加 rejection_revocation/uninspected 轮；不改总量、不新增 revision，不恢复旧可入分配。已拒收批次发生独立实收更正时也一律为 receipt_correction，正剩余回 uninspected，零剩余可办结；如仍拒收必须再次决定。两者保留原拒收及已入／已退事实，不解除已有采购终止约束。

检查中拒收会在同一事务把未完成 Quality case 标为 superseded。旧页面迟到提交直接返回状态冲突，不先插一条结果再作废。已经完成的检验保留真实历史，不能因拒收覆盖。

人工拒收不等于质检不合格，也不等于实际退回。实际退回引用当前拒收 allocation，校验真实 manual_rejection 轮并登记交接；允许无 QC 及正常 acceptance，但不能没有分配／拒收依据。普通质量／超发／采购终止退回仍要求正常正式依据。人工拒收及其退回不取得质量补发资格。

## 成品数量与职责

成品保留独立现场实测C，由产线管理员核对清单、工单负责人批准；库管按有效正式批准量实际入库。质检计算仅提供定稿数量建议，不决定最终批准数量，也不把来料库管的定稿职责或强制超建议说明套入成品。

当前输入和计算见[Quality成品数量规则](../../apps/api/src/modules/quality/docs/finished-inspections.md#数量输入与放行)，固定基准与剩余复检目标见该文的已确认目标章节。普通检验须有真实检查，零产出使用独立核实方式；实际报废独立处理。负责人批准后，仓管按类别收齐一次确认入库。计划内任务计划约束、已入类别锁量、整数及检验计数合法性保持。

CQ-01取代成品以质检计算量限制定稿数量的硬门禁，以及将历史已入量计入新检验的范围定义。已确认目标为：明确放行后，全检建议R=G、抽检建议R=C−F，固定基准I₀形成累计建议S=I₀＋R。计划内A＋计划外E与S不同只提示并保留差异，不新增强制超建议说明或额外审批；原有产出说明、更正原因及负责人审批保留。不自动改G/F、产出或库存，不叠加历史建议。实际入库继续受有效正式批准数量约束，不能靠重复引用建议增加执行额度。

复检开始即冻结全部剩余入库资格，直至形成有效新批准依据；待复检／不放行不能恢复旧资格，取消清单更正也不能隐含恢复已暂停的旧放行。旧批准版、检验记录和实际入库事实继续保留。数量非阻断规则属于当前实现；固定基准、剩余范围快照及复检开始冻结仍待实施。剩余实施与验收统一列于[路线图](../roadmap.md#cq-01成品剩余复检整改)，不据本决策新增在库质量、成品出库或已确认入库冲销能力。

## 正式依据与实际执行

```mermaid
flowchart LR
  D["来源数量草稿"] --> Q["Quality 检查事实与结论"]
  Q -->|"明确放行"| V["来源负责人核对正式清单"]
  V --> B["有效正式依据；成品继续审批"]
  B --> W["库管确认实际入库"]
  W --> I["Inventory 唯一库存账本"]
```

“引用”针对某版有效记录，不设置“采用多少件”字段。例如C10、正式可入9，本次实际入8，正式可入余量为1，其余实物按独立处置保留。历史记录不可覆盖，不能多次引用同一份额重复入库。

到货、质检、正式清单均不写库存。只有实际入库通过 Inventory public 能力写 inventory_transaction，首次生成内部批次，后续沿用同到货批次。一次采购入库可选同供应商的多个有效正式范围；逐条检查轮次、版本、分配、QC及余量。更正／复检／拒收／入库／退回在同一批次上事务互斥，成功审计同事务。

## 采购归属、超量与补发

同次到货先按实物检验，再由库管分配。计划100、到货120、全检118/2，可选择原单可入118＋质量待退2，或原单100＋补单18＋质量待退2，或原单100＋超发待退18＋质量待退2。归属改变不重复到货、检验或批次。

超量承接补单 existing_receipt 首次绑定计划等量的正式可入量；未生效先留待处理。换轮保留未消费采购归属，数量未变不能换挂，变化按净差额显式核对，不能恢复一次性绑定资格。实收更正不提交归属分配；后续定稿或拒收时核对。拒收遇补单且继承总量与当前剩余不同，须填写 ownership，不能自动挂回原单；实际全退后解除处置待办，历史绑定仍保留。

质量补发 new_arrival 引用有效质量退回处置和供应商约定，可以先补后退，不要求原单先关闭；补发另走到货、检查和入库。真实实际退回单独跟踪。采购人工逐行关闭，正式可入余量加已入事实按各行归属统计，不合计历史正式清单，不用补单凑原单计划。

## 适用范围

当前只覆盖来料和成品。后续检查可复用G/F事实及“草稿—检查—负责人确认—执行”职责顺序，但必须先确认是否破坏性取样、是否存在返修或独立消耗，以及来源数量授权，不能默认所有新检查都套C−F或库管超建议例外。

本文取代[ADR-0013](0013-procurement-source-and-stock-boundaries.md)中独立剔除量、检验后直接可入、检前按采购拆批、来料部分复检和 QC 数量硬上限的旧语义；其余单工单采购、逐行供应商、需求独立及库存边界保持。[ADR-0014](0014-task-material-policy-and-output-inspection.md)的成品数量选择由本文归并，其当前公式由 Quality 所有者文档维护。字段和执行条件各归模块，不建立兼容双写或第二套库存事实。
