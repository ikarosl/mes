# ADR-0009：研发轮次结案、产出处置与物料余量

状态：Accepted

## 背景

研发需要在同一生产任务内使用同一基础物料的多个版本，也需要结束一次试制后，使用新成品编码、新工单继续下一轮。旧轮次可能只有部分可用产出，或者全部产出报废。现有报废补料命令会生成补料需求和产品补产授权，不能直接用于已经决定停止的研发轮次。

## 决策

1. 研发流程固定为：**结束本轮 → 登记可用产出、报废和差额 → 关闭旧工单 → 可用部分手动入库 → 新成品编码、新研发单继续下一轮。** 全部产出报废时只登记报废并结案，不办理入库。
2. 研发保留 BOM 内同一基础物料的多启用版本选择和现有数量校验，用于本轮拼版。下一轮创建新的成品记录和工单，旧单、旧产出和库存仍关联旧成品，不改旧编码，不继承旧 BOM 的批准事实；新生产任务仍须通过新成品 BOM 审批门禁。
3. 本轮结束后的产出报废属于停止生产时的业务处置，记录来源工单/批次、数量、原因、确认人和时间，不触发补料需求或补产授权。不建设报废库、废品库存或销毁管理；报废记录不等于已销毁证明。
4. 此处报废只覆盖尚未入库的本轮产出，不增加或扣减库存，不重复扣除已经领用的原材料；已入库库存的后续报废仍属于未开放的通用库存报废范围。生产报废处置须核对既有来源，不能重复统计同一产出的报废事实。
5. 工单关闭停止本轮生产，不代办库存入库；有可用产出时在现有入库管理页通过按钮和弹窗按实际量确认，已关闭来源工单仍须可追溯并办理待入库产出。生产终态与产出处置进度分别表达，可用产出为零不代表没有发生生产。
6. 成品计划差额与剩余物料是不同数量。管理员核对现场实物、决定未领需求是否继续需要及实际退料量，系统提供需求、分配、领料、退料和损耗记录并校验业务额度，不根据成品差额或 BOM 自动推算物料消耗、余料、退料或损耗。
7. 未确认出库的部分只处理需求、出库单和预留，不生成退料流水；已领且可退的余料沿原精确版本、原库存批次退回公共可用库存。退料不恢复需求，不改变历史领料履约，不替代工单结案。已消耗或损坏的部分不得作为余料回库，也不得为了结案调用会自动补料的损耗命令。
8. 研发沿用共用的生产批次结束、工单关闭和成品入库能力，不建设独立研发子系统。正常产出与额外产出的来源分类独立于可用/报废处置，普通产出的报废部分不改为 `production_extra`；额外产出仍按独立入库、独立库存批次的规则处理。

## 所有权与实施边界

Production 所有研发结案和产出处置，Product 继续所有成品、BOM 与物料版本。库存和需求分别只以 `inventory_transaction`、`production_item_demand` 为事实来源；不建立现场物料实时耗用账本，不扩展完整 Quality。

具体实现边界见[批次结束设计](../../apps/api/src/modules/production/docs/database/production-termination.md)；关闭、终止产出处置和实际入库是分开的命令，须分别完成契约与并发门禁后开放；不修改已执行 migration，不建立双写或影子表。
