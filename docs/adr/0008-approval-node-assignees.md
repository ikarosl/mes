# ADR-0008：单节点待办与角色或指定用户审批

状态：Accepted。业务关联人员由 [ADR-0011](0011-task-closeout-output-list-and-finished-goods-inbound.md)补充；角色／指定用户不再是全部分派类型。当前完整规则、接口和资格校验见 [Approval](../../apps/api/src/modules/approval/README.md)，字段约束见[数据库设计](../../apps/api/src/modules/approval/docs/database.md)。

## 背景

原实现为每个角色成员创建个人任务，新增成员必须人工重新分派才能处理已有节点。这与“同级任意一名合格人员即可决定”的业务需求不符，并使任务快照与实时角色资格互相制约。

本决策取代 [ADR-0006](0006-approval-workflow-boundaries.md) 的个人任务及人工重新分派语义，选择共享节点待办与实时资格判断。

## 决策

1. 每个节点只有一项共同待办；多人是候选资格，不是多份任务。多级仍顺序执行，首期不引入会签、认领、代理或转交。
2. 流程版本固定人员来源规则；角色节点实时解析合格成员，指定用户固定身份，后续业务关联人员在送审时解析并冻结身份。账号与审批权限始终实时校验，配置身份不自动授予权限。
3. 角色人员变化直接影响未结束节点的当前资格；无人时保留节点并显示阻塞，不自动批准、不按查询修改事实，也无需重新分派。固定人员不自动转给其他人，新流程不改写在途申请。
4. 任一合格人员明确决定即完成本节点；并发只接受一次有效决定，业务生效、决定记录和成功审计同事务。允许自审及同人逐级处理，但每一级必须独立操作与记录。
5. 通知与待办分别保存事实。节点激活通知当时的收件人不决定此后的资格；新角色成员不补写旧收件记录，无收件人不代表全员广播或自动批准。当前通知触发规则见 [Approval 通知事件](../../apps/api/src/modules/approval/README.md#通知事件)，事务及外部扩展选择见 [ADR-0007](0007-general-notification-boundaries.md)。

## 查询与历史可见性

当前合格人员可以查看活动申请；申请人和实际决定者保留相应历史访问资格。曾是候选人、曾收到通知或后来加入角色，都不单独授予历史全文访问权。列表与详情使用同一规则，前端不得提交授权人员集合；全局读取与接口入口权限的区别见 [Approval HTTP 与权限](../../apps/api/src/modules/approval/README.md#http-与权限)。

## 实施边界

当前配置、分页、决定、通知和历史可见性以 Approval 所有者文档为开发入口，不恢复个人 taskId 授权。数据库、迁移和交付遵守仓库公共规则，未完成验收见[路线图](../roadmap.md)。
