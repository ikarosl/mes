# ADR-0011：任务统一结案、产出清单与成品入库

状态：Accepted（已确认业务边界与流转顺序，未实施）

## 背景与适用范围

正常生产、短产和中途停止都需要核对最终产出。实际投入余量不能由计划或 BOM 准确推算，工序报工数量也不能直接当作仓库实收数量。产线申报、线下检验后的数量确认、生产结案审批分别承担不同职责；仓管依据有效批准清单和实物核对结果确认入库。质检确认属于产出处置业务，不是通用审批流程的第二级。

本决策补充 [ADR-0009](0009-research-round-close-and-output-disposition.md)。任务指生产批次，清单和入库均须关联任务 ID，并保留来源工单、成品身份及库存批次关系。本节是下一阶段目标，不表示当前正常完工、打印清单、成品入库或清单更正已经实现；实施顺序见[路线图](../roadmap.md)。

## 任务结束与审批

1. 未实际领料且未开工的任务仍使用取消，处理待出库、预留及活动需求。已经领料后即使全部退回，也不抹去执行事实并改为未执行取消。
2. 所有实际执行过的任务统一经过任务结案审批，包括正常完成、短产和提前停止。质检保存当次检验记录及实际清单，产线管理员据此核对产出处置单，随后由任务所属工单负责人审批结案；负责人取 `work_orders.work_order_owner_id`，不以任务负责人、申请人或某角色成员替代。管理审批复用通用 Approval，结案放行节点必须由该负责人处理；其他管理节点按实际管理要求配置，不因存在生产、质检两个业务角色而固定为两级审批。短产作为数量差异及结案依据，不另建独立短产审批流程，也不因未达到计划而强制补产。
3. 保留现有工序报工的计划量、前道放行及补产授权规则。区分工序执行结束、结案审批和任务最终结案，不因管理员登记最终产出而反写报工或扩大工序额度。正常完成与提前停止保留各自原因和执行事实，不把正常任务伪装成提前终止。
4. 提前停止继续使用现有逐项收尾能力；正常完成只处理实际存在的未决事项。产线管理员送审前核对物料，有可退余料时先办理实际退料，已耗用或损坏部分据实记录；审批查看已执行的操作和安排，不按成品差额推算余料，也不要求把所有已领物料退回。
5. 审批驳回或撤回允许补正清单和说明，不恢复已经关闭的需求、工序或已经发生的退料事实。任务结案与成品入库进度分别表达，任务已结案可以仍有待入库产出。

## 草稿、线下检验与数量

业务职责：

| 环节 | 职责 | 结果 |
| --- | --- | --- |
| 产线申报与核对 | 登记生产情况、产出草稿、工序报废来源和物料安排；依据质检记录填写或修正最终清单 | 申报数量、引用的检验记录及收尾依据 |
| 质检记录 | 线下检验、点数，保存当次实际清单、检验结果及凭据；无权改写产出处置单 | 独立留存的当次检验记录 |
| 生产结案审批 | 工单负责人审核生产情况、收尾结果、质检确认数量、差异及报废处置，决定是否允许按这些结果结案 | 对特定清单版本的批准或驳回 |
| 仓管入库 | 对照最新有效批准清单核对实物并确认接收 | 实际入库记录及库存流水 |

确定顺序：**生产执行结束 → 产线填写产出处置草稿 → 质检保存当次检验记录及实际清单 → 产线管理员据此核对并修正产出处置单 → 工单负责人审批 → 产线交接实物 → 仓管按批准清单核对并确认入库。** 管理审批同时查看质检记录、最终申报数量及收尾事实；质检记录是送审前的业务依据，不占用通用审批节点。

- 每个任务一份产出处置单，初次申报不要求立即定稿。质检确认与管理员申报的差异保留依据；同一版本的数量须在送审前明确，提交后锁定本次审批证据，最终批准形成可打印、可追溯的入库依据。审批人在审批节点不直接改数量；送审后数量或检验依据改变，须撤回／驳回后修正并重新送审。
- 质检仅保存自己当次的检验记录，不编辑产线草稿，也不替管理员修改最终数量。记录关联任务、当时申报版本／数量、实际检验数量与结果、记录人、检验时间及凭据，保存后不覆盖；复检或记录纠正另存关联的新记录。产线管理员只能引用，不能修改质检原记录。送审须引用与最终数量相符的有效检验依据，不能改量后静默沿用不相符的旧记录；审批快照保留所引用的具体记录及双方数量。
- 检验记录中的申报版本是当时的来源快照，不要求与随后送审版本号相等。例如原申报 10、质检实检可用 8，管理员依据该记录将清单改为 8，可继续引用该记录；核对的是最终数量与检验依据是否一致，不因管理员据实改量而要求重复质检。
- 清单批准的是“可入库数量”，库存仅由仓管实际确认入库产生。草稿阶段允许反复修改；送审与批准后按冻结及更正规则处理。仓管对生产流转、额外产出两类分别收齐后一次确认，不开放同一类分次收货。例如批准计划内 10 件，须核对收齐 10 件后确认，不能先入 6 件再入 4 件；两类可以在不同时间分别办理。
- 三个登记区域为计划内产出、报废、计划外产出。计划内可入库量不超过任务计划量；计划外承接超出计划的可用产出。计划外产出和新增报废不按计划量封顶，保留非负整数及存储安全范围校验，不要求可用产出与报废合计等于计划量。
- 计划缺口按“计划量 − 计划内可用产出”计算；报废不能计入达标数量。计划 10、可用 8、报废 2，计划缺口仍为 2；可用 12 时，计划内 10、计划外 2。
- 报废区只读展示已有的已确认工序报废，新增报废只登记此前未记录的部分；累计报废为两者合计。质检可提出新增报废数量和依据，结案审批审核该处置；不合格或未处置异常不直接等于报废，需要返修／复检的不能直接填为最终报废或可入库成品。原材料领料损耗不与产品报废相加。最终新增报废不触发补料、补产或库存变化。
- 一期线下完成质检，系统提供上述轻量检验记录留存，不建设在线检验、检验批、抽样或完整 Quality 模块。检验记录不是产出处置单的影子表，也不写库存或工序报工。半成品及待判定实物的结案分类留待后续，不在本阶段新增。
- 研发共用本流程，不记录研发成功／失败结论；人员决定是否新建成品编码、新工单和下一轮任务，旧任务按实际执行情况结案，原有拼版多物料版本能力保留。

## 清单与仓库入库

1. 入库管理页按任务选择批准清单，带出最新有效批准版本及对应可入库／已入库／待入库数量。清单包含任务、成品、两类可入库量、报废信息及审批信息，支持产线管理员线下交接。
2. 生产流转入库与额外产出入库分别办理，共同关联任务和批准清单，形成不同库存批次；额外产出来源为 `production_extra`。报废只留记录，不进入成品库存；零可用产出不生成零数量入库。
3. 两类入库不要求按先后顺序办理，不重复计量。每类确认量等于最新有效清单批准的该类全部待入量；生产流转量同时受任务计划量约束。任务每类只有一次有效确认，未确认草稿可以修改／取消重建；确认后保留真实数量，不再另建同类入库追加收货。待入量按批准数量与有效入库事实核算，不随库存被领用而恢复。
4. 仓管核对实物及清单后明确确认，才生成库存批次和流水。提交时校验任务、清单批准状态、有效版本、数量、并发及重复确认，不能只靠前端按钮状态控制，也不能由结案审批自动入库。

## 数量不符与清单更正

1. 仓管线下发现不符可直接拒收，不要求创建系统拒收单或差异单，不确认入库、不生成库存流水。
2. 产线管理员核实：漏送则补齐后继续使用原批准清单；批准数量确实有误，才发起清单更正，记录原清单、原数量、新数量、差额及原因。短少不自动登记为报废。
3. 批准后的数量更正重新走工单负责人的管理审批，复用通用审批能力；涉及检验数量或依据变化时，先重新核对质检结果，再提交更正审批。原批准清单及审批证据保留，新批准清单明确关联原版；不建设独立差异账本或影子表，不覆盖历史批准事实。首次送审前的质检核定属于草稿形成，不作为已批准清单的更正审批。
4. 更正送审期间暂停受影响产出的入库。批准后只有新版作为有效入库依据；驳回或撤回不改变原批准数量，已确认的不符仍须线下核实或重新更正后再收货，不能以驳回自动视为数量一致。
5. 仓管第二次按最新有效清单核对，一致后入库。入库事实关联实际采用的批准版本，旧纸质清单不能绕过服务端版本校验。
6. 清单更正不重开生产工序，也不修改已发生的入库。针对计划内／计划外可入库数量，已确认类别的批准数量保持不变，只允许更正尚未入库类别；不能通过增大已入库类别批准数量绕开“一类一次确认”，也不能减小数量消除原入库事实。该限制不把报废等非入库信息一并锁死，它们仍按清单更正保留前后依据及审批。已入库后发现收货事实错误，需要另行定义受控入库更正／冲销，本决策不提前开放该写入口。

追溯关系：**原批准清单及审批 → 更正原因与前后数量 → 新版批准清单及审批 → 实际入库记录。** 线下拒收不必产生系统单据，数量差异由清单更正及两次审批保留。

## 实施边界

工单负责人审批需要扩展现有 Approval 的人员来源能力。现有角色／指定用户仅能固定角色或某个用户，不能自动随不同工单选择负责人。扩展方案见[审批设计：业务关联人员](../approval-design.md#7-业务关联人员分派扩展待实施)：流程版本保存人员来源规则，每次送审由 Production 解析该任务所属工单负责人，Approval 保存本次解析结果并校验实时资格。结案负责人约束由场景后端校验，不能只依靠配置界面约定；不为每位负责人单独发布流程版本。

Production 所有产出处置、任务结案及生产来源入库业务，Approval 所有流程、节点和审批事实。`inventory_transaction` 仍为唯一库存事实来源；成品身份、数据结构及事务关联在所属模块设计中明确后，通过追加 migration 落地，不直接把成品 ID 写入现有物料外键，不引入双写或兼容影子表。

已有逐项收尾及物料需求纠错先完成当前验收；随后实现统一结案和清单，再实现成品库存身份及两类入库，最后完成联合验收。补料管理仍排在全部成品入库任务完成之后。具体未完成事项只维护于[路线图](../roadmap.md)，不在本文记录实施流水。
