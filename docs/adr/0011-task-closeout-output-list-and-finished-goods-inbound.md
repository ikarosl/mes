# ADR-0011：任务统一结案、产出清单与成品入库

状态：Accepted。本文保留跨模块职责及选择依据。当前完整规则见 [Production 结案设计](../../apps/api/src/modules/production/docs/database/production-termination.md)、[Quality 成品检验](../../apps/api/src/modules/quality/docs/finished-inspections.md)及[成品入库](../../apps/api/src/modules/production/docs/database/finished-goods-inbound.md)。数量与统一事实的后续选择见 [ADR-0015](0015-unified-quality-quantity-semantics.md)，不改变负责人审批、批准清单及每类一次入库边界。

## 背景与适用范围

正常生产、短产和提前停止都需要核对最终产出。计划与 BOM 不能准确推算余料，工序报工也不能直接代表仓库实收。因而把生产执行、独立检验、生产处置、结案审批及实际入库分别保存为各自负责的事实。

本决策补充 [ADR-0009](0009-research-round-close-and-output-disposition.md)。任务指生产批次，清单和入库均关联任务、工单、成品及库存批次。研发共用此流程，不增加独立成功／失败结论或研发子系统；旧轮产出继续归原成品和原任务。

## 任务结束与审批

- 未实际领料且未开工可取消；执行过的任务统一经过结案审批，不能因全部退料抹去执行事实。正常完成、短产和提前停止保留原因差异，短产不另设审批流程，也不强制补产。
- 批量执行保留工序报工及补产额度，研发使用任务级开始和结束。登记最终产出不反写报工或扩大工序额度。
- 产线管理员先逐项处理实际未决事项、实核物料并登记产出，再送审。可退余料实际办理，损坏及耗用据实保留，不要求退回全部领料，不按成品差额推算余料。
- 结案最后节点由所属工单负责人处理，不能用任务负责人、申请人或某角色成员替代。质检不是通用审批节点，不因有生产和质检两种职责而固定两级审批。驳回／撤回不撤销已发生的收尾与物流事实。

## 草稿、线下检验与数量

| 环节 | 唯一职责 |
| --- | --- |
| 产线管理员 | 保存草稿，依据实测修正计划内、计划外及实际报废，核对物料与收尾事实 |
| Quality | 独立保存不可变检查事实、明确结论及凭据，不改产出处置单 |
| 工单负责人 | 审核特定清单版本及其证据，不在审批节点直接改数量 |
| 仓管 | 对照最新批准依据核对实物并确认实际接收 |

固定职责顺序为：执行结束 → 产出草稿 → 独立质检 → 管理员核对 → 负责人批准 → 实物交接与入库。质检和批准均不自动产生库存。

每任务一份产出处置单，草稿可修改，送审后冻结证据；数量或依据变化须撤回／驳回后修正重提。原申报数量、版本只是当时快照，不锁定实测；在既有有效放行范围内修正申报或分类不要求重复检验。新增送检实物、重新纳入不合格品或结论变化须新增整批依据，保留前驱，不累加历次放行量，不建立局部范围树。

成品全检、抽检、零产出核实的输入、公式、凭据和差异示例统一见[Quality数量规则](../../apps/api/src/modules/quality/docs/finished-inspections.md#数量输入与放行)。按ADR-0015，检验计算量只作定稿建议，不因清单或历史已入量超过本次建议而拦截送审、批准；仍须最新检验明确放行。计划内不超过任务计划；计划外和新增报废不按计划量封顶，不要求三者之和等于计划。成品由产线核对、负责人审批，职责不变。

报废独立于质检不合格、少申报和原材料损耗；历史已确认工序报废只读引用，新增只记尚未记录的实际报废，避免重复。计划缺口按计划量减计划内可用产出，报废不计入达标。最终报废不补料、不补产、不写库存。半成品、待判库存、已入库质量冲销与完整在线质量仍不在本决策范围。

部分类别已入库后新检验的 C 范围已按 [ADR-0015](0015-unified-quality-quantity-semantics.md#成品数量与职责)明确为剩余送检实物，固定已入基准并在复检开始冻结剩余入库；代码仍待整改，差异证据保留于 [CQ-01](../documentation-conflicts.md#cq-01)。已入类别锁量与历史事实边界保持，不能把已确认目标视为已经实现。

## 清单与仓库入库

批准清单形成可打印、可追溯的入库依据。生产流转与额外产出分两类、各建独立批次，可在不同时间办理；每类收齐批准量后一次确认，零量不建入库。不开放同类分次追加收货，也不因库存后来被领用重新获得入库额度。

只有仓管核对并明确确认才写 Inventory 唯一库存流水。服务端重新校验来源、最新有效批准版、类别、数量、重复确认与并发，不能只依靠页面按钮，不能由结案审批自动入库。当前身份、类别槽位和事务规则见[成品入库设计](../../apps/api/src/modules/production/docs/database/finished-goods-inbound.md)。

## 数量不符与清单更正

仓管发现不符可线下拒收，不要求系统拒收单或差异账本。漏送先补齐；批准数量有误才由产线发起更正，保留原版、前后数量与原因，重新经工单负责人审批。短少不自动成为报废，仅在检验范围或依据改变时追加整批检验。

更正送审暂停受影响产出的入库；批准后新版生效，驳回／撤回不改旧批准量，也不自动证明实物一致。再次收货必须核验最新版本，旧纸质清单不能绕过服务端校验。

已入类别的批准数量锁定，不能增量追加或减量消除事实；尚未入库类别可按规则更正。本次建议与历史已入量不作阻断性比较，已入事实不重新计入新检验。固定基准和剩余范围快照仍属CQ-01待办，当前分列已入量与本次建议，不补造累计建议。报废等非入库信息仍可依审批更正；更正不重开工序，不提前开放已入库冲销。

## 实施边界

Production 所有草稿、实际处置、结案与生产来源编排，Quality 所有检验，Approval 所有流程及决定，Inventory 所有入库和账本。成品身份不写入物料外键，不增加影子表或第二套库存事实。

Approval 已支持业务关联人员：流程保存来源规则，Production 在送审事务解析工单负责人，Approval 固定本次身份并实时核验资格；不同工单复用流程。Quality 通过 Production 公开能力锁内核验来源，Production 通过 Quality 公开能力核验检验依据，两方不跨界写表。契约与锁序在所有者文档维护。

交付遵守仓库公共规则；未完成验收与正式测试见[路线图](../roadmap.md)，实现接入不代表用户验收通过。
