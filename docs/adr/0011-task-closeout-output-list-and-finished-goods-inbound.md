# ADR-0011：任务统一结案、产出清单与成品入库

状态：Accepted。本文保留跨模块职责及选择依据。当前完整规则见 [Production 结案设计](../../apps/api/src/modules/production/docs/database/production-termination.md)、[Quality 成品检验](../../apps/api/src/modules/quality/docs/finished-inspections.md)及[成品入库](../../apps/api/src/modules/production/docs/database/finished-goods-inbound.md)。数量与统一事实的后续选择见 [ADR-0015](0015-unified-quality-quantity-semantics.md)，负责人审批和批准清单边界保留；每类一次入库、类别独占批次和已入类别锁量由 [ADR-0016](0016-inbound-authorizations-and-stock-batches.md) 取代。

## 背景与适用范围

正常生产、短产和提前停止都需要核对最终产出。计划与 BOM 不能准确推算余料，工序报工也不能直接代表仓库实收。因而把生产执行、独立检验、生产处置、结案审批及实际入库分别保存为各自负责的事实。

本决策补充 [ADR-0009](0009-research-round-close-and-output-disposition.md)。任务指生产批次，清单和入库均关联任务、工单、成品及库存批次。研发共用此流程，不增加独立成功／失败结论或研发子系统；旧轮产出继续归原成品和原任务。

## 任务结束与审批

- 未实际领料且未开工可取消；执行过的任务统一经过结案审批，不能因全部退料抹去执行事实。正常完成、短产和提前停止保留原因差异，短产不另设审批流程，也不强制补产。
- 批量执行保留工序报工及补产额度，研发使用任务级开始和结束。登记最终产出不反写报工或扩大工序额度。
- 产线管理员先逐项处理实际未决事项、实核物料并登记产出，再送审。可退余料实际办理，损坏及耗用据实保留，不要求退回全部领料，不按成品差额推算余料。
- 结案最后节点由所属工单负责人处理，不能用任务负责人、申请人或某角色成员替代。质检不是通用审批节点，不因有生产和质检两种职责而固定两级审批。驳回／撤回不撤销已发生的收尾与物流事实。

## 草稿、线下检验与数量

| 环节 | 唯一职责 |
| --- | --- |
| 产线管理员 | 保存草稿，依据实测修正计划内、计划外及实际报废，核对物料与收尾事实 |
| Quality | 独立保存不可变检查事实、明确结论及凭据，不改产出处置单 |
| 工单负责人 | 审核特定清单版本及其证据，不在审批节点直接改数量 |
| 仓管 | 对照最新批准依据核对实物并确认实际接收 |

固定职责顺序为：执行结束 → 产出草稿 → 独立质检 → 管理员核对 → 负责人批准 → 实物交接与入库。质检和批准均不自动产生库存。

每任务一份产出处置单，草稿可修改，送审后冻结证据；数量或依据变化须撤回／驳回后修正重提。原申报数量、版本只是当时快照，不锁定实际检查数；在既有适用放行依据下修正申报或分类不要求重复检验。新增送检实物、重新纳入不合格品或结论变化须新增当前轮检验依据，保留前驱，不叠加历次检查事实，不建立局部范围树。

成品全检、抽检、零产出核实的 G/F 输入、凭据和结论统一见[Quality 数量规则](../../apps/api/src/modules/quality/docs/finished-inspections.md#数量输入与放行)。ADR-0015 的成品 C/R/S 建议公式现由 [ADR-0019](0019-finished-inspection-measurement-simplification.md) 取代；仅 Production 定稿引用 `full+released` 时按原检验轮固定已入基准加 G 给出非阻断差额提示，仍须适用检验明确放行。计划内不超过任务计划；计划外和新增报废不按计划量封顶，不要求三者之和等于计划。成品由产线核对、负责人审批，职责不变。

报废独立于质检不合格、少申报和原材料损耗；历史已确认工序报废只读引用，新增只记尚未记录的实际报废，避免重复。计划缺口按计划量减计划内可用产出，报废不计入达标。最终报废不补料、不补产、不写库存。半成品、待判库存、已入库质量冲销与完整在线质量仍不在本决策范围。

部分类别已入库后，新检验仍针对全部剩余送检实物所在轮次，固定建立时已入基准并在复检开始冻结剩余入库；Quality 不测整批 C。轮次及授权模型见 [ADR-0016](0016-inbound-authorizations-and-stock-batches.md)，实施验证与验收以路线图为准。历史事实边界保持；已入类别锁量由 ADR-0016 的历史已入下限及剩余授权取代。

## 清单与仓库入库

批准清单形成可打印、可追溯的入库依据。按 [ADR-0016](0016-inbound-authorizations-and-stock-batches.md)，计划内外分别形成不可变授权，可以分多次交接并选择新建或已有库存批次。类别归属不决定是否拆库批；没有剩余可入授权时不创建入库，库存后来被领用不恢复额度。

只有仓管核对并明确确认才写 Inventory 唯一库存流水。来源模块在锁内核验当前轮、有效批准依据、授权及本次总消费量；Inventory 核验目标身份及明细流水一致性。多条明细各自追溯当时的批准版与检验，主单不承担唯一批准版本。具体字段与命令由[成品入库设计](../../apps/api/src/modules/production/docs/database/finished-goods-inbound.md)维护。

## 数量不符与清单更正

仓管发现批准数量不符，由产线显式发起更正，保留原版、原因及历史执行，再经工单负责人审批。只调整有效检验范围内的剩余分配不强制重复检查；新范围或新结论另行检验。短少不会自动成为报废。

开始更正即固定历史已入基准并暂停旧剩余授权，最终批准只授予新剩余数量。已入类别的累计批准目标不得少于该类别真实已入量；库存明细、类别及原依据不回写。驳回、撤回及取消更正不隐含恢复旧授权。固定检查基准与非阻断建议规则见 ADR-0015，累计／剩余结构见 ADR-0016；均不开放已入质量冲销或重开生产。

## 实施边界

Production 所有草稿、实际处置、结案与生产来源编排，Quality 所有检验，Approval 所有流程及决定，Inventory 所有入库和账本。成品身份不写入物料外键，不增加影子表或第二套库存事实。

Approval 已支持业务关联人员：流程保存来源规则，Production 在送审事务解析工单负责人，Approval 固定本次身份并实时核验资格；不同工单复用流程。Quality 通过 Production 公开能力锁内核验来源，Production 通过 Quality 公开能力核验检验依据，两方不跨界写表。契约与锁序在所有者文档维护。

交付遵守仓库公共规则；未完成验收与正式测试见[路线图](../roadmap.md)，实现接入不代表用户验收通过。
