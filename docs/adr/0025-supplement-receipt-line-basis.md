# ADR-0025：两类采购补单统一关联到货明细

状态：Accepted。当前规则由 [Procurement 采购订单](../../apps/api/src/modules/procurement/docs/purchase-orders.md)维护；实施、用户验收及正式测试状态见[路线图](../roadmap.md#采购补单来源与办理待验收)。

## 选择理由

补单用于记录采购安排和来源，不承担每次退回与每次补发的逐笔核销。超量补购量需要结合合格实物和供应商约定由采购确认，质量补发量同样由人员决定；两者均能以原采购行、具体到货明细和依据说明满足追溯要求。

仓库分配记录表达一次处置及其执行授权。定稿更正可能拆分、合并或改变剩余实物去向，实际退回仍引用执行时的历史分配。采购固定引用某条分配，会额外引入历史当前性提示和引用更正能力，却没有相应的逐笔核销需求。到货明细在这些变化中仍保持稳定身份，适合作为补单来源边界。

## 决策

1. 超量和质量补单均保存原采购行、原到货明细及建单依据说明；质量补单不保存分配 ID，不开放后补关联、换绑或分配引用更正接口。选错原采购或整次到货时，按既有取消与结束规则处理，不以新状态改写物流事实。
2. 新建质量补单时，原到货明细须未作废，且存在当前有效质量退回分配或真实质量退回事实。只剩已失效、未执行的质量退回分配不提供新建资格；人工拒收、超发退回和采购终止退回不提供质量补发资格。具体分配仅用于服务端核验，不持久化为补单关系。
3. 新建资格与已有补单下单资格分开。已保存来源继续核对同源身份、未作废及采购资格，不要求建单时的处置条件永久成立。仓库更正、复检或执行不自动改变采购状态、数量和来源。
4. 两类候选按到货明细分页，每条明细只出现一次，并统一展示整次到货的处理数量，便于采购核对接收与退回安排。展示全部原因的退回量不改变质量原因资格；不合计历轮安排量、不把同一事实重复计入。具体数量口径见[候选查询](../../apps/api/src/modules/procurement/docs/receipt-queries.md#入库候选及正式分配)。质量退回单号可以用于搜索，但不能以任意一张退回单代表整条到货。
5. 补购量由采购核对后填写，不设置累计补购次数或数量上限。同到货明细、同补因的相关补单统一汇总，保留已取消记录和状态区分。系统不声明某张补单已经核销某次退回。
6. 超量补单只记录已有实物的补购，不新增到货、不分走原采购物流统计。质量补单有自己的新到货、检验、定稿和实际入退，独立统计。
7. 删除采购行的 `origin_allocation_id`、分配引用更正命令及专属 UI；既有全局操作日志保持原样，不新增历史表。仓库分配、轮次、实际入退引用及执行校验保持不变。
8. 到货作废仍被非取消补单的到货来源引用阻断。迁移只追加成对文件，不建立兼容双写，也不猜造回滚后的历史分配关联。

## 取舍

同一到货明细多次质量退回、多次补发时，系统提供共同来源、真实退回记录、补单数量和说明，不能通过关系字段精确配对某次退回与某次补发。现有轻量采购范围接受这一取舍；若未来出现逐笔核销需求，应独立设计，不把仓库授权 ID 直接作为核销关系。

例如一条到货实际因质量退回 2 件后，更正后的清单只包含剩余可入 8 件：该到货仍可作为质量补单来源；候选显示到货量 10、当前可入库 8、已入库 0、待退回 0、已退回 2，补单不需要选择旧分配或新轮次。

## 取代范围

完整取代 [ADR-0024](0024-quality-supplement-basis-correction.md) 的分配引用人工更正能力；取代 [ADR-0023](0023-supplement-source-and-receipt-ownership.md) 中质量补单精确引用分配、按该引用显示历史当前性及精确反查的规则，以及 ADR-0013 中质量补单精确关联退回分配的要求。ADR-0023 的物流归属、两类补单后续到货差异、创建与继续办理资格分离、来源作废依赖及仓库事实不可变规则继续有效。
