# ADR-0023：补单历史来源与到货采购归属

状态：Accepted。具体接口和操作规则由 [Procurement 采购订单](../../apps/api/src/modules/procurement/docs/purchase-orders.md)、[正式清单](../../apps/api/src/modules/procurement/docs/receipt-acceptance.md)及[数据库](../../apps/api/src/modules/procurement/docs/database.md)维护；实施、验收和正式测试状态见[路线图](../roadmap.md)。

部分取代：质量补单精确引用分配、历史当前性提示及精确反查由 [ADR-0025](0025-supplement-receipt-line-basis.md) 的到货明细级来源取代；[ADR-0024](0024-quality-supplement-basis-correction.md) 的中间更正方案也由 ADR-0025 完整取代。其他规则继续有效，下面记录本决策原有理由及边界。

## 选择理由

本项目不承担逐单财务履约核算。将同次到货拆给原采购与超量补单，会使补单办理时机改变采购物流统计，并把仓库更正、入库授权与采购手续相互绑定。补单只记录采购安排及其来源，足以支持现有追溯需求。

分配是不可变的一次处置判断。更正或复检会替代其执行资格，但不抹去当时基于它作出的采购决定。新旧分配可能拆分、合并或改变去向，自动换绑会改写补单成立时的依据。

## 决策

1. 到货、当前处置和实际入退始终归到货明细自身的采购行；分配不保存第二个采购行归属。质量补单自己的到货归其自身，不沿补单来源追溯链累计到最初原单。
2. 超量补单只保存补购数量和真实到货来源，不新增到货，也不取得原实物的物流统计。质量补单引用质量退回分配说明补发原因，后续新到货独立办理。
3. 新建补单原子记录来源并核验可选资格。仓库定稿不选择补单，实际入退可在补单办理前后发生。
4. 已创建补单保留建单时的历史关联。来源轮次被替代不自动换绑，不改变补单数量、状态或其自身到货资格。新建资格与已有补单继续办理资格分开。
5. 补单草稿只调整采购量和备注；依据选错需取消旧草稿并按新有效依据重建。不增加关联修正表、独立补关联接口或新旧分配映射。
6. 同次到货、同补因的相关补单跨轮次展示，并区分状态。提示旧依据已成为历史，不将历史引用解释为当前可执行授权。
7. 到货登记作废仍须先处理非取消补单引用；定稿被替代不解除来源依赖。实际执行事实及不可变历史不改写。

## 明确取代范围

本决策取代 ADR-0015 中超量补单承接实物、定稿选择采购归属、首次精确绑定及跨轮次保留补单份额的规则；取代质量补单正式下单时必须继续满足当前分配资格的限制。来料数量建议、QC 放行、超建议说明、采购终止约束和真实入退事实仍有效。

ADR-0013 的采购来源、需求独立和唯一库存账本，ADR-0018 的逐明细身份及跨供应商实际确认，ADR-0022 的人工采购状态和登记作废边界继续有效；其中对“正式承接事实”的取消检查及后续承接纠错设想由本决策取代。迁移只追加成对文件，开发旧业务通过统一初始化重建，不猜造历史归属。
