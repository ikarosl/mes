# ADR-0020：公共出入库单据与来源边界

状态：Accepted。适用范围为采购入库、批准成品入库、生产退料、其他入库、生产领料和其他出库六场景；用户验收及正式测试状态见[路线图](../roadmap.md#通用出入库后续阶段)。

## 公共主从与内嵌来源

采用公共 `inbound_order/detail` 与 `outbound_order/detail`，由 Inventory 整表所有，在明细内嵌有类型的来源外键。生产退料使用公共入库，不保留独立退料主从或第二份退料数量；Production 仍负责领退料资格、额度和履约，Procurement 仍负责采购来源资格。需求、分配、采购和产出授权保有各自独立事实，不因物流单据共用而归并。

轻量模块化单体的六个明确场景可以复用既有采购／成品来源字段，直接外键减少来源关联主从和联查。接受公共表了解来源结构的依赖成本；新增实际场景时按已确认需要增加来源字段和条件约束，不预建万能业务 ID 或插件式来源体系。

未选择“每个场景各建物流主从”，因为会增加其他入出库的独立状态和查询，并继续保留重复的退料物流字段。未选择“公共主从加每场景来源分表”，因为当前来源引用没有独立数量或生命周期，收益不足以抵消额外关联和组合约束。未来出现独立业务事实及生命周期时可建立所属业务表，本决策不构成永久禁止关联表的规则。

## 事实与范围

公共单据表达待办及实际执行，库存数量事实仍只来自不可变流水；来源授权、实际交接和库存变动分别保留。人工其他单只修正库存，不改变需求、分配履约、采购或产出授权。共用结构不放松来源资格，也不增加质检、审批、部分确认或已确认单据的通用撤销入口；盘点保持独立主从及物料范围。

## 预留反向读取的取代范围

其他出库必须保护 Production 的有效预留，但已完成生产领料事实由 Inventory 所有。因此允许 Inventory 定义窄读取端口，由 API 组合根适配器只通过 Production `public.ts` 取得目标批次的当前有效分配事实；Production 只锁自有分配，Inventory 当前读取自有已完成领料并核对未预留量。预留仍归 Production，不增加预留表或缓存数量。

此决定仅在**其他出库保护预留的只读事实协作**范围，取代库存协作协议原有的完全单向调用限制。它不允许 Inventory 反调来源任务办理资格、替来源选择版本、修改或释放分配，也不允许跨模块直接写表、深层导入或用展示查询承担命令校验。其余来源仍先在来源锁内核验资格，再调用 Inventory 实际记账；各模块仅锁定自有表。当前读、NOWAIT、整体回滚与有限重试遵守[库存协作协议](../inventory-extraction-design.md#其他出库保护生产预留的窄例外)。

字段、状态和数据库守卫由 [Inventory 所有者文档](../../apps/api/src/modules/inventory/docs/database/inventory-ledger-and-inbound.md)维护，端口由[公开能力](../../apps/api/src/modules/inventory/docs/public-contracts.md)维护。上述决策不授权双写、影子表或第二套库存事实。
