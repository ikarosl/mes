# ADR-0014：任务用料边界、研发执行与产出检验

状态：Accepted。当前任务用料规则见 [Production 工单设计](../../apps/api/src/modules/production/docs/database/work-orders-and-batches.md)与[需求设计](../../apps/api/src/modules/production/docs/database/demand-allocation-and-outbound.md)，产出与数量分别见[结案设计](../../apps/api/src/modules/production/docs/database/production-termination.md)和 [Quality 成品检验](../../apps/api/src/modules/quality/docs/finished-inspections.md)。本文保留业务选择及取代范围，验收事项见[路线图](../roadmap.md)。

## 任务与物料

1. BOM 继续由 Product 所有，只作为批量工单创建任务和生成初始需求的技术依据。研发仅凭有效成品和必要计划资料创建任务，不要求 BOM 或其审批，不复制路线、工序或虚构 BOM 基础。
2. 批量用料一致性范围从工单下降到任务。同任务同基础物料只使用一个精确版本，任务之间可以不同。在完整确认初始 BOM 需求的事务中，冻结该任务的版本和供应商提示；所有人工追加、工序报废补料及更正均须符合任务版本。确认后不改写该任务的版本，换版通过新任务表达，原任务按实际进度取消或结案。
3. 复用任务需求基础 `production_material_requirement_basis` 保存批量公式、锁定版本及提示，移除工单版本配置，不双写。研发直接生成无 BOM 引用的手工需求，首次与后续采用同一手工提需能力；实际物料、精确版本、单位、原始需求数量仍必须明确且不能被覆盖。
4. 研发后续可选择新的有效物料或版本；旧未领需求不再需要时独立关闭，新版本另提需求。日常数量更正继续保持原物料和版本，不建设跨版本替代链。供应商提示只服务本任务或本次研发提需，不限制实际库存供应商，不建立全局物料－供应商绑定；实际供应商由采购逐行明确。
5. 研发开工保留齐套或有效短批授权及已确认领料门禁，由任务级开始动作记录实际开工。研发不报中间工序，正常结束进入正常结案，提前放弃进入提前结案，不把所有研发都标为 terminated。剩余需求和未决物料单据须在结案中据实处理。
6. 批量与研发的在产损耗使用同一规则：只记录原领料、物料、版本、数量和原因，不自动生成补料需求。损坏是实物事实，追加需求是独立用料决策；原已领料履约不回退，需要更多用料时由管理员另提需求并明确数量。批量追加遵守任务版本锁，研发可选其他有效版本。损耗占用实际可退额度，不重复扣库存；结案损坏沿用不补料规则。工序异常报废补产方案仍按既有独立审批闭环处理。
7. 工单向有效任务分配的计划总量继续受工单计划约束，取消／终止任务释放计划额度的现有规则保留；实际可用产出可超过任务计划，以计划内、计划外分别登记。数量、库存和需求保持独立事实来源，不按成品差额倒推物料耗用。

## 产出检验

选择将检查事实、生产处置、批准依据和实际入库分开，避免原申报错误锁住现场实测数量，也避免不合格直接变成报废或库存变化。

1. Quality 独立保存检验和明确放行；Production 管理员依据实测核对计划内、计划外与实际报废，工单负责人批准，仓管实际确认入库。任何一方不得改写另一方事实。
2. 原申报版本和数量只作来源快照，修正原申报或计划内外分类不必重复检验；新增送检实物、重新纳入不合格品或结论改变须有新的整批依据。复检保留前驱，只以最新有效记录提供额度，不累加历次额度。
3. 全检、抽检、零产出核实的定义、公式和差异示例统一维护于[Quality成品数量规则](../../apps/api/src/modules/quality/docs/finished-inspections.md#数量输入与放行)。Production保持清单核对及负责人审批，计划内仍受任务计划约束。[ADR-0015](0015-unified-quality-quantity-semantics.md#成品数量与职责)已明确质检计算只作数量建议、不因定稿差异阻断；剩余复检、历史基准及冻结原则同样已确认。[CQ-01](../documentation-conflicts.md#cq-01)保留尚未整改的实现差异。
4. 每类成品收齐后一次入库，已入类别锁量；不开放已入库质量冲销、待判库存或完整在线质量系统。

## 与已有决策的关系

- 取代 [ADR-0012](0012-work-order-material-configuration.md) 的工单选版及跨任务阻断规则，保留计划额度和历史事实边界。
- 将 [ADR-0006](0006-approval-workflow-boundaries.md) 与 [ADR-0009](0009-research-round-close-and-output-disposition.md) 的 BOM 任务门禁限定为批量；研发轮次、历史产出与独立入库原则保留。
- 替换 [ADR-0011](0011-task-closeout-output-list-and-finished-goods-inbound.md) 的质检三项产出相等约束，保留独立质检记录、负责人审批、批准清单更正和入库规则。
- 同期落实 [ADR-0013](0013-procurement-source-and-stock-boundaries.md) 已批准的单工单按需采购、逐行供应商和统一表名前缀。采购只关联具体正式需求，源版本保持一致，后续数量和状态不自动联动。

## 实施边界

遵循模块化单体和已有模块所有权，需求仅以 `production_item_demand`、库存仅以 `inventory_transaction` 为事实来源。数据库只追加成对 migration，不改已执行文件、不建立兼容双写或影子表；无法真实转换的开发数据按统一入口重建，不伪造旧 BOM、质检或审批事实。

交付、用户验收和正式测试遵守仓库公共规则；实现接入不代表用户验收通过。

## 成品质检所有权与入口

Quality 所有不可变成品检验、复检与放行，Production 所有草稿、实际处置和结案。来源状态及申报依据在同一事务通过 Production 公开能力核验，不以展示查询替代业务校验。当前事实结构见 [Quality 模型](../../apps/api/src/modules/quality/docs/unified-inspection-model.md)，独立页面与结案引用交互见[成品质检页面](../../apps/admin-web/docs/finished-inspections.md)；不增加完整在线质量范围。
