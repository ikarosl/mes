# 任务开始与结束

任务生命周期由 Production 拥有，任务主表结构见[工单与任务](work-orders-and-batches.md)，逐盘执行、异常和最终产出见[追踪卡](execution-traceability-quality.md)。数量达到计划不会自动完成任务。

## 管理员任务开工与物料阶段

批量任务必须完整确认初始 BOM 需求基础，研发任务至少曾有一条正式手工需求，才能开始。需求已履约或已关闭仍是曾配置事实。开始不要求领料齐套；当前有未领需求时必须填写提前开工说明。首次开工时间、账号、说明及需求／已领／未领快照同事务保存，后续不覆盖；工单原为 released 时一并进入 doing。

POST /production/batches/:batchId/actions/start 使用任务 version，要求 production:batches:transition 和 Idempotency-Key。开工后任务 doing，后续领料不回退到物料阶段。现场人员到站身份与任务开工账号分别记录。任务页通过 GET /production/batches/:batchId/start-check（production:tasks:view）读取当前开工前提和缺料说明要求，提交仍在锁内重新核验。

## 人工结束与收口

POST /production/batches/:batchId/actions/finish 使用当前任务 version、必填原因、明确的正常完工或提前结束方式和 Idempotency-Key，要求 production:batches:transition。正常完工要求已开工且没有未完成有效卡或未处理异常；提前结束允许尚未开工或仍有未完成卡。两种方式均不要求最终产出达到计划，短产、零产出及超产如实展示，不补造产出确认事实。

结束事务先阻断在途需求更正审批、待确认退料和待确认领料损耗，要求先办理或取消这些单据。存在盘量为零且异常未结算的卡时，也须先完成关联报废结算。随后通过 Inventory 公开能力取消待领料出库单，释放有效物料预留，以 task_finished 原因关闭活动剩余需求。未完成卡保留原状态、工序和数量，任务结束期间禁止继续执行；结束不自动作废卡。已完成领料、退料、交接、异常、更正、报废、产出及入库事实均保留，已领事实不回退。

最后同一事务将任务转为 completed，保存结束原因、方式、结束账号、完成时间、版本和成功审计。任务状态不自动推进工单完工；工单由显式命令复核全部非取消任务已结束，不以产出足量为门槛。已结束任务仍可办理其待入库产出。

## 恢复执行

已结束任务可填写原因，通过显式恢复命令重新开放；已经开工的任务返回 doing，尚未开工的任务返回准备阶段并另行明确开工；所属工单必须仍为 released 或 doing，且按当前任务版本、权限及幂等规则核验。首次开工事实不覆盖；历史尚未开工即结束的任务在后续明确开工时核验首次开工前提并登记真实首次开工事实。取消任务不恢复。恢复只恢复执行资格，原卡从保留位置继续，不自动恢复已关闭需求、已取消单据、已释放预留或旧规则作废的卡。缺料通过普通提需和分配办理；继续生产及多次产出无独立补产类型。

不建立专门状态历史表，结束和恢复的前后状态、原因、操作者及时间沿同事务操作日志追溯；主表保存当前结束信息，首次开工信息保持原义。

## 未执行任务取消

取消仍用于尚未开工、没有实际领料的 pending/material_pending/material_assigned 任务，要求当前版本和原因。取消一并取消待领料单、分配及活动需求，并作废尚未使用的卡；存在实际领料或已到站执行则拒绝，须使用人工结束。取消不产生库存反向流水。

## 研发最终产出

研发任务没有路线和追踪卡；在 doing 时登记当前启用的现场人员，通过 confirm-research-output 多次确认实际产出，允许零。正数量进入待入库，零数量不记库存；各次记录相互独立，不覆盖前次。提前结束允许没有产出事实，不推测历史质量结论。结构及撤销规则见[最终产出表](execution-traceability-quality.md#production_tracking_output)。

## 库存与余料

任务结束只停止新执行和未履约安排，不把已领物料推算成现场库存。真实余料可在任务或工单结束后沿原分配办理退料，具体额度见[退料与损耗](return-scrap-and-stocktake.md)。实际出入库及库存余额继续只由 Inventory 所有，公共锁序见[库存协作](../../../../../../../docs/inventory-extraction-design.md)。
