# 表格模板与公开契约

Template 唯一拥有模板名称、表格内容、列填写规则、启停状态、编辑并发版本及已登记场景的默认绑定。模板在系统管理页统一维护，业务模块拥有填写结果；新增业务场景仍须确认产品范围、业务资料所有权及公开边界。模板不建立项目实体、项目数据隔离、动态脚本或通用表单引擎。

## 内容与复制边界

后续业务中仅用于描述、展示和留档，不参与计算、判定或状态流转的键值对及表格资料，统一复用现有模板与 `JsonTableData`。参与业务逻辑的数量、日期、状态和结论仍由所属模块定义结构化字段及校验，不从自由表格取值驱动业务规则。

模板内容使用共享 `JsonTableData`；完整字段规则、上限及规范化行为由 [utils JSON 表格](../../../../../../packages/utils/README.md#json-表格)维护。模板至少需要一列；未配置填写规则的模板允许没有数据行。

自由复制把完整表格复制到业务表单草稿，后续由业务模块按原接口执行权限、状态和并发校验，并保存独立的 `JsonTableData`。Product 等自由复制消费者不受模板列规则约束；模板改名、修改或停用不联动已复制的内容。Template 不访问消费者业务表。

## 设计与填写

`columnRules` 与表格内容分开保存，以列 key 为索引，将每列指定为 `fixed`（固定内容）、`required`（必填输入）或 `optional`（可空输入）。配置规则时须覆盖且仅覆盖全部列，至少有一行和一个可填写列；规则不改变 `JsonTableData` 结构。`columnRules = null` 表示自由复制模板，既有模板不推断填写意图，不能直接用作场景默认。

管理端设计模板时可编辑列、行、内容和规则；新填写草稿仅保留固定列内容，可填写列从空白开始，不能把设计中的预设文本视作实检回答。场景填写时保留模板列 key、列名、列顺序、行数及固定单元格，只允许编辑 `required/optional` 单元格。所有必填列每行均须有非空白输入，且可填写区域至少一格有非空白输入；固定内容不计作回答。单元格原文仍保留，空白判断只用于完整性检查。此校验只保证资料完整，不参与数量计算、质量判定、放行或状态流转。

## 场景默认与公开协作

当前只登记 `quality_incoming_inspection`，供来料首次检查和复检初始化填写草稿。每个场景至多一项当前默认配置，目标须启用、未删除且具有完整填写规则、有行及可填写列。新建模板不会自动改默认；当前不提供删除或清空默认的命令。已被绑定的模板不能停用或移除填写规则，须先将默认切换到另一合格模板；仍可修改其设计，按下述并发规则保护正在填写的草稿。

Template 经 `public.ts` 公开 `BusinessTemplateSceneQuery`，提供默认模板读取及活动事务内的提交核验；消费模块不得直接查询或写入模板表。默认绑定、被绑定模板修改和填写提交按一致顺序锁定场景配置及模板，提交只接受仍为当前默认的模板 ID、版本和设计，并重新校验填写内容。默认改绑、模板修改或停用等造成依据失效时返回 HTTP 409，保留草稿；重新加载须由用户明确确认，不能静默换用新模板或只更新版本号。

模板 ID 和版本是本次提交的并发校验依据，不是业务事实的持久引用。消费者保存填写后的完整表格，不保存模板发布版本或历史规则；已保存资料不随默认或模板变化，历史也不从当前模板补齐。各场景的草稿触发时点及业务输入范围由消费者所有者文档维护。

## 名称、启停与并发

稳定身份是 `id`；名称是可编辑的展示名，当前名称在系统内唯一，包含软删除记录，采用数据库排序规则；改名不保留旧名称占用。停用保留内容和历史，模板选择只请求启用项；管理读取可以包含停用项。当前不开放删除命令，软删除列按[数据库公共约定](../../../../../../docs/database-conventions.md)保留。

模板的 `version` 用于自身更新及填写依据的并发校验，每次名称、内容、列规则或状态修改均递增；它不构成业务发布版本或历史业务快照。默认配置有独立编辑版本。列表、模板设计草稿及默认配置草稿分别持有状态，读取失败不能成为可保存的空模板或未绑定状态；并发冲突保留草稿，重新加载须明确放弃当前输入。

## HTTP 资源

路径前缀 `/api/templates`；分页、ID、时间及错误结构沿用[公共 HTTP 规范](../../../../../../docs/api-conventions.md)。

列表按名称和 ID 排序；不指定状态时包含启用和停用项。新建、完整读取和局部修改的字段及路径见[HTTP 入口](../presentation/http/)，名称冲突与编辑版本冲突须区分处理，不能静默换版本覆盖草稿。本模块未启用 HTTP 幂等，遵循公共请求头规则。

模板管理使用独立的查看、创建和修改权限，默认配置读取及修改分别使用 `system:templates:view/update`；Product 或其他消费者的业务权限不授予模板管理。场景默认读取经消费者接口鉴权，来料使用 `quality:inbound-inspections:view`，不要求质检员同时拥有模板管理权限。权限目录属于 [Identity](../../identity/docs/database.md#14-permissions)，通过版本化 migration 发布，不自动给已有业务角色补授。
