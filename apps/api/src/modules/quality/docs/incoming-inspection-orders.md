# 来料质检分组主单（已停用）

来料质检分组已停用，当前页面直接按到货及物料办理检查报告，不再提供分组目录、新建或关联调整入口。分组专用主单列表、目标候选、主单详情及其到货目录、新建、备注和关联命令均保留并标记 `@deprecated`；现有权限、事务和幂等边界不变。共享到货列表、完整明细、精确定位及独立报告接口继续使用，读取范围由[到货查询](../../procurement/docs/receipt-queries.md#来料质检查询)维护。

Quality 继续拥有保留的分组主单及当前到货关联；停用不删除、解除或改写既有关系、编号和报告。两表定义见[检验数据库](database.md)，来源锁和资格见[到货办理](../../procurement/docs/receipts.md)，当前草稿及定位见[管理端来料交互](../../../../../admin-web/docs/incoming-inspection-adoption.md)。以下约束适用于保留的实现与数据，不表示分组仍是当前办理流程。

## 分组身份与检查事实

一张主单可关联不同采购、不同供应商的完整到货单，同一到货同时最多属于一张质检主单。关联只用真实 `receiptId`，单号不充当身份。创建时选择 1～100 张到货，之后可以继续增加；100 是一次命令涉及到货 ID 并集的上限，不限制主单累计关联总数。

主单没有待检、检验中或已完成状态，不承担入库资格。移走最后一张到货后保留空主单及编号；不提供删除、取消或归档。质检单号表示当前工作分组；独立报告另有服务端报告编号，不引用或冻结当前分组。分组不建设关联历史表或历史版本，保留空主单只能保留编号身份，不能据此还原该单号在过去某时刻关联的到货；历史报告仍按到货行及报告 ID 追溯。

现场已打印或贴附的质检单号不会随系统关联变化而更新。调整关联时须提示核对现场标签：转移到其他质检单后更新为新单号，解除关联后移除或作废旧标签；保留原主单不代表旧标签仍与当前到货归属一致。标签核对由现场人员完成，系统不据此冻结关联或新增标签管理流程。

首次检查前、填写中和保存后均可追加、解除或转移整张到货。关系变化不修改到货明细、不可变报告或库存事实，不冻结正在填写的报告草稿。检查提交只核验具体到货来源，不增加主单 ID 或版本条件。不同来源的检查不因分组而合并，跨到货合并检验仍在[产品范围](../../../../../../docs/product-scope.md)之外。

不向到货主表写分组缓存，也不复制供应商、数量、检查进度或质检物料明细。工作列表按当前关联到货读取报告数量和最近登记的报告摘要；摘要不代表检验状态或入库资格。建立分组不预造报告，未分组来源可直接登记、读取及打印报告。精确定位使用 `receiptLineId/reportId`，不猜历史分组归属。成品质检和采购主单供应商调整不属于本能力。

## 关系命令与版本

新建、追加、解除、转移均处理完整到货；客户端提交明确动作，不能把当前可见物料行当作整单范围，也不能用全量 `receiptIds` 覆盖关系。跨组必须明确转移，不因保存勾选抢占已有关系。

每条动作携带预期 `fromOrderId`，未分组为 `null`；同时携带全部受影响既存来源及目标主单的 `expectedVersion`。事务内同时核对当前归属和主单版本，任何一项变化返回冲突。关联没有独立版本，数据库与来源锁共同保证一张到货只有一个当前归属。新建主单连同初始关系以 version=0 返回；每个实际发生关系或备注变化的既存主单在一次命令中只推进一次版本，纯分组不推进到货版本。

首次纳入分组只接受存在且未作废的未分组到货，已检查或已处理完不构成排除条件。新建主单也可显式把已有分组的到货转入，须提交真实原归属及原主单版本。已有关系的来源后来作废时保留关联和历史；仍允许解除或移组，但不能首次关联原本未分组的作废来源。检查资格由 Procurement 独立判断，分组管理不授予检查资格。

主单创建、服务端取号、初始关联、成功审计和 HTTP 幂等结果同事务，失败不遗留空主单或额外取号。编号使用 `incoming_inspection_order` 类型，前缀只由共享 `BUSINESS_NUMBER_PREFIX` 定义，遵守[平台编号](../../../../docs/business-numbering.md)。修改备注只锁本主单。关联调整不强制业务原因，已有 `operation_logs` 保存到货 ID、原／新主单、前后版本及操作者，不新增关联审计表。

## 模块与权限边界

Procurement 按 Quality 场景权限核验来源，再在同池事务调用 Quality 公开命令。Quality 只写自己的主单及关联，不反向依赖 Procurement，不自行查询或锁定采购表，不为分组建立来源 Registry。固定锁序由[来源编排](../../procurement/docs/receipts.md#独立检验与分组)维护。

`/quality/inbound-inspection-orders` 由 Procurement 场景 Controller 提供，不改变表所有权。读取要求 `quality:inbound-inspections:view`；新建、备注与关联变更要求 `quality:inbound-inspections:manage`。报告登记使用 `quality:inbound-inspections:inspect`；不额外要求采购或仓储页面权限，也不存在按分组授予检查权限的模型。

版本或归属冲突须重新核对；未知结果按[平台幂等契约](../../../../docs/idempotency.md)保留原请求重试。展示读取范围见[查询契约](../../procurement/docs/receipt-queries.md#来料质检查询)。
