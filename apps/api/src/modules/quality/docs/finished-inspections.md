# 成品检验与放行

本文维护成品检验的数量定义、请求语义及定稿数量建议，是这些规则的主要维护位置。来料与成品共用[检验两表](database.md)，来料数量授权及其依据要求由 Procurement 的[正式清单与整批分配](../../procurement/docs/receipt-acceptance.md)维护。[ADR-0015](../../../../../../docs/adr/0015-unified-quality-quantity-semantics.md)保留共同边界、选择理由和取代关系。当前定稿数量使用非阻断建议；CQ-01的固定已入基准、剩余范围快照和复检开始冻结仍未实施，以下分开说明。

Quality 所有 `quality_inspection_record` 是每个任务当前整体送检的一次不可变检验事实。Production 所有产出草稿和批准清单，只引用记录；Inventory 根据批准清单办理成品入库。批量和研发共用本规则。

## 数量输入与放行

本节描述当前请求、事实计算及定稿建议。检验事实合法性和明确放行要求继续校验，检验计算量与清单数量的差异不构成保存、送审或批准的门禁。

全检分别填写实际合格数 G 与不合格数 F，服务端形成实际检查总数 N=G+F、送检总数 C=N；不能用产线原申报量减不合格数推算实检合格数。抽检填写实际送检整批总量 C 及本次样本合格 G、不合格 F，服务端形成 N=G+F，要求 0<N<=C。每项及合计均为 0..99999999 的安全整数，普通全检／抽检必须有实际检查数量；零产出使用专用核实方式，G=F=N=C=0 且明确完成核实。

只有明确 `released` 才产生本次建议量R：全检R=G，抽检R=C-F。现有契约字段仍名为 `releasedQuantity`；待复检或不放行该值为零，但零值不能代替明确放行资格；样本合格数只描述实际检查结果，不按样本合格率推算整批。没有独立的剔除数量输入，也不自动把不合格数登记为产品报废。

`RecordFinishedInspectionPayload` 与事实响应分开。请求提交 `inspectionMethod/qualifiedQuantity/unqualifiedQuantity/releaseDecision`，抽检必须提交 `coveredQuantity`；全检和零产出可省略该值，显式提交时必须与服务端派生值一致。请求不提交 `inspectedQuantity`。检验时间、结论和凭据仍必填。`normalizeFinishedInspectionFacts` 通过 `normalizeInspectionQuantities` 校验并转换为 C/N/F 应用输入（持久化统一 C/G/F）；写入、读取记录和 Production 审批解析通过公开纯规则 `evaluateOutputInspection` 复用同一数量校验及派生公式。

产线三项数量和版本保留为登记当时的来源快照，只供核对；不限制实际检验总数，也不自动改变实测 G/F。例如产线申报 10，质检核实实际有 12：全检填合格 11、不合格 1，形成 C=N=12；抽检填实际送检总数 12、样本合格 4、不合格 1，形成 C=12、N=5。两种情况明确放行后的本次建议量都为 11。管理端提示实物总数与原申报的差异，产线管理员随后修正计划内、计划外及实际报废，主动引用最新检验记录送审。质检不合格数不能自动作为已报废数量。

## 成品来源与统一事实

| 字段 | 含义与约束 |
| --- | --- |
| `id` | BIGINT UNSIGNED 主键 |
| `closeout_id / production_batch_id` | 非空来源；组合外键保证同一 Production 结案根／任务 |
| `declared_version` | 登记时 Production 根版本，非负，不要求等于后来送审版本 |
| `declared_available_quantity / declared_extra_quantity / declared_scrap_quantity` | 当时产线草稿三项参考快照，不由质检修改 |
| `inspection_method` | full / sampling / zero_confirmation |
| `covered_quantity` C | 实际送检整批总数；全检由 G+F 派生，抽检明确输入 |
| `qualified_quantity` G | 本次实检合格数；N=G+F只读派生 |
| `unqualified_quantity` F | 本次实检不合格数 |
| `release_decision` | released / pending_reinspection / not_released，必须明确选择 |
| `inspected_at` | 真实检验时间 DATETIME |
| `result_note / evidence_reference` | 结论及凭据，各非空且最多 5000 字 |
| `previous_record_id` | 当前根最新检验前驱；组合 FK 保证同根，不覆盖原记录 |
| `created_by / created_at` | 不可变事实操作者 FK users 与创建时间 |

统一结果只持久化C/G/F，N=G+F与建议量R按共同规则派生；成品原申报版本和三项数量移至case。响应/批准证据继续提供N与G的只读视图，不建立重复物理计数。字段/组合FK见[数据库](database.md)。

**当前定稿规则**：Production管理员决定计划内A、计划外E及新增报废。明确放行后的建议只作核对，不以A+E超过建议量或历史已入量超过本次建议为由阻断保存、送审或批准。不新增强制超建议说明或额外审批，原有产出说明、更正原因、物料安排及负责人审批保留。`A<=任务计划`、已入类别批准量锁定、整数与存储上限继续校验；不合格不自动转报废。

尚未入库时，页面比较A+E与本次建议R并提示差异。已有入库时分别展示当前累计已入量、本次建议及当前清单，不把动态已入量当成固定I₀，也不计算未经快照固定的累计建议S。固定基准、剩余范围和复检开始冻结仍见 **[CQ-01](../../../../../../docs/documentation-conflicts.md#cq-01)**；数量提示能力不表示完整剩余复检已落地。

## 部分已入后的复检：已确认目标，待实施

本节补充尚未实施的固定基准及剩余范围；上述非阻断数量原则已适用于首次定稿和更正。新复检覆盖本任务全部剩余送检实物。已经实际入库的实物及已单独处置的报废不混入本轮C/G/F，不能把未再次检查的历史已入量加到实检合格数。当前成品按计划内、计划外两个类别各一次入库，部分已入通常是一类已入、另一类未入，并不表示同一类别支持任意分次入库。

Production在发起复检时固定已入基准`I₀`及剩余送检范围，并冻结全部剩余入库资格。Quality记录本轮实际检验事实及明确结论，不决定计划内外分配、产品报废或库存处置；“质检不负责来源数量授权”不等于可以忽略G/F及其对应实物范围。抽检C仍须独立核实，不能由样本G/F反推。

| 数量／提示 | 全检 | 抽检 |
| --- | --- | --- |
| 本轮实际检查数N | G＋F | G＋F，仅为样本 |
| 本轮剩余送检总数C | G＋F | 独立核实的全部剩余送检实物量，0＜N≤C |
| 明确放行后的本轮建议量R | G | C−F |
| 任务累计建议量S | I₀＋R | I₀＋R |
| 定稿核对 | 比较A＋E与S，显示差异 | 比较A＋E与S，显示差异 |

这里A、E分别为任务累计计划内、计划外数量，与来料“本次分配可入量”的记号用途不同。A＋E与S不一致时系统提示核对，不因该差异阻止保存、送审或批准，也不自动修改G/F或产出数量。不新增强制的超建议说明或额外审批；原有产出说明、更正原因、物料安排及负责人审批继续保留。检验事实、当时建议和最终批准数量须能够关联追溯。

首次尚未入库时I₀=0，同样只提供建议而非上限。I₀固定于本次依据，后续执行不能用增长后的累计已入量再次加同一R；新旧检验建议也不能相加。已入10、剩余全检G=2/F=0时，新C=2、R=2、S=12，历史10件继续引用其真实旧依据；最终累计数量偏离12时保留差异，不以12直接卡定稿。

放开的是质检建议与定稿数量的比较，不是全部数量校验：A仍不超过任务计划，已入类别的批准数保持原值；整数、存储上限及检验物理计数合法性继续校验。实际入库按有效正式批准数量办理并防止重复，不能以建议量替代或自动扩大正式授权。

只有明确放行后，产线管理员核对更正清单并由负责人批准，才恢复剩余实物按新依据入库。待复检／不放行继续阻断；记录新G/F本身不生成正式授权，也不改库存。旧质量记录、批准清单与入库事实保留；已经入库后发现的质量问题不通过本入口虚构退库、冲销或重检全部实物。

实施差异与验收事项统一见[路线图：CQ-01成品剩余复检整改](../../../../../../docs/roadmap.md#cq-01成品剩余复检整改)，不在本章预设新增表或兼容结构。

## 不可变记录与事务

每次新记录代表本任务本轮完整送检范围；扩大送检实物或复检时追加新记录并关联前驱，只采用最新记录，不叠加历史检验数量。部分已入后的固定范围、累计建议与开始冻结目标见上节，当前不能用动态已入量补造历史基准。仅调整计划内外划分或减少草稿可用量不要求重复质检；实际送检范围变化仍须新依据，不能借差异提示混用不同批次实物。质量登记不替管理员选择引用；送审须主动引用当前记录。

命令先通过 Production 注册来源能力在同池活动事务锁定工单→任务→结案根，核对请求版本及草稿存在；非初次可编辑根须先办理清单更正。Quality 读取当前前驱、追加记录、写审计，Production 自身能力推进根版本。幂等 namespace 为 `quality.finished-inspection.record.v2`，指纹使用规范化后的 C/N/F、方式、决定及来源版本、时间和去首尾空白的说明／凭据。省略非抽检 C 与明确提交相同派生值形成同一规范化事实；有冲突则拒绝。结果仅含 batchId、inspectionId、version。

Quality 不写 Production 表。Production 送审和最终批准通过 Quality public 当前共享读重新核对联合指纹、最新记录与快照。UPDATE／DELETE 触发器禁止改写事实；保留 `(id,closeout_id)` 引用唯一键及 case的 `(closeout_id,id)` 与结果的 `(production_batch_id,id)` 查询索引。
