# 来料检验与来源协作

本文维护来料检验事实与来源、正式数量和库存的分工。表结构及约束见[数据库](database.md)，数量授权见[正式清单](../../procurement/docs/receipt-acceptance.md)。Production 的追踪卡和末道终检由生产模块独立所有，不通过 Quality 创建生产检查单或质检轮次。

## 所有权和流转

Quality 拥有检验办理和不可变 G/F 事实。Procurement 拥有到货、实收修订、整批处理轮次、正式清单及执行范围；Inventory 只记录真实库存。每份检查绑定真实到货明细、实收修订和处理轮，不因工作分组混合来源。

[来料质检分组主单](incoming-inspection-orders.md)及其关联表只组织完整到货，可跨采购、跨供应商；分组不成为检查来源，不冻结检查、合并 G/F 或改变逐到货明细的放行资格。主单没有业务办理状态，移动到货不修改逐来源事实链。

来料首次、复检均有明确开始动作。Quality 办理完成表示检查事实已完成；来源轮次分别表达待复检、不放行、待核对定稿。检验明确放行后，库管核实整批 C、确认分配并形成正式依据，再执行实际入库或退回。Quality 的明确放行本身不生成库存或数量授权。

全检和抽检都判断本轮整批实物资格，样本不是独立处置份额。复检在开始前替代本批所有尚未实际处置范围，统一形成新轮；已经入库或退回的事实不变。旧记录不能重新消费，不相加历史正式清单。

未完成检查因来源更正、拒收或整单登记作废而失效时，迟到提交直接拒绝，不生成新结果。整单作废由 Procurement 判断资格并建立终止轮，Quality 经公开命令终止各来源行仍在途的办理；已完成检验及 G/F 保留，字段和事务边界见[数据库](database.md)。

## 数量与执行资格

质检只填写全检或抽检方式、实际合格数 G、不合格数 F 和明确结论，自动派生 N=G+F，且 N 必须为正整数。实收零量通过来源更正处理，不创建零量检查事实。

整批 C 由库管正式清单确认；全检建议 G，抽检建议 C−F。库管超建议需非空依据，原 G/F 不可覆盖，分配总和仍须等于 C。定稿时 C 与申报量、全检 N 与 C 或抽检 N>C 的差异须有核对依据，完整校验由[正式清单](../../procurement/docs/receipt-acceptance.md#数量与建议)维护。

Quality 公开能力只核验精确检查事实、同源身份和明确放行。当前轮、正式授权、未消费数量及执行资格由 Procurement 锁内判断；展示查询和历史检查不能代替这些判断。
