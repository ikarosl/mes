# 附件引用与清理生命周期

附件对象一经登记不覆盖内容；每次上传生成新对象和新附件 ID。元数据、保留关系的表结构由[数据库设计](database.md)唯一维护，Product 的具体 SOP 选版与规格书输入语义见[技术文件](../../product/docs/technical-files.md)。

## 引用与业务协作

`attachment_references` 只表示对象仍需保留。它不是业务归属授权，也不供前端提交任意 owner／slot。

| owner／slot | 业务对象及引用归属 |
| --- | --- |
| `product_process_step/default_sop` | 工序当前默认 SOP，由 Product 决定何时替换或解除 |
| `product_route_step/sop` | 路线步骤 SOP；已发布路线停用、归档不解除，草稿释放由 Product 显式办理 |
| `product/specification` | 成品当前规格书 |
| `material_variant/specification` | 精确物料版本当前规格书 |
| `production_batch_step/default_sop` | 任务步骤冻结的默认 SOP 历史 |
| `production_batch_step/actual_sop` | 生产实际使用的 SOP 历史 |

Product 可在保存当前配置时替换该对象、用途的引用；编辑草稿路线或删除从未启用的整条草稿时，由 Product 的业务动作显式解除已丢弃步骤的当前引用。已发布路线不可删除，停用、归档不解除引用；主数据软删除不等同于解除。生产下达登记冻结的默认／实际 SOP 引用，引用能力只追加，不开放事后更换或普通解绑。Attachment 不自动级联解除业务引用。

业务命令先锁所属业务根并校验权限、状态、版本，再在同池事务内调用 `requireAvailable` 和引用服务。新增引用只接受启用、未软删且未进入清理流程的相应用途附件。资格校验和引用服务按附件 ID 顺序取得共享锁；回收和清理取得排他锁后读取当前引用，避免“检查后又被绑定”的竞态。业务更改、保留关系和成功审计原子提交，调用方不能只修改业务外键而漏记引用。

当前元数据和历史显示分离：目录与当前下载过滤停用及软删；批量历史显示保留全部元数据，不能据此判断可绑定。生产历史内容按冻结的文件 ID 与对象键核对读取，不回读当前工序配置，也不把已物理清理的记录恢复为有效对象。

## 回收与清理

| 状态 | 含义与允许动作 |
| --- | --- |
| 正常 `active` | 对象保留；零引用时才允许按版本移入回收站 |
| 回收站 `trashed` | 已软删除且对象尚保留；禁止新增绑定，可由管理下载或请求物理清理 |
| 清理中 `processing` | 清理尝试已独立提交；禁止绑定和下载。最近尝试满 5 分钟后允许显式重试 |
| 失败 `failed` | 对象操作失败、安全错误码已登记，可显式重试 |
| 完成 `completed` | 对象已确认不存在，元数据及审计持续保留；禁止恢复、绑定或下载 |

移入回收站和发起清理都锁附件、比较 `version` 并复核当前零引用。清理必须先软删除，不能通过单一步骤清理仍正常的附件。引用存在时即使客户端列表曾显示零引用，也拒绝操作。

清理分两次本地事务：先把 `processing`、开始时间和新版本与开始审计一起提交；事务外删除 S3 对象并核验对象不存在；再以该次版本完成状态与审计。对象操作失败会登记 `failed` 及稳定错误码，HTTP 返回持久化后的清理状态，管理界面须按结果区分失败。

进程退出、对象操作后数据库暂时失败或响应丢失都可能留下 `processing`。重试在租期到期后读取最新版本，重新登记尝试并对同一对象做幂等删除；对象本就不存在可完成。旧尝试的迟到结果只有在版本仍匹配时才可写入，不覆盖新尝试。恢复依赖持久化状态与显式重试，不依赖进程内 `afterCommit` 钩子或内存队列；当前不提供后台自动清理调度。

上传先写对象再登记元数据和审计。登记抛错不代表事务未提交，提交确认丢失时不得直接删除对象：只有无外围业务事务，并且独立事务按完整随机 locator 的唯一键进行当前锁定读、确认未登记且该检查事务成功结束，才允许补偿删除。此读取会等待原插入事务结束；存在元数据、外围事务仍活动、读取或提交结果无法确认时均保留对象并抛出原错误。不能根据异常消息猜测提交结果。

补偿失败或数据库不可确认留下的未登记孤立对象由运维对账处理；补偿判断与对象操作之间不再重试原元数据登记或复用该随机对象键。元数据已登记而后续业务绑定失败的文件保留为无引用附件，可通过管理界面回收，不伪造绑定或静默删除。

## 存储配置与运维边界

配置继续使用 `S3_ENDPOINT/S3_REGION/S3_BUCKET/S3_ACCESS_KEY_ID/S3_SECRET_ACCESS_KEY/S3_SESSION_TOKEN/S3_FORCE_PATH_STYLE`；endpoint 可省略以连接 AWS S3，自建兼容服务使用对应 endpoint。`pnpm storage:ensure-bucket` 是显式初始化入口，普通 API 启动和业务请求不创建存储桶。

对象键使用 `<用途>/<北京时间年>/<月>/<UUID><扩展名>`，不含用户路径。全部技术文件共用共享白名单和 20 MiB 上限，应用公开上传也验证空文件、名称、扩展名与 MIME；业务 HTTP 入口继续限制单文件和 multipart 大小。部署 API 请求体上限留足 multipart 开销，业务文件上限不随之增加。

当前物理清理只支持从未启用版本控制的存储桶。删除前后读取 Bucket versioning；`Enabled` 和 `Suspended` 都拒绝标记完成，因为普通删除可能只写入删除标记、旧版本仍存在。凭据必须允许查询桶版本设置、删除对象及检查对象是否存在；无法确认时记录安全失败码，不能猜测物理删除已完成。版本设置和保留策略变更须停止相关上传／清理并按部署恢复方案处理，不能在清理期间切换配置。

桶与数据库备份必须保持稳定 locator 一致。日志和失败码不记录 SDK 原始消息、凭证、签名 URL 或文件内容；版本桶、对象保留策略或权限不足造成的失败由环境维护者处理，不通过改写附件状态绕过。
