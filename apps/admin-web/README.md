# apps/admin-web

Vue 3 管理端主线。视觉与交互遵守[视觉设计](docs/visual-design.md)：左侧菜单 + 顶部栏 + 内容区；列表优先；新增、编辑、分配、确认使用 Modal，不使用 Drawer。前端分层、候选数据所有权、竞态守卫和刷新时机遵守[管理端架构](docs/architecture.md)。

```text
src/
  app/
  api/
  components/
    data-table/
    query-form/
    modal-form/
    status-tag/
  composables/
  layouts/
  router/
  stores/
  styles/
  views/<module>/<feature>/
    components/
    composables/
    schemas/
    index.vue
```

页面负责组合，Modal 表单、查询模型、状态字典和 API schema 分离。当前共享组件仍由 admin-web 的
`src/components` 所有；只有出现第二个独立前端消费者且组件 API 已稳定时，才评审提取 workspace UI 包。

## 验证

`corepack pnpm --filter @company/admin-web typecheck` 检查应用源码、共享契约和测试文件；`build` 在打包前执行同样的完整类型检查。相邻测试由独立 `test` 入口执行。单独检查应用源码不能替代完整验证。

## 审批试探手工验收路径

本次前端试探只接入产品 BOM 审批，站内通知和工单审批不在范围内。后端完成迁移并准备至少一个启用角色后，可按以下路径验收：

1. 以具有 `approval:configure` 的账号进入“审批中心 → 审批流程配置”，打开“BOM 审批”，添加两个节点并分别选择角色；保存草稿后修改一个角色，直接点击“发布流程”，确认发布的是刚修改的节点。
2. 以具有产品 BOM 管理权限的账号进入“成品与物料”，为一个未送审成品配置并保存 BOM；重新打开 BOM，确认未保存修改时不能提交审批，保存后“提交 BOM 审批”可用。
3. 提交后确认 BOM 显示“审批中”且编辑控件被锁定；在“审批待办”打开该申请，核对成品编码、规格、BOM 明细、节点角色和处理记录。
4. 使用节点角色下的合格账号明确点击“通过当前节点”，确认申请进入下一级；同一账号可继续处理下一级，但每一级都有独立记录。点击“驳回申请”必须填写原因。
5. 申请人从“我发起的”打开申请并撤回，确认申请结束、BOM 恢复可编辑；再次提交应生成新的申请并从第一级开始。全部节点通过后确认 BOM 显示“已批准”并永久锁定。
   驳回或撤回后返回已缓存的“成品与物料”标签，确认列表和此前打开的 BOM 弹窗都恢复草稿状态，无需浏览器刷新。审批通过后返回同一标签，确认弹窗同步为永久锁定。若本地仍有未保存修改且产品版本发生变化，应保留草稿并阻止保存，只有确认“重新加载 BOM”后才丢弃修改。
6. 角色没有合格成员时，发布或提交应被后端拒绝并提示；运行中成员失去资格时，详情显示“暂无合格审批人”，有 `approval:reassign` 权限的账号填写原因重新分派后再继续。
7. 审批中心默认显示全部状态：普通用户范围为“与我相关”，审批管理员为“全部申请”。通过、驳回或撤回后，申请人和曾分派任务的审批人均能查看该申请的完整处理记录；“待我处理”只显示当前待办，不提供已结束状态筛选。从产品进入审批中心时也使用全部状态，不限定为本人发起。

前端页面通过 `src/api/approval.ts` 使用审批公开契约，详情页以服务端返回的 `canApprove`、`canWithdraw` 和 `canReassign` 决定操作入口；页面按钮可见性不替代后端鉴权。

BOM 编辑及审批证据明细仅显示物料、单位、单位用量和备注，不提供关键物料或记录批次开关。
