# 通用出库 UI 预览与接入评估

本轮授权范围为 `/warehouse/outbound-orders` 的成品／物料通用出库界面和 mock 交互。界面待用户验收，后端未实施；本文的接入建议不是已批准的数据库或公开 API 设计。待办集中在[路线图](../../../docs/roadmap.md#通用出库ui-预览待验收)。

## 界面与数据边界

- 页面分为“通用出库”和“生产领料”。通用出库共用列表和表单，按成品／物料选择库存；同一张演示单限同一类型。生产领料沿用原有真实接口、需求分配和确认流程，mock 不进入生产链路。
- 库存样例使用现有 `InventoryBatchItem` 契约：公共字段为编码、名称、批号、单位和数量；成品使用 `productId`，物料使用 `itemId + materialVariantId` 并展示精确版本。响应数量及 ID 沿用字符串，非适用身份为 `null`。
- 去向是人员必填的自由文本，与备注分开。通用单据仅为前端本地预览模型；去向等新增字段不代表现有后端已支持，不伪造生产任务、需求或分配来满足生产出库契约。
- 通用候选、创建、详情、确认和取消均由页面内存 mock 完成，不调用业务 HTTP 或持久化到 Web Storage。页面持续标明示例数据；硬刷新或关闭页面标签后重置，普通缓存页面切换保留状态。
- 数量遵守[整数数量规则](../../../docs/database-conventions.md#统一类型与状态规则)，正数最小为 1，最大为 99999999；小数、重复批次、空白去向和超量输入不能提交，不跨单位求总数。
- 预览只允许可用批次。成品按 `onHandAvailableQuantity` 展示可出量，不能使用恒为零的物料可分配字段；物料按 `availableToAllocateQuantity` 展示，保留生产预留影响，不再重复扣减待确认生产领料。
- 保存演示单后待出库，确认前重新核对所有明细的 mock 库存，全部合格后一次更新本地状态和库存。取消限待出库单且填写原因；完成单只读，不提供冲销或无痕撤销。演示中的待出库不新建生产预留，也不履约生产需求。

草稿关闭保护、路由缓存和确认弹窗遵守[路由与标签页规范](route-dialogs-and-tabs.md)，颜色与布局遵守[视觉规范](visual-design.md)。本轮不引入销售、客户目录、审批、采购退货或库存报废。

## 当前数据库能否直接支持

结论：库存批次、唯一账本和余额投影可以复用，但现有数据库不能直接完整支持通用出库。正式接入需要追加成对 migration，本轮不创建或执行 migration。

| 现有结构／能力          | 评估与依据                                                                                                                                                                                                                                                                                                                                                                 |
| ----------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 统一库存批次与查询字段  | 已区分成品／物料身份，可供统一 UI 模拟。[契约](../../../packages/contracts/src/production/inventory.ts)和[查询](../../api/src/modules/inventory/infrastructure/queries/mysql-inventory-batch.query.ts)中，成品的 `availableToAllocateQuantity` 为零，物料该字段还受版本资格、批次状态及预留影响。                                                                          |
| `outbound_order/detail` | 属于 Production；主单绑定工单／任务，明细绑定需求／分配及物料版本，没有成品身份和通用去向。不能通过虚构生产来源承载通用出库，见[生产出库表](../../api/src/modules/production/docs/database/demand-allocation-and-outbound.md#12-outbound_order)及[建表 migration](../../../packages/database/migrations/202608110002-production-material-allocation-and-outbound.up.sql)。 |
| 成品库存流水            | 当前 CHECK、来源外键及 INSERT 触发器仅接受正数成品入库和真实入库明细，禁止成品负出库流水。见[成品约束 migration](../../../packages/database/migrations/202609170002-finished-goods-inbound.up.sql)和[当前来源约束 migration](../../../packages/database/migrations/202609240001-unified-inbound-allocation-target.up.sql)。只新增前端或 API 无法绕过这些约束。             |
| 通用去向与单据事实      | 缺少独立于生产需求的通用出库事实。建议后续由 Inventory 拥有通用主从单，保存去向、操作者、状态、版本和审计，明细引用真实库存身份／批次；具体表名和字段尚待后端设计。此建议不建立第二库存账本或生产领料影子表。                                                                                                                                                              |
| 流水类型与引用          | 当前没有通用出库类型。已有 `sales_outbound` 是销售语义，不应借用为任意去向；正式接入须明确新类型、来源引用及对应 CHECK／外键／触发器，同时维护 constants、contracts 和所有权登记。                                                                                                                                                                                         |

库存字段和现行约束的权威定义仍在 [Inventory 数据库文档](../../api/src/modules/inventory/docs/database.md)；本文只记录本次预览所需的差异评估。

## 后端接入必须先明确的边界

生产领料单、需求、分配和任务状态继续归 Production；通用出库不消费生产需求或改变分配。库存事实仍仅写 `inventory_transaction`，不得直接覆盖余额投影。

物料出库必须在同一事务中保护已有生产预留，不能只读取页面数量或扣账面库存。现有[库存协作协议](../../../docs/inventory-extraction-design.md)只批准展示查询读取预留，禁止将跨模块展示 SQL 当命令校验，也禁止持库存锁后反向获取生产来源锁。正式接入前须明确预留保护的公开能力、调用方向、同池事务和稳定锁序；界面中的 mock 限量不构成并发保障。

库存资格（包括停用版本能否通用出库）、待出库单是否额外占用额度、后端权限／幂等／确认原子性和完整来源约束须随接入设计确认。当前预览采用待出库不扣库存、确认时复核的演示行为，不擅自扩大现行公开边界。
