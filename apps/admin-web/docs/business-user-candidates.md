# 业务人员配置与工单负责人

业务场景、角色配置及当前人员资格由 [Identity](../../api/src/modules/identity/README.md) 所有，工单写入与下达资格由 [Production 工单设计](../../api/src/modules/production/docs/database/work-orders-and-batches.md) 所有。本专题维护管理端的配置草稿与人员选择边界；通用选择、读取取消、页面权限和标签关闭保护沿用[管理端架构](architecture.md)。

## 配置草稿

业务人员配置页消费独立页面查看权限，系统提供的场景只读，管理员为每个场景选择多个启用角色。角色来自专用角色候选，不下载角色管理列表。候选人数和已保存角色描述服务端已保存配置，未保存角色修改不重算人数；没有配置或清空角色时明确提示没有候选人员。

每个场景分别持有开始编辑时的配置版本、角色草稿与最新读取结果。保存使用原版本进行比较更新；刷新配置保留脏草稿，远端配置发生变化时阻止旧依据保存，只有人员明确确认重新载入才放弃草稿。保存期间锁定本场景输入；保存结果未确认时保留原修改，先刷新核对结果再继续。读取失败不得生成可保存的空配置。

配置和角色候选初次进入时分别读取，后续通过显式入口独立刷新；缓存返回保留输入，离开页面使在途读取失效。角色完整候选成功返回后，缺失的已选角色仍保留 ID 和已有名称，标为失效，允许移除并阻止保存；未完成核验或读取失败时不把缺项判为失效。页面标签关闭前保护未保存修改及待核对结果。

## 工单负责人选择

新增、编辑和开启下一轮研发表单只消费工单负责人专用完整候选，在打开表单及显式刷新时读取，不回退通用人员候选，也不自动指定负责人。候选为空时提示联系管理员配置业务人员角色；负责人为空仍允许保存草稿，非空负责人须核验成功且位于当前候选。

候选刷新保留当前表单输入和已选负责人。编辑或下一轮研发带入的负责人退出候选后，继续显示原 ID 与工单提供的姓名并提示重新选择或清空；首次候选读取失败时只标待核验。工单列表及详情直接使用工单返回的负责人姓名，历史显示不依赖当前候选范围；任务负责人和工序派工继续使用各自已有契约。
