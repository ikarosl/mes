# 成品质检、产出与入库的前端约束

检查事实与放行由 [Quality](../../api/src/modules/quality/docs/finished-inspections.md)维护；产出、收尾及批准由 [Production](../../api/src/modules/production/docs/database/production-termination.md)维护；执行依据见[成品入库](../../api/src/modules/production/docs/database/finished-goods-inbound.md)。步骤见[操作手册](../../../docs/manuals/finished-output-inspection-inbound.md)，通用草稿与未知结果保护见[管理端架构](architecture.md)。

## 输入与证据

普通检验的数量和结论初始留空。切换方式清空数量和结论；普通检验数量变化后也清空结论，要求重新核对，避免沿用另一组事实的放行决定。“待全检或复检”是真实结论，不能作未选择占位；零产出使用专用核实入口并主动确认。

“送检数量”显示本轮建立时的剩余申报快照，“检查总数／样本总数”显示本次 G/F 事实；两者分开核对，不以实时入库量补造送检快照。历史中的产线申报明确标为登记检验时的参考；详细数量含义与差异提示见上述所有者文档。

检验引用必须人工选用；保留原绑定明细供核对，不默认替换为最新记录。未绑定、失效和历史只读分别说明；没有可选依据时解释原因，不隐藏原绑定证据。

## 查询与跨页引用

任务列表按当前页工单组织，分组不能被理解为完整工单。历史精确定位使用任务与检验记录 ID，独立于历史分页；定位失败可退出定位或重试，不替换为最近记录。

产出未保存时，用户可选择保留填写后前往同任务质检，或保存成功后前往；保存失败或结果未知时不能跳转。返回仍保留本地填写，检验不会替产线自动保存或选用依据。

产出依据变化后，允许逐项对照本地与服务端的数量、检验引用及说明，再明确保留输入并接受已核对版本，或放弃后重载。这是有比较与确认的重新核对，不能只更新版本后重发。

复检由 Quality 工作台持有写意图；生产入口只负责定位。关闭结果表单只放弃本地填写，不撤销已开始的检验。开始与复检的真实影响须在提交确认中说明。

## 产出、结案与物料实核

办理引导直接使用已保存草稿、检验引用及服务端阻断原因，不另存一套前端完成进度。打开或返回某一步不表示已完成，全部步骤就绪也不自动送审；负责人等非物料阻断不能被统一解释为“物料未核对”。

收尾事项与产出编辑器分别持有输入。登记结案损坏采用独立确认，明确其不可撤销影响，不能让用户误以为它随产出草稿或审批一起撤回；实际影响见[收尾规则](../../api/src/modules/production/docs/database/production-termination.md)。

## 成品入库与跨页定位

入库选择、目标拆分及草稿归属遵守[入库交互](procurement-inbound.md#7-有效放行与实际入库)，定位遵守[采购与入库定位](procurement-inbound.md#21-详情定位)。成品入库历史的检验入口定位本次入库保存的记录，待入库的检验入口按任务定位。
