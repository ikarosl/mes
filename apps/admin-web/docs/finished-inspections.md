# 成品质检、产出与入库的前端约束

数量、放行及复检职责由[Quality 成品检验](../../api/src/modules/quality/docs/finished-inspections.md)维护；产出与入库规则见[Production 收尾](../../api/src/modules/production/docs/database/production-termination.md)和[成品入库](../../api/src/modules/production/docs/database/finished-goods-inbound.md)。本文维护输入及证据引用的额外约束，操作步骤见[手册](../../../docs/manuals/finished-output-inspection-inbound.md)。

成品质检只展示 G/F 检查事实及明确结论；Production 仅对所引用的 `full+released` 检验在定稿时显示非阻断数量提示。固定已入基准、剩余范围和复检开始冻结以 Production 与 Quality 当前所有者规则为准；用户黑盒和 UI 验收状态见路线图。

## 输入与证据

- 普通全检／抽检数量初始留空，不按产线申报自动填写或封顶；申报只是待核对快照。空输入不等于零，零产出须专用确认、说明和凭据。
- 普通检验结论初始留空，必须人工选择；切换检验方式清空原数量，普通检验方式或数量变化后清空结论，须核对后重新选择，避免沿用另一组事实的放行决定。“待全检或复检”是真实结论，不能作为未选择的占位值。零量使用专用核实方式，并须主动确认确无可送检成品。
- 质检表单、提交确认和历史只展示检查 G/F、自动 N、方法、明确结论、时间及凭据；原产线申报只作为来源参考，不在质检流程计算或展示产出数量差异。抽检不输入整批量、不推算整批结果，也不展示抽检合格率；不合格不自动成为生产报废。
- Production 只读消费检验历史并显式引用有效依据，不能通过修改产出草稿代替质检；Quality 检验表单及命令独立所有。
- 既存检验记录由 Quality 的 `FinishedInspectionRecordDetail` 统一展示身份、人员、检验与登记时间、原申报数量、说明和凭据，并组合 `FinishedInspectionFacts` 展示检查事实；审批证据、批准清单／打印、检验历史及产出核对共用。组件只消费传入记录，保留引用时的历史数量与基准，不自行请求或替换为最新检验；折叠、定位、选用资格和编辑状态仍由宿主负责。
- `declaredVersion` 与送审工单版本只供后台并发及追溯，业务详情不展示技术版本数字。产线来源明确标为“登记检验时的产线申报数量”，保留计划内、计划外及新增报废的类别和单位。前次批准清单按服务端解析的真实 `revision_no` 显示“第 N 版”，不将记录 ID 当版次；无前版才显示“首次结案”，存在引用但版次缺失须明确显示无法读取。

## 刷新、并发与未知结果

通用保护遵守[管理端架构](architecture.md#2-草稿与关键详情)。质检表单保存开始填写时的任务、申报快照及版本；申报变化保留输入并阻止旧依据保存，不只替换版本号。

登记成功响应须匹配任务、记录 ID 及原版本加一；格式异常按未知结果保留原命令／键，避免服务端已落库又新建记录。历史读取失败保留上次数据并标错误；返回缓存页刷新上下文但保留输入。关闭、换任务、关闭标签均保护草稿和未知结果，提交中禁止关闭。

## 查询与跨页引用

本节描述当前办理交互；交付验证与用户验收状态见[路线图](../../../docs/roadmap.md#成品质检与产出核对整改)。

列表按工单组织当前页任务，分页总数仍按接口返回的任务计算；同一工单可能跨页，不据当前页推导整单完成率。检验参考展示真实检验记录 ID，并可定位对应明细；不以轮次 ID 或检验事项 ID 代替。当前轮状态与最近记录结论并列区分，详情根据记录所属轮次与接口当前轮比较，标明本轮或历史；缺少当前轮信息时不推断历史归属。未新增同轮检查记录不等于没有可继承依据，正式采用仍以产出清单引用为准。开始或登记入口分别消费服务端的 `canStartInspection`、`canRecordInspection`，不以最近结论推断当前可办理性。摘要只使用已返回字段，不逐任务补读详情。

当前轮固定计划内／计划外历史已入基准在页面标为“本轮建立时已入库”，不显示 `I₀` 数学符号。成品质检不显示本次放行量或累计建议量。仅 Production 产出定稿引用 `full+released` 时，比较累计目标与**原引用检验轮**两项固定已入基准加 G，显示差额核对提示；抽检和零量核实不作整批数量差异。提示不禁用保存／送审，不增加强制说明或额外审批；质量未放行、计划内上限、历史已入下限、本轮暂停状态和清单执行资格仍由后端独立校验。

定稿核对统一标为“入库数量提示”。本轮拟新增可入库以“累计目标 − 本轮建立时已入 = 结果”展示实际数字，已入取本轮固定的计划内／外基准合计，不混用后续实时入库进度；未建立本轮或输入无效时不展示确定的算式。引用的有效放行抽检存在不合格时，用警告提示实际不合格数及核对拟入库数量是否已剔除；样本无不合格时仍提醒按实际产出核对，不宣称整批合格。不将任务计划、草稿可入目标或抽检样本数当作独立核实的整批产出，也不自动扣减目标或推算可入上限。

待办按当前办理状态查询，当前轮待检、检验中和当前记录待复检／不放行的任务不被历史放行结论排除；未保存产出草稿、正在审批及可沿用适用放行依据的纯清单更正不混入待检。列表用于寻找当前工作，具体动作仍以详情读取的来源资格及写入时校验为准。“已有检验记录”只表示存在历史，可以与当前待办重叠；最近历史结论继续展示，不冒充本轮办理状态或当前清单采用依据。

首次检验明确开始后接续填写，检验中可继续填写。需要新一轮时由成品质检详情提供“开始复检”，确认中展示任务、复检原因、当前已入基准及全部剩余送检范围的影响；一次确认由 Quality 编排 Production 来源能力建立并开始新轮，立即暂停旧剩余授权，成功后直接接续填写。不另设申请、受理或第二次开始。Production 产出清单只提供定位同一任务质检的入口，不再持有复检写命令。正在检查时不可重复开始；本轮完成后能否再次复检消费服务端资格，不因处于清单更正中一概禁止。清单纯更正与新检验分别办理，不能用数量调整替代检查。

填写与核对摘要在同一工作台中呈现：身份、申报参考、当前轮“本轮建立时已入库”基准、G/F/N 检查事实及明确结论可同时核对，历史不挤占当前办理区域；质检表单、确认和历史不呈现产出数量差异。遵守系统有边框描述表、主题配色、单一正文滚动与固定 footer 规范；正常保存与放弃填写留在固定操作区。未开始、无已保存草稿、审批冻结或其他不可办理情况显示具体原因，不以统一禁用按钮代替解释。关闭或放弃填写只放弃本地输入，不撤销已开始的检验，也不恢复旧授权。

跨页以 batchId 定位同一任务；已入库历史另带 inspectionId 定位确切检验记录，按任务和记录 ID 读取单条历史事实，不受历史分页影响。记录不存在或读取失败时明确显示错误，不回退到最近记录；可退出精确定位，返回全部分页历史。产出未保存时可明确选择保留填写并前往，或保存成功后前往；产出与质检页普通跳转保留各自缓存草稿。提交中或结果未知时阻止切换意图，明确关闭或换对象才执行相应放弃确认。返回后刷新资格和版本，旧输入继续保留但不能提交过期依据。产出版本变化时可逐项对照本地与最新服务端的数量、检验引用和说明，明确确认后保留本地填写并接受已核对版本，或放弃后重新加载；不能静默更新版本号。保留填写不自动保存、送审或替换检验引用，当前适用依据仍须明确采用。批准版和入库证据保留当时快照，不用当前最新检验替换历史。Quality 查询／历史不额外要求 Production 页面权限。

## 产出、结案与物料实核

- 收尾事项与产出编辑器分别持有输入；正常结束也须核对物料，不能以成品差额乘 BOM 推算余料。数量分类及上限引用 Production 规则，历史工序报废、当前新增报废和物料损耗分开显示，未批准草稿不计入审定产出。
- 登记结案损坏使用独立弹窗，确认前说明其永久占用可退额度、无自动补料或库存扣减、审批驳回也不撤销。保留打开时版本、实核令牌和上限，变化后禁止沿用旧确认；成功刷新物料依据并要求重新实核。
- 审批证据及打印保留逐笔损耗来源、数量、原因、用途和人员／时间；不把物料损耗计作成品报废。批准版不可变，历史版明确标注不能用于入库；更正保留旧证据，不直接改批准版。
- 数量输入保留越界原值并显示字段错误；计划内上限、各类历史已入下限和字段整数范围由校验阻止草稿保存，不用输入组件自动截断掩盖错误。
- 送审使用当前版本和核对指纹，未保存草稿不能送审。更正时分别展示本轮固定的计划内／外已入基准、当前累计目标和拟新增授权；按类别以历史已入量为下限，已入类别仍可增加累计目标。计划内已达任务计划时，新增产出填入计划外。新增成品报废独立填写，不受计划外已入量限制。未执行余额由新版授权，暂停或冻结由服务端状态决定。发起复检后即使取消更正也不恢复旧授权；未完成检验期间不能送审。`finalOutput=null` 和批准零产出分开显示，报工量不标成质检合格量。
- 产出编辑与所引用检验依据并排核对，普通说明和历史不把关键数量挤出视野。引用下拉位于核对区顶部，展示全部历史但仅当前适用的最新放行记录可选；最新历史记录若因开始新轮而过时，也须禁选。检验办理中在依据选择位置说明送审／入库阻断，暂停展示无可选项的下拉，不在该核对区重复设置质检跳转；原绑定明细仍可核对。原历史绑定保留展示而不自动替换，下方明细仅展示实际绑定记录，未绑定时不以最新记录代替。有效依据须明确引用，尚未引用、引用已失效和历史只读分别展示；不通过默认选择冒充人员核对。说明和凭据直接展示，清单累计目标、拟新增授权与 G/F 检查事实分开标注；仅引用 `full+released` 时显示上述定稿差异，原送审门禁不变。检验历史、批准清单与更正记录独立查看，保存和送审保持不同动作。
- 最新批准版本只说明批准历史顺序，不等于当前可以入库；是否可执行由当前轮、清单及剩余授权状态共同决定。更正或复检期间明确显示旧授权暂停，取消更正后仍显示实际执行资格，不提示“继续使用原批准清单”或用“当前有效”代替“最新批准”。

## 成品入库与跨页定位

入库页的外购／成品 editor 独立；切换页签保留输入并隐藏非活动弹窗，只刷新所属数据。成品候选分页，窗口缺项不当作失效。仓管从当前有效授权选择本次数量和新建或已有的合资格库存批次，直接确认；每条执行明细保留授权、版本、数量和目标批次。一次确认可选同一任务的计划内与计划外授权，也允许把同一授权拆入多个目标；多次确认按各授权分次消费，历史按明细显示来源。批次选择遵循两类入库共用的[一期交互约束](procurement-inbound.md#7-有效放行与实际入库)，不提供复用本次新批次。

候选在待入库页选择，按工单组织当前页明细并默认展开；分组不改变候选分页计数或同一任务限制，不能把当前页摘要当成整张工单的完整产出。收起后仍显示暂不可入的数量及已有阻断原因。同页刷新保留手动折叠与跨页选择，确认弹窗消费同一份已选草稿，不另建候选实例。取消某授权的选择移除其全部目标明细，弹窗内移除单条目标只影响该行。拆分量由人员明确填写并从原行扣减，保持拆分前后总量；输入原文、逐授权合计和剩余额度的展示约束与外购共用，见[采购入库专题](procurement-inbound.md#7-有效放行与实际入库)。历史存在多个产出类别时展示实际来源集合，不能用第一条明细代表整单。

成品已入库记录按入库单分页分块，每页仅首单默认展开，其余按需展开；同页刷新保留手动折叠，成品、工单、任务、确认人和确认时间在收起时仍可识别。展开单据时读取现有详情接口，逐行直显实际来源类别、目标库存批次、本次数量、当时批准依据，以及采用的检验记录 ID 与结论。有成品质检查看权限时，该 ID 定位到质检页的确切历史记录；无权限时保留静态 ID，不以当前最新检验代替。批准依据不从列表概览或任务最新状态推断；同一单据的重复展开复用已读详情，缓存限于当前页与外部定位单，主动刷新重新读取已展开单据与定位单。详情响应须按请求入库单校验身份，不把其他单据结果缓存为当前单。加载与失败重试反馈留在对应块内，刷新失败明确标注上次读取结果。批次可按目标页面权限跳转库存，无权限保留文字。

本地未提交选择若因刷新发现授权或余量变化，保留原数量和目标，要求明确重新核对；结果未知保留原 body 与幂等键，禁止静默换授权或目标。零剩余额度退出候选；复检暂停由服务端状态判断。

`warehouse:inbound:view` 足以读取入库单采用的清单与质检依据，不附加任务管理权限；原审批链接独立鉴权。待入库以工单、任务、成品及来源类别识别，质检入口按任务定位；已入库检验入口使用本次入库保存的批准版检验快照中的任务与记录 ID，跨页定位确切历史记录。入库历史行展示批准人、批准时间及检验结论；检验时间作为记录入口提示，说明与凭据在精确历史记录中查看。缺少详情明确提示未提供，不回退显示任务最新检验。行内实际入库量取本次执行明细，不把批准版查询时的累计执行量解释为当时数量。标识层级遵守[视觉设计](visual-design.md#3-字体与排版)。成品来源链接用 `/warehouse/inbound-orders?inboundId=...`，库存批次用 `/warehouse/inventory?itemBatchId=...`。定位单在当前页时展开并高亮；不在当前页或筛选范围时独立读取展示，不改写分页结果或总数，并允许取消定位与失败重试。定位另一张单前确认放弃脏草稿，取消恢复原定位；提交中／未知结果禁止换单。离开仅取消导航读取，不销毁缓存草稿。
