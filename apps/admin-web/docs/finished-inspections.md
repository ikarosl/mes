# 成品质检、产出与入库的前端约束

数量、放行及复检职责由[Quality 成品检验](../../api/src/modules/quality/docs/finished-inspections.md)维护；产出与入库规则见[Production 收尾](../../api/src/modules/production/docs/database/production-termination.md)和[成品入库](../../api/src/modules/production/docs/database/finished-goods-inbound.md)。本文维护输入及证据引用的额外约束，操作步骤见[手册](../../../docs/manuals/finished-output-inspection-inbound.md)。

质检数量建议只提示、不限制定稿。固定已入基准、剩余范围和复检开始冻结以 Production 与 Quality 当前所有者规则为准；用户黑盒和 UI 验收状态见路线图。

## 输入与证据

- 普通全检／抽检数量初始留空，不按产线申报自动填写或封顶；申报只是待核对快照。空输入不等于零，零产出须专用确认、说明和凭据。
- 切换检验方式清空原数量；普通检验方式或数量变化后重置结论，须核对后重新选择，避免沿用另一组事实的放行决定。零量按专用规则处理。
- 表单、确认和历史显示实测与当时申报的差异；申报报废不混入送检量，不合格不自动成为生产报废，差异不回写产线草稿。
- Production 只读消费检验历史并显式引用有效依据，不能通过修改产出草稿代替质检；Quality 检验表单及命令独立所有。

## 刷新、并发与未知结果

通用保护遵守[管理端架构](architecture.md#2-草稿与关键详情)。质检表单保存开始填写时的任务、申报快照及版本；申报变化保留输入并阻止旧依据保存，不只替换版本号。

登记成功响应须匹配任务、记录 ID 及原版本加一；格式异常按未知结果保留原命令／键，避免服务端已落库又新建记录。历史读取失败保留上次数据并标错误；返回缓存页刷新上下文但保留输入。关闭、换任务、关闭标签均保护草稿和未知结果，提交中禁止关闭。

## 查询与跨页引用

本次建议按 Quality 所有者公式显示。已有入库时分列轮次固定 I₀、本轮 R、累计建议与清单累计目标，不以动态库存余额替代固定基准。不因超出或低于建议禁用保存／送审，不增加强制超建议说明或额外审批；质量未放行、计划内上限、历史已入下限和本轮暂停状态和清单执行资格仍由后端独立校验。

“已有检验记录”只表示存在历史，最新待复检也可命中；不能让查询范围强制排他。默认待检下看不到已放行任务时，切到已有记录／清空筛选或从产出清单直达。新检验必须明确开始本轮：Production 保存初次草稿或发起复检时建立固定基准轮并冻结旧剩余授权；Quality 的“开始本轮检验”把该轮推进检查中，再允许填写并完成不可变记录。清单更正与新检验资格以服务端状态为准。

跨页以 batchId 定位同一任务，跳转前处理脏草稿；批准版和入库证据保留当时快照，不用当前最新检验替换历史。Quality 查询／历史不额外要求 Production 页面权限。

## 产出、结案与物料实核

- 收尾事项与产出编辑器分别持有输入；正常结束也须核对物料，不能以成品差额乘 BOM 推算余料。数量分类及上限引用 Production 规则，历史工序报废、当前新增报废和物料损耗分开显示，未批准草稿不计入审定产出。
- 登记结案损坏使用独立弹窗，确认前说明其永久占用可退额度、无自动补料或库存扣减、审批驳回也不撤销。保留打开时版本、实核令牌和上限，变化后禁止沿用旧确认；成功刷新物料依据并要求重新实核。
- 审批证据及打印保留逐笔损耗来源、数量、原因、用途和人员／时间；不把物料损耗计作成品报废。批准版不可变，历史版明确标注不能用于入库；更正保留旧证据，不直接改批准版。
- 数量输入保留越界原值并显示字段错误；计划内上限、各类历史已入下限和字段整数范围由校验阻止草稿保存，不用输入组件自动截断掩盖错误。
- 送审使用当前版本和核对指纹，未保存草稿不能送审。更正时分别展示本轮固定的计划内／外已入基准、当前累计目标和拟新增授权；按类别以历史已入量为下限，已入类别仍可增加累计目标。计划内已达任务计划时，新增产出填入计划外。新增成品报废独立填写，不受计划外已入量限制。未执行余额由新版授权，暂停或冻结由服务端状态决定。发起复检后即使取消更正也不恢复旧授权；未完成检验期间不能送审。`finalOutput=null` 和批准零产出分开显示，报工量不标成质检合格量。

## 成品入库与跨页定位

入库页的外购／成品 editor 独立；切换页签保留输入并隐藏非活动弹窗，只刷新所属数据。成品候选分页，窗口缺项不当作失效。仓管从当前有效授权选择本次数量和新建或已有的合资格库存批次，直接确认；每条执行明细保留授权、版本、数量和目标批次。一次确认可选同一任务的计划内与计划外授权，也允许把同一授权拆入多个目标；多次确认按各授权分次消费，历史按明细显示来源；同次不同授权共建新批次须显式复用请求内 clientKey。

本地未提交选择若因刷新发现授权或余量变化，保留原数量和目标，要求明确重新核对；结果未知保留原 body 与幂等键，禁止静默换授权或目标。零剩余额度退出候选；复检暂停由服务端状态判断。

`inbounds:view` 足以在入库详情读取其采用的清单与质检依据，不附加任务管理权限；原审批链接独立鉴权。成品来源链接用 `/warehouse/inbound-orders?inboundId=...`，库存批次用 `/warehouse/inventory?itemBatchId=...`。定位另一张单前确认放弃脏草稿，取消恢复原定位；提交中／未知结果禁止换单。离开仅取消导航读取，不销毁缓存草稿。
