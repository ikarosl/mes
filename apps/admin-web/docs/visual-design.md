# 管理端视觉设计

管理端采用克制的表格与弹窗交互，优先让身份、数量、状态和办理风险易于核对。候选、草稿和并发行为见[管理端架构](architecture.md)，组件接入见[路由与标签页](route-dialogs-and-tabs.md)。业务字典以共享常量为准，不在本规范固定页面和菜单清单。

## 2. 色彩规范

使用当前 Element Plus 主题变量，不为业务页面另造配色。颜色表达状态和风险，完整文字、单位及数量同时保留，不能仅靠颜色区分。

| 语义 | 主题变量 |
| --- | --- |
| 操作、链接、选中、办理中 | `--el-color-primary` |
| 成功、完成、已生效 | `--el-color-success` |
| 待确认、需核对、时间风险 | `--el-color-warning` |
| 失败、阻断、拒绝、危险操作 | `--el-color-danger` |
| 未开始、历史、失效 | `--el-color-info` |

身份与关键数量用主要文字色、字重及对齐强调，不用链接蓝表达“重要”。真实导航保留链接样式，普通文字不保留隐形点击。表格和分组采用白色、浅灰底及细边框，语义色限于标签、文字和必要提示，不铺大块饱和背景或闪烁。

已记录的合格、不合格量分别用成功与错误色，零值中性；颜色只说明检查结果，不授予放行或入库资格。普通累计、ID、轮次及输入草稿保持中性，不能把未知值当零。关键正文最多使用三种色系。

### 2.1 状态标签一致性

同一状态跨列表、详情和编辑器采用相同语义与样式，映射集中在展示辅助函数，文字使用共享字典。相近状态可用同色系的描边／浅底配合完整文案区分，不要求每个状态拥有独立颜色；某一阶段完成不代表全流程结束。

### 2.2 异常与时间风险的可视层级

风险必须来自真实事实或可靠的日期、数量和状态。错误高于警告，始终保留逾期时间、待办数及原因；进度显示完成量与总量，不让普通标签遮住阻断。

## 3. 字体与排版

字体依次使用 Inter、PingFang SC、Microsoft YaHei、Noto Sans SC、Arial、sans-serif。

| 场景     | 字号 | 字重 |
| -------- | ---: | ---: |
| 页面标题 | 20px |  600 |
| 区块标题 | 16px |  600 |
| 表格正文 | 14px |  400 |
| 表单标签 | 14px |  500 |
| 辅助说明 | 12px |  400 |
| 状态标签 | 12px |  500 |

页面内容边距为 24px；卡片内边距为 16px 或 20px；表单垂直间距为 16px；按钮间距为 8px；工具栏与表格间距为 12px。

详情与记录页的识别信息、状态和数量摘要优先采用紧凑的描述区，同一区域保持相同字号与标签样式。通过减少装饰容器及空白提高密度，不通过浅色小字弱化关键数量；收纳次要信息时仍保留主要数量、办理阻断、风险和未知结果。

主要数量默认可见；简短规则、范围提示及数量说明使用 [InlineHint](../src/components/InlineHint.vue) 直接呈现，通常一行，窄处自然换行，不以截断或省略号隐藏提示。普通提示用主蓝边线与浅底，关键数量及限制用主文字色加粗；真实差异或阻断按语义着色，不能仅靠颜色表达。长记录可收纳，摘要保留主要阻断、风险和继续查看的入口；审批冻结与未知结果不能收进折叠区。尚无结果与已确认零数量使用不同提示。

业务识别优先用单号、物料编码／版本和真实明细序号。ID、版次与轮次必须正确命名，不能互相替代或从排序推算；原始 ID 只在必要的追溯场景显示，并说明含义。来源已经明确时不重复堆叠内部编号；历史引用保留原关系，不拿当前值填补缺失证据。采购与到货的特殊定位标识见[采购专题](procurement-inbound.md#21-详情定位)。

多级业务列表的分组仅通过标题前的独立细线箭头按钮展开／收起；单号、标题和数量为按钮旁可选择复制的普通文本，状态标签独立呈现。分组文字与整行不承担折叠点击，独立选择、来源导航和业务动作不触发折叠。箭头方向、可访问动作名称与 `aria-expanded` 同步，按钮支持键盘操作且焦点清晰；长证据可收纳，简短提示和关键阻断保持可见。

## 4. 管理端布局

左侧菜单展开宽度为 220px、最多两级；顶部标题前提供始终可用的收起／展开按钮，收起后完整隐藏侧栏，内容区填满可用宽度。切换保留菜单展开状态、当前路由和标签页草稿；折叠状态由布局实例持有，路由切换保留，整页刷新恢复展开。按钮提供动作提示、键盘操作和同步的展开状态；侧栏隐藏时其菜单不可获得键盘焦点。路由区弹窗的遮罩边界随内容区尺寸同步更新。

顶部显示当前页面及系统／用户入口，不放业务动作。菜单由路由及权限驱动；内容区不重复顶部标题，优先从筛选、工具栏或主体开始。不放“迁移验证／测试入口”等开发占位说明。

## 5. 弹窗规范

编辑、详情和确认统一用 Modal，不以 Drawer 为主要方式。整体最大高度为挂载区 `.content` 的 90%，不是视口高度；垂直居中，标题／底部可见，仅正文溢出滚动。

| 类型 | 推荐宽度 | 上限 |
| --- | --- | --- |
| 小型确认 | 420px | 90vw |
| 常规表单 | 640px | 75vw |
| 多字段表单 | 860px | 75vw |
| 复杂详情 | 1000px | 75vw |
| workbench | 1400px | 内容区宽度减 32px |

工作台左右至少各留 16px，宽表操作列固定右侧；共用普通弹窗的高度和滚动规则。挂载、缓存、关闭保护和最小代码示例见[路由规范](route-dialogs-and-tabs.md)，不再逐页复制尺寸 CSS。

## 6. 表格规范

直接路由页面的分页列表统一使用 [PaginationFooter](../src/components/PaginationFooter.vue)，包含页面内的页签、子路由面板和侧栏列表；默认页长和分页协议见[公共 API 规范](../../../docs/api-conventions.md#3-分页)。改变每页条数先回到第一页再请求，页码、查询和草稿保护由宿主负责。固定条数的列表不提供条数选择；弹窗和弹出层内的列表按上下文适配。候选窗口和完整明细读取不属于页面默认分页。

表格使用白底、浅灰表头与细边框层次。使用主题填充和边框变量，不逐页硬编码颜色。建议行高 48px。列优先按身份、名称／型号、分类、数量、状态、负责人、时间、操作排序；关键识别字段可加粗。超过四个行内操作收进“更多”，危险动作须确认。

数据列按内容分配可用宽度，操作列按实际动作保留，不用空白列或操作列吸收余宽。长身份与依据应能完整查看，窄屏允许横向滚动，不通过挤压、遮挡动作或截断关键数量适配。

## 7. 表单与反馈

简单单列、中等两列、复杂表单分组，必填清晰。提交和危险确认同时展示当前对象身份、数量／日期约束、真实副作用及不可撤回结果；不能仅有动作名，也不能展示未实现字段。关闭脏草稿须明确确认。

新增、编辑、删除、确认、上传、下载等成功经 EMessage 提示；失败显示可理解原因并遵守[HTTP 消息去重](http-error-handling.md#7-错误对象与页面责任)。普通查询可静默。

## 8. 图标、圆角与空状态

使用轻量线性图标。卡片／按钮输入／弹窗圆角分别 8／6／10px；卡片轻微或无阴影，弹窗可用中等阴影。空状态只提供当前上下文相关操作，不硬编码未来功能。

## 9. 响应式与交付检查

主要适配宽度 ≥1440px，最低 1280px；窄屏表格允许横向滚动，不优先为手机重构。
