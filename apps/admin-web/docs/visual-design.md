# 管理端视觉设计

管理端采用克制的表格与弹窗交互，优先让身份、数量、状态和办理风险易于核对。候选、草稿和并发行为见[管理端架构](architecture.md)，组件接入见[路由与标签页](route-dialogs-and-tabs.md)。业务字典以共享常量为准，不在本规范固定页面和菜单清单。

## 2. 色彩规范

到货、质检与入库组件使用当前运行中的 Element Plus 主题变量，与现有系统配色一致。此约定不涉及应用外壳、品牌样式或全局主题变更。

| 用途 | 主题变量 | 当前默认色 | 说明 |
| --- | --- | --- | --- |
| 主色 | `--el-color-primary` | `#409EFF` | 操作、链接、选中、办理中 |
| 成功 | `--el-color-success` | `#67C23A` | 成功、完成、已生效阶段 |
| 警告 | `--el-color-warning` | `#E6A23C` | 待确认、部分完成、需核对 |
| 错误 | `--el-color-danger` | `#F56C6C` | 阻断、拒绝、危险操作 |
| 中性 | `--el-color-info` | `#909399` | 未开始、历史、失效状态 |
| 主要文字 | `--el-text-color-primary` | `#303133` | 身份与关键数量 |
| 正文 | `--el-text-color-regular` | `#606266` | 常规内容与提示正文 |
| 次级文字 | `--el-text-color-secondary` | `#909399` | 辅助说明 |
| 弱文字 | `--el-text-color-placeholder` | `#A8ABB2` | 零量等低优先级内容 |
| 浅底 | `--el-fill-color-light` | `#F5F7FA` | 表头、分组与普通容器 |
| 主体底色 | `--el-bg-color` | `#FFFFFF` | 表格、表单、弹窗 |
| 浅边框 | `--el-border-color-lighter` | `#EBEEF5` | 表格线、分隔线 |

在 CSS 中引用变量，浅色提示与选中底色使用对应语义色的 `light-9`，不另造深蓝、棕黄或不同绿／红色。单号、物料名和普通待办数量用主文字色、字重及对齐强调，不以链接蓝表示“重要”。本页详情与历史查看采用明确的操作文字，将对象身份与操作分开；同一列表入口统一采用文字按钮，不混用描边小按钮。普通查看、管理和编辑按钮用主蓝，普通菜单项保留组件默认中性文字；需求追溯的“更正最新需求”作为主要办理入口使用主题绿色实心按钮，保留目标需求标识，颜色不代表更正已批准。需要确认或核对的重要流程动作用警告橙，取消等危险操作用错误红。生产任务的结束执行／研发、收尾／产出核对、提前结束与撤回结束遵守同一警告语义；已结束后的只读查看仍用主蓝。重要动作的行内入口、更多菜单及确认弹窗保持一致，禁用、悬停和键盘焦点仍使用对应组件反馈。普通文字不得保留隐形点击行为。色彩表达状态与风险，不给每个普通数字着色。表格与分组保留白色、浅灰层次，标签和必要的局部提示承担语义色。

同一页面的关键正文强调最多使用三种色系，优先复用已有语义色，不为不同数字各配一种颜色。已记录的合格量与不合格量分别用成功绿、错误红的主题文字色并适度加粗；零值保持中性，不以红色制造异常。来料、成品、定稿摘要及引用的历史检验事实遵守同一规则，颜色只表达该记录的检查结果，不表示当前放行或入库资格。实际检查总数、建议量、普通累计量、轮次、ID 及输入中的草稿维持原有中性展示；标签文字、单位及完整值继续保留。

### 2.1 状态标签一致性

来料、到货与成品质检共享语义：未开始用灰色，检验中用主蓝，待核对用橙色，阻断或拒绝用红色，成功或完成用绿色。同一业务状态在列表、详情及办理弹窗中使用一致的标签样式，映射集中到展示辅助函数；Vue 模板引用共享业务字典。

相近状态使用同一语义色家族并通过 `effect` 和明确文案区分：待复检用橙色描边，待定稿用橙色浅底；人工拒收用红色描边，检验不放行用红色浅底；已定稿用绿色描边，实物全部处理完用绿色浅底；历史替代用灰色描边。已定稿只代表该办理阶段完成，不能改写为已入库。不同业务状态不强制分配互不相干的颜色，也不能仅靠颜色区分。

生产任务类型标签在列表、任务详情和工序管理中保持一致：批量使用主题蓝色 `primary`，研发使用主题橙色 `warning`，均采用 `light` 效果。颜色映射集中在生产展示辅助函数，文案使用共享 `WORK_ORDER_TYPE_LABELS`；其颜色表达任务类型，状态与办理风险继续通过各自的标签和文字说明。

物料需求总览与物料分配的需求表统一使用“需求状态”，共同消费服务端需求进度与生产展示辅助函数。需办理的待分配、部分办理及更正审批中用警告橙，已分配用主蓝，领料缺口用错误红，已出库用成功绿，已关闭／取消用中性灰；标签保留共享字典的完整文字，使用相同的小号浅底样式。状态下的分配数量及替代关系仍独立展示，不因配色变更改写需求事实或办理资格。

### 2.2 异常与时间风险的可视层级

风险来自服务端事实或可稳定派生的日期、数量和状态，不能伪造异常或进度。逾期未完使用警告并显示计划日期／天数；有效异常、失败或待处置阻断使用错误色。错误高于警告，始终保留“逾期 N 天／待处置 N 项”等文字，不能仅靠颜色区分。

业务阶段标签彼此可辨，风险用更鲜明的文字或局部边框，不被普通标签盖住。进度同时显示完成／总数，异常和阻断放在识别信息附近；不使用大块高饱和背景或闪烁。列表风险与进度由批量查询投影返回，不逐行加载详情。

### 2.3 报废补产的路线表达

补产来源、固定起点和待补料／前道放行的专用显示边界见[生产交互约束](architecture.md#生产需求收尾与库存)，本规范不重复其数量规则。

异常处理过程与报废补料弹窗的强调色限定为主题蓝、橙、红三色：异常来源工序用橙色、固定首工序起点及任务冻结物料版本用蓝色、产品补产数量用红色，配合完整标签及加粗文字。处理标签中，待处置用橙色、办理中用蓝色、已批准报废用红色，完成与历史用中性灰。编辑与复核均显示冻结版本，补料数量与产品量各自标明单位；失效或不一致的草稿版本保留原值，并在该行显示红色阻断原因。不以整块彩色背景强化普通上下文。

### 2.4 报工事实与异常分组

报工数量列明确标为“数量变动（正常／异常）”：正向非零量带 `+`，冲销非零量带 `-`，零量保持 `0`。业务类型与状态分别说明含义；被冲销原单标“已冲销”，有效冲销事实标“已生效”。异常非零正向量使用主题错误色，普通数量、零值与冲销量保持中性。

异常处理过程的摘要保留待办数和记录总数；非零待办用主题错误色加粗，零待办及记录总数保持次要中性色，始终保留“项待办／项记录”文字。异常处理分组沿用浅灰表头、主体底色和细边框；状态用局部标签表达，不使用整块粉色／红色背景。已完成返工的折叠摘要保留来源单、处置单、返工单、结果单及恢复正常／再次异常量；报废摘要明确“已批准报废”。展开／收起操作与状态标签分开，业务引用使用明确的查看入口打开只读详情。折叠与关联查看的状态所有权见[生产交互约束](architecture.md#生产需求收尾与库存)。

## 3. 字体与排版

字体依次使用 Inter、PingFang SC、Microsoft YaHei、Noto Sans SC、Arial、sans-serif。

| 场景     | 字号 | 字重 |
| -------- | ---: | ---: |
| 页面标题 | 20px |  600 |
| 区块标题 | 16px |  600 |
| 表格正文 | 14px |  400 |
| 表单标签 | 14px |  500 |
| 辅助说明 | 12px |  400 |
| 状态标签 | 12px |  500 |

页面内容边距为 24px；卡片内边距为 16px 或 20px；表单垂直间距为 16px；按钮间距为 8px；工具栏与表格间距为 12px。

详情与记录页的识别信息、状态和数量摘要优先采用紧凑的描述区，同一区域保持相同字号与标签样式，不混用大块数字卡片和密集表格。通过减少装饰容器及空白提高密度，不通过浅色小字弱化关键数量。执行记录的任务概览采用两行摘要，完工检查与办理按钮相邻；工序展开控制与批量操作合并为紧凑工具栏，使用实色背景，仅吸顶时增加轻微阴影。次要信息和完整核对通过明确入口展开，已选明细在独立清单弹窗查看。工序收起头保留关键数量和风险标记，展开正文集中显示动作与完整记录；前道数量核对和有值处理中明细提供局部收纳入口，不把主要数量、办理阻断或未知结果再收进折叠。

执行记录与本人工序列表的额度分段条使用主蓝表示正常、危险色表示已报废、警示色表示处理中、中性色表示剩余额度，已终止未恢复另列并使用灰色。条旁的数量文字与单位始终明确，不能仅靠颜色或百分比说明，更不能让正常段暗示已完工或质检通过。分类待核对时保留真实正常量、上限和余额，未知分类不显示为零；不绘制补差额或零分母的比例，执行记录的报废明细入口仍可用。正文正常来源与摘要正常总量分开，不重复总数。报工弹窗沿用同一数量语义的紧凑只读摘要，突出本次输入上限，不引入记录页的详情操作或重复规则说明；草稿与未知结果提示不能被精简隐藏。

主要数量默认可见；简短规则、范围提示及数量说明使用 [InlineHint](../src/components/InlineHint.vue) 直接呈现，通常一行，窄处自然换行，不以截断或省略号隐藏提示。普通提示用主蓝边线与浅底，关键数量及限制用主文字色加粗；真实差异或阻断按语义着色，不能仅靠颜色表达。长记录可收纳，摘要保留主要阻断、风险和继续查看的入口；审批冻结与未知结果不能收进折叠区。数量必须明确区分执行报工、批准产出和实际入库；尚无结果与已确认零数量使用不同提示。

业务识别优先使用单号、物料编码／版本及服务端真实明细序号；到货明细按[采购专题](procurement-inbound.md#21-详情定位)统一使用真实明细 ID；“第 N 轮”只能取真实轮次字段，不能使用数据库主键、分页索引或当前页排序推算。仅有轮 ID 时使用“当前轮／历史记录”配合检验时间、结论区分。普通业务列表不为清单、授权、分配等原始 ID 单独设列；来源已经明确时不再以内部编号重复识别。追溯入口使用业务名称并直接定位对应单据或任务，版本号须说明属于哪份业务依据，并配合批准人、批准时间或检验结论解释其用途。需要排查的原始标识只在明确的追溯记录或技术页面标为“检验记录 ID／处理轮 ID”，不以裸 `#数字`、含糊的“身份”或“轮次”冒充业务编号。历史引用必须保留原记录关系，不能借用当前轮次、最新检验或时间；接口未提供的业务编号及依据内容不得由前端伪造。

工单详情采用紧凑的带边框描述表，浅灰标签格、白色内容格，单号、正文和数量均使用 14px，长单号与备注自然换行。该弹窗的强调色限定为主题蓝、橙、红三种：计划数量及非零审定可用合计用蓝色，计划内产出与计划的差额及待结案非零批数用橙色，非零审定报废用红色；零值保持中性。状态沿共享元数据使用蓝／橙／红表达办理中、待处理与取消，其余状态用中性加粗文字保留完整名称，不额外增加绿色。普通标识用中性字重强调，不使用卡片式数量摘要或独立的基本信息／产出大分组。研发前后序都为空时合并为简短说明，不重复放置大面积空状态；真实关联保留明确的查看入口，开启下一轮继续遵守 [Production 的研发轮次规则](../../api/src/modules/production/docs/database/work-orders-and-batches.md#研发轮次关联与资料带出)。

单据分块头沿用采购到货表格的浅灰底、细边框与紧凑间距，主标识使用 14px 加粗、摘要使用 12–13px。仅用于展开的单号采用主文字色，悬停也不变成链接蓝；独立来源链接和业务操作继续使用主蓝。外购物料、批准成品及其他入库共用 `InboundGroupHeader`，标题与计数区域可点击，左侧以中性描边的箭头和“展开／收起”明确折叠动作；文案、箭头方向与 `aria-expanded` 同步，键盘焦点清晰。独立选择和来源操作不触发折叠。长证据折叠仍可使用浅主色底，样式按组件显式接入，不全局覆盖所有折叠组件，也不把简短提示重新收进折叠区。

需求总览与更正追溯为人工核对替代关系保留需求 ID 列，相关记录统一使用 `id:{id}`，不使用 `#{id}`。需求 ID 仅表示真实记录身份，不表示更正次数或业务版次。

## 4. 管理端布局

左侧菜单展开宽度为 220px、最多两级；顶部标题前提供始终可用的收起／展开按钮，收起后完整隐藏侧栏，内容区填满可用宽度。切换保留菜单展开状态、当前路由和标签页草稿；折叠状态由布局实例持有，路由切换保留，整页刷新恢复展开。按钮提供动作提示、键盘操作和同步的展开状态；侧栏隐藏时其菜单不可获得键盘焦点。路由区弹窗的遮罩边界随内容区尺寸同步更新。

顶部显示当前页面及系统／用户入口，不放业务动作。菜单由路由及权限驱动；内容区不重复顶部标题，优先从筛选、工具栏或主体开始。不放“迁移验证／测试入口”等开发占位说明。

## 5. 弹窗规范

编辑、详情和确认统一用 Modal，不以 Drawer 为主要方式。整体最大高度为挂载区 `.content` 的 90%，不是视口高度；垂直居中，标题／底部可见，仅正文溢出滚动。

| 类型 | 推荐宽度 | 上限 |
| --- | --- | --- |
| 小型确认 | 420px | 90vw |
| 常规表单 | 640px | 75vw |
| 多字段表单 | 860px | 75vw |
| 复杂详情 | 1000px | 75vw |
| workbench | 1400px | 内容区宽度减 32px |

工作台左右至少各留 16px，宽表操作列固定右侧；共用普通弹窗的高度和滚动规则。挂载、缓存、关闭保护和最小代码示例见[路由规范](route-dialogs-and-tabs.md)，不再逐页复制尺寸 CSS。

## 6. 表格规范

直接路由页面的分页列表统一使用 [PaginationFooter](../src/components/PaginationFooter.vue)，包含页面内的页签、子路由面板和侧栏列表；默认查询每页 10 条，分页协议和可选条数见[公共 API 规范](../../../docs/api-conventions.md#3-分页)。改变每页条数先回到第一页再请求，页码、查询和草稿保护由宿主负责。窄侧栏通过 `compact` 使用紧凑布局，加载或导航保护期间通过 `disabled` 禁用操作；已有固定条数约束的列表通过 `showPageSize=false` 隐藏条数选择。弹窗和弹出层内的列表按其上下文单独适配，不强制套用页面布局；候选窗口和完整明细读取不属于页面默认分页。

表格使用白底、浅灰表头与细边框层次。到货、质检与入库组件使用 `--el-fill-color-light` 作表头／分组、`--el-border-color-lighter` 作边框、`--el-fill-color` 作悬停色；采购单等其他页面保持现有中性底色。建议行高 48px。列优先按身份、名称／型号、分类、数量、状态、负责人、时间、操作排序；关键识别字段可加粗。超过四个行内操作收进“更多”，危险动作须确认。

自适应操作列按当前实际按钮内容及单元格留白确定宽度，空表按表头；固定右侧只决定位置，不能把剩余表宽分配给操作列。载入、分页、尺寸及字体变化后重新测量，测量容器保持自身内容宽，避免列宽反向撑大测量值。

## 7. 表单与反馈

简单单列、中等两列、复杂表单分组，必填清晰。提交和危险确认同时展示当前对象身份、数量／日期约束、真实副作用及不可撤回结果；不能仅有动作名，也不能展示未实现字段。关闭脏草稿须明确确认。

新增、编辑、删除、确认、上传、下载等成功经 EMessage 提示；失败显示可理解原因并遵守[HTTP 消息去重](http-error-handling.md#7-错误对象与页面责任)。普通查询可静默。

## 8. 图标、圆角与空状态

使用轻量线性图标。卡片／按钮输入／弹窗圆角分别 8／6／10px；卡片轻微或无阴影，弹窗可用中等阴影。空状态只提供当前上下文相关操作，不硬编码未来功能。

## 9. 响应式与交付检查

主要适配宽度 ≥1440px，最低 1280px；窄屏表格允许横向滚动，不优先为手机重构。交付时核对统一视觉、危险确认、操作反馈和 UTF-8 中文无乱码；业务验证与状态遵守[测试策略](../../../docs/testing-strategy.md)和[路线图](../../../docs/roadmap.md)。
