# 其他入出库交互

单据、批次及确认资格由 [Inventory](../../api/src/modules/inventory/docs/database/inventory-ledger-and-inbound.md)维护；仓储分类与父标签关闭保护见[路由规范](route-dialogs-and-tabs.md)。本文只补充草稿编辑的特殊边界。

## 草稿与目标

界面允许临时移除全部明细，空表单不能保存。编辑行位置不充当业务行号；详情使用服务端行号并保留已移除历史。

新建物料批次先选基础物料，再选精确版本；只完成第一步也算未保存输入。已有批次带出历史对象并只读显示；切换对象或批次方式后清除不再适用的旧选择。

新批次组在保存草稿后仍保留关系，显示为“本单新批次组”，确认后才显示实际批号。批次目标的本地选择与拆分交互共用[入库目标规则](procurement-inbound.md#7-有效放行与实际入库)，不能因共用组件而共享可变草稿。

## 保存、确认与并发

保存草稿和整单确认是不同意图；确认前明确实际库存影响和不可修改的后果。输入、版本与未知结果的保护统一遵守[管理端架构](architecture.md)。
