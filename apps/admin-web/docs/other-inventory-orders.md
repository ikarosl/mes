# 其他入出库交互

管理端为其他入库、其他出库提供独立页面与缓存标签。业务单据、批次、库存流水及确认资格由 [Inventory](../../api/src/modules/inventory/README.md) 所有；公共六场景的字段和约束见[通用出入库设计](../../../docs/tmp_sql_design/README.md)。人工验收与正式测试状态由[路线图](../../../docs/roadmap.md#通用出入库后续阶段)维护，实现存在不表示已验收。

## 草稿与目标

首次创建及每次保存均提交完整的 1–50 条有效明细；界面允许临时移除全部行，但空表单不能保存。数量采用整数，办理原因必填，单据及行备注可选。编辑保留服务端明细 ID；已移除行不再进入保存载荷，后端保留其软删除历史。详情区展示真实行号及历史已移除行，不将编辑行位置当作业务行号。

每行明确选择物料精确版本或成品。已有批次选择直接带入批次的历史对象、单位和版本，允许办理停用对象的合格存量批次；入库候选包括零余额批次。新建目标只从启用对象的服务端搜索窗口选择；重开草稿按已选 ID 单独核验，失败或失效时保留名称与 ID，并阻止保存。

其他入库的新批次组只在本单内有效。相同对象、版本及单位的行可选择同一组，界面显示临时组名与行数，不展示分组键或将其当作库存批号。更换对象或点击单独建批会建立新的组；实际批号由确认命令生成。既有批次补入不开放批号、生产日期或建批来源修改。

批次及对象均使用服务端远程搜索的有限窗口，不接入旧 Live Options 封装或全局可变缓存。窗口缺少原已选批次不表示失效，详情提供历史名称兜底；余额、批次状态与生产预留由确认命令重新检查。出库候选分别显示可用库存、生产预留和可出数量，不能将草稿数量或生产预留当成已出库事实。

## 保存、确认与并发

保存只产生或修改草稿。整单确认前展示单号、有效行数和按单位分别汇总的数量，以及实际库存影响与终态不可修改的约束。取消原因独立必填，取消保留全部历史明细。不同单位不合并为一个总数；其他单据不以备注、对象或库存流水推断原采购、生产领退料或产出履约。

创建、保存、确认及取消均由当前编辑器持有幂等意图，首次请求冻结路径、完整载荷及父单版本。未知结果锁定输入，安全重试使用原请求与原键；结果损坏或超出重试窗口不能继续盲发。详情刷新可以用于核对，但不替换脏草稿、原版本或未确认意图；远端发生变化时阻止旧依据提交，明确采用最新单据才替换输入。

首次页面挂载读取一次列表；列表、详情、批次候选及对象候选各自持有读取代际和取消信号。详情在打开或手动刷新时读取，候选在搜索、选择展开、显式刷新或重开草稿核验时读取。缓存页返回保留输入，不自动刷新全部资源。写成功只刷新当前有效列表并更新本次提交的单据；关闭、切换单据、页面失活或销毁使旧读取失效。

Dialog 与列表并列挂载，遵守[路由弹窗规则](route-dialogs-and-tabs.md)。关闭窗口、切换单据或关闭非活动标签均保护未保存输入和未知结果；提交中禁止关闭。权限控制菜单、路由与整页可见性，各动作仍由后端独立鉴权。候选、详情及列表读取失败局部提示，不以空结果覆盖草稿或让迟到错误影响新目标。

既有采购入库、批准成品入库、生产领料及退料仍从各自办理入口进入；公共主从结构不为这些来源开放其他单据的草稿编辑或人工来源填写。
