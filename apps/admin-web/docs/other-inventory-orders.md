# 其他入出库交互

管理端将其他入库、其他出库分别纳入入库管理、出库管理的页内分类，同一方向共用顶部缓存标签。分类仍按各自查看权限开放，只有其他单查看权限的账号也能从对应菜单进入；整合入口不授予采购入库、成品入库或生产领料资格。业务单据、批次、库存流水及确认资格由 [Inventory](../../api/src/modules/inventory/README.md) 所有；公共六场景的字段和约束见[Inventory 数据库设计](../../api/src/modules/inventory/docs/database/inventory-ledger-and-inbound.md)。人工验收与正式测试状态由[路线图](../../../docs/roadmap.md#通用出入库后续阶段)维护，实现存在不表示已验收。

## 草稿与目标

首次创建及每次保存均提交完整的 1–50 条有效明细；界面允许临时移除全部行，但空表单不能保存。数量采用整数，办理原因必填，单据及行备注可选。编辑保留服务端明细 ID；已移除行不再进入保存载荷，后端保留其软删除历史。详情区展示真实行号及历史已移除行，不将编辑行位置当作业务行号。

每行明确选择物料精确版本或成品。新建批次的物料分两级选择：先基础物料，再由服务端按该物料查询精确版本；成品只选择成品身份，不借用 BOM 或工艺版本。基础物料候选要求至少一个有效启用版本，两个搜索窗口分别携带已选 ID 核验；不能从精确版本的有限窗口在前端分组推算全部物料或版本。库存用途沿用自身候选和权限，不直接使用允许停用版本的采购候选。重开草稿核验失败或失效时保留名称与 ID，并阻止保存；只选择基础物料尚未选版本也属于未保存输入。

已有批次选择直接带入批次的历史对象、单位和版本并只读展示，允许办理停用对象的合格存量批次；入库候选包括零余额批次。新建目标只从启用对象的服务端搜索窗口选择，切换类型、物料或批次方式时不能保留与新目标不一致的旧版本或批次。

其他入库的新批次组只在本单内有效，共用资格及交互遵守[入库目标规则](procurement-inbound.md#7-有效放行与实际入库)。更换对象或点击独立新建会建立新的组，草稿保存保留组关系；实际批号由确认命令生成。共用新批次在批次列直接选择，行备注放在主明细行独立备注列，均不要求先展开明细；对象、数量、单位、错误与未知结果始终可见。既有批次补入不开放批号、生产日期或建批来源修改。

批次及对象均使用服务端远程搜索的有限窗口，不接入旧 Live Options 封装或全局可变缓存。窗口缺少原已选批次不表示失效，详情提供历史名称兜底；余额、批次状态与生产预留由确认命令重新检查。出库候选分别显示可用库存、生产预留和可出数量，不能将草稿数量或生产预留当成已出库事实。

## 保存、确认与并发

保存只产生或修改草稿。整单确认前展示单号、有效行数和按单位分别汇总的数量，以及实际库存影响与终态不可修改的约束。取消原因独立必填，取消保留全部历史明细。不同单位不合并为一个总数；其他单据不以备注、对象或库存流水推断原采购、生产领退料或产出履约。

创建、保存、确认及取消均由当前编辑器持有幂等意图，首次请求冻结路径、完整载荷及父单版本。未知结果锁定输入，安全重试使用原请求与原键；结果损坏或超出重试窗口不能继续盲发。详情刷新可以用于核对，但不替换脏草稿、原版本或未确认意图；远端发生变化时阻止旧依据提交，明确采用最新单据才替换输入。

首次分类挂载读取一次列表；列表、详情、批次候选、基础物料及精确对象候选各自持有读取代际和取消信号。详情在打开或手动刷新时读取，候选在搜索、选择展开、显式刷新或重开草稿核验时读取。缓存分类返回保留输入，不自动刷新全部资源。写成功只刷新当前有效列表并更新本次提交的单据；关闭、切换单据、分类失活或销毁使旧读取失效。

Dialog 与列表并列挂载，使用与采购及既有入库弹窗相同的 workbench 尺寸，遵守[路由弹窗规则](route-dialogs-and-tabs.md)与[视觉设计](visual-design.md)。切换页内分类隐藏所属弹窗并保留草稿；关闭父标签时检查各分类的未保存输入和未知结果，包括当前不可见的分类。关闭窗口、切换单据或关闭非活动标签均保护未保存输入和未知结果；提交中禁止关闭。权限控制菜单、分类路由与整页可见性，各动作仍由后端独立鉴权。候选、详情及列表读取失败局部提示，不以空结果覆盖草稿或让迟到错误影响新目标。

采购入库、批准成品入库及生产领料仍从各自分类办理，退料保留原入口；公共主从结构不为这些来源开放其他单据的草稿编辑或人工来源填写。“其他”分类明确独立办理，不计入采购或生产履约，不以“通用”命名暗示全部来源均可手工创建。
