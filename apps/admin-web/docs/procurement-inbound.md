# 采购与入库的前端约束

订单、金额和补单由[采购订单](../../api/src/modules/procurement/docs/purchase-orders.md)维护；到货及作废由[到货处置](../../api/src/modules/procurement/docs/receipts.md)维护；数量与执行授权由[整批定稿](../../api/src/modules/procurement/docs/receipt-acceptance.md)维护。本文只保留额外的输入、草稿与跨页约束。

通用候选、并发及未知结果遵守[管理端架构](architecture.md)，检验与定稿的表单差异见[来料交互](incoming-inspection-adoption.md)。

## 2. 页面与路由

### 2.1 详情定位

| 入口 | 定位身份与特殊含义 |
| --- | --- |
| 采购 | `purchaseOrderId`；具体行附 `purchaseOrderLineId` |
| 从需求建单 | `workOrderId+demandId`；不能只凭需求 ID 猜工单 |
| 从到货办补单 | 原采购定位加 `supplementLineId+supplementReason+receiptLineId`；重新核验后进入补单选择，不自动采用依据 |
| 到货／来料 | 到货用 `receiptId`，具体行附 `receiptLineId`；来料直接用到货行 ID |
| 入库 | `inboundId`；外购附 `sourceType=purchased`。缺少类型的既有入口仍按成品处理，再由详情核实 |
| 库存批次 | `itemBatchId` |

采购行与到货行分别标为真实“采购行 ID”“到货行 ID”，不借用彼此行号、处理轮或页内序号。退回历史只定位来源采购，不带补单参数开启办理。关联补单从目标详情按原采购行、可选到货明细及补因解析目标行；没有唯一匹配就只展示主单并提示核对，不猜首行。

定位不改变查询、分页或总数；页外单据独立展示。成功后同步真实主单／行 ID，清除已消费的建单或补单参数，缓存返回不重复办理。目标不存在、读取失败或用户取消时保留原有效定位；清除定位同时清除临时页外单据及对应参数。换单保护见[公共草稿规则](architecture.md#2-草稿与关键详情)。

生产需求总览是任务内弹窗，没有独立需求路由；相关采购须回到真实任务入口，不把同名 HTTP 资源当页面链接。

## 3. 供应商及采购选择

### 3.1 候选和跨页选择

按需采购的已选需求独立于分页窗口；不提供隐式全选或全量读取。添加时按当前草稿全部行来源标识“已添加”，行级关联则带入本行来源。选择窗只是临时集合，确认采用后才改变采购草稿，失败保留两边输入。

切换工单影响全部编辑行，即使没有勾选需求也须确认清空；外部定位触发同一守卫。相同物料精确版本的新增需求加入既有行，保留采购量、金额及逐需求供应商提示，由人员重新核对；提示不自动代选供应商。

### 3.2 采购行与独立补单

补单主窗持有已采用的明细；来源选择窗持有独立搜索、分页与临时集合。定位不等于选择，即使只有一个候选也不能自动采用。确认才批量加入，取消丢弃临时变化；主窗已有行防止再次加入。

更换依据只查当前原采购行；采用后保留数量和说明并提示重核，取消不改变原依据。已有选择或输入时，切换补因须确认清空。候选空态只说明当前条件未命中，不宣称该来源没有历史依据；资格和数量口径见[补单所有者](../../api/src/modules/procurement/docs/purchase-orders.md#补单来源与独立物流)。

### 3.3 需求相关采购

相关采购从具体需求按需打开，只核对真实采购行及来源，不在需求总览预加载采购数或采购量。发起采购携带工单与需求定位，目标页重核；来源查看和办理入口各自按目标页权限提供。

### 3.4 到货身份与数量输入

未到行可留空。同一采购行追加另一来料批次是新增输入，不从原行扣量；空行属于草稿。采购行的参考累计只显示一次，本次合计只计将提交的实收输入。

累计变化不覆盖输入。提交前若发现累计已变，先停止并提示核对，再次确认后才继续；不能把采购计划余量设置成实收输入上限。

### 3.5 金额草稿与下单后更正

金额输入、推算和手填覆盖直接遵守[金额契约](../../api/src/modules/procurement/docs/purchase-orders.md#明细采购单位单价)。已有草稿的派生预览不回填为手填输入；历史总额与新公式不同，也不能仅因此生成待保存更正。是否有修改按打开时的人工输入判断。

正式金额更正在采购单详情独立编辑，不由物流列表承担。主单内全部已修改行作为一次保存意图；状态或依据变化须重新打开核对，不只替换版本。普通列表刷新不重建这份金额草稿。

## 5. 到货、实收更正与退回

采购与来料的分层读取、完整目录及统计口径见[到货查询](../../api/src/modules/procurement/docs/receipt-queries.md)。展开仅作用于当前层已加载项，明确定位和人工选择优先；收起主单同时收起下层到货，重开先恢复目录。缓存只保留当前分页窗口及必要定位对象。

处置、定稿、作废和历史分别持有上下文，收起或翻页不销毁草稿。采购和来料只共用展示，各自持有查询、分页及动作；本单物料检索只过滤索引，不清除当前行或子编辑器。

普通到货摘要用“到货量”，作废历史用“作废前到货量”；当前“尚未入库或退回”不能被标成待检量。定稿的总量输入与历史剩余量见[来料核对](incoming-inspection-adoption.md#库管核对定稿)。

作废按专用整单预览确认，不以当前页或已展开明细代表范围。确认须说明所有者规定的整单影响；历史查看继续保留原登记与检查依据。退回只核对具体有效分配，不因快捷入口跳过范围选择。

## 7. 有效放行与实际入库

业务确认范围及原子性见[外购入库决定](../../../docs/adr/0018-purchase-inbound-multiple-suppliers.md)、[成品入库](../../api/src/modules/production/docs/database/finished-goods-inbound.md)；批次身份与共批资格见 [Inventory 目标契约](../../api/src/modules/inventory/docs/public-contracts.md)。

候选选择和确认弹窗使用同一份本地草稿；分组只组织当前页，不能代表整张到货或工单。加入新来源保留已有选择、数量和目标，并明确本次核对范围。各入库场景独立持有候选及草稿。

数量默认有效余量，可由人员调整。新批次默认逐行独立，只有人员明确选择才共用；移除或退出一行不改其他成员。拆分由人员填写分出量并扣减原行，保持本次合计；取消授权选择移除其全部目标，删除单个目标只影响该行。

编辑行用本地 `rowKey` 绑定输入、错误和操作，不进入请求；`target.clientKey` 标识本次新批次，两者不能混用。按真实授权汇总其全部目标核对余量，不依赖行是否相邻；非法数量保留原文并阻止确认，不自动截断或回填。重核仍是同一授权时可更新余量，但保留已填数量供核对，不能静默换分配或目标。

历史按入库单组织，明确定位优先，刷新保留人工展开选择；页外定位单独显示，不计筛选总数。来源入口使用当时真实采购行、到货行及采用的检验记录；缺少来源投影时明确说明，不逐行猜补。

目前外购入库折叠摘要保留供应商信息，确认提示保留涉及的到货单数和供应商数；供应商摘要与家数提示是否保留仍是[待决定项](../../../docs/temp/todo.md)。逐明细来源与历史证据不因这两处展示取舍而变化。
