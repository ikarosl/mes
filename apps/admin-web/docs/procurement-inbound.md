# 采购与入库的前端约束

订单、金额和补单由[采购订单](../../api/src/modules/procurement/docs/purchase-orders.md)维护；到货登记、实际入库和其他处理由[到货所有者](../../api/src/modules/procurement/docs/receipts.md)维护。本文只保留额外的输入、草稿与跨页约束。

通用候选、并发及未知结果遵守[管理端架构](architecture.md)，独立检验报告见[来料交互](incoming-inspection-adoption.md)。

## 2. 页面与路由

### 2.1 详情定位

| 入口         | 定位身份与特殊含义                                                                                     |
| ------------ | ------------------------------------------------------------------------------------------------------ |
| 采购         | `purchaseOrderId`；具体行附 `purchaseOrderLineId`                                                      |
| 从需求建单   | `workOrderId+demandId`；不能只凭需求 ID 猜工单                                                         |
| 从到货办补单 | 原采购定位加 `supplementLineId+supplementReason+receiptLineId`；重新核验后进入补单选择，不自动采用依据 |
| 到货／来料   | 到货用 `receiptId`，具体行附 `receiptLineId`；来料直接用到货行 ID                                      |
| 外购入库     | `inboundId`，附 `sourceType=purchased`                                                                 |
| 成品入库记录 | `inventoryBatchId`；输入与跨页约束见[工序追踪](production-tracking.md)                                 |
| 库存批次     | `itemBatchId`                                                                                          |

采购行与到货行分别标为真实“采购行 ID”“到货行 ID”，不借用彼此行号、处理轮或页内序号。退回历史只定位来源采购，不带补单参数开启办理。关联补单从目标详情按原采购行、可选到货明细及补因解析目标行；没有唯一匹配就只展示主单并提示核对，不猜首行。

定位不改变查询、分页或总数；页外单据独立展示。成功后同步真实主单／行 ID，清除已消费的建单或补单参数，缓存返回不重复办理。目标不存在、读取失败或用户取消时保留原有效定位；清除定位同时清除临时页外单据及对应参数。换单保护见[公共草稿规则](architecture.md#2-草稿与关键详情)。

生产需求总览是任务内弹窗，没有独立需求路由；相关采购须回到真实任务入口，不把同名 HTTP 资源当页面链接。

## 3. 供应商及采购选择

### 3.1 候选和跨页选择

按需采购的已选需求独立于分页窗口；不提供隐式全选或全量读取。添加时按当前草稿全部行来源标识“已添加”，行级关联则带入本行来源。选择窗只是临时集合，确认采用后才改变采购草稿，失败保留两边输入。

切换工单影响全部编辑行，即使没有勾选需求也须确认清空；外部定位触发同一守卫。相同物料精确版本的新增需求加入既有行，保留采购量、金额及逐需求供应商提示，由人员重新核对；提示不自动代选供应商。

### 3.2 采购行与独立补单

补单主窗持有已采用的明细；来源选择窗持有独立搜索、分页与临时集合。定位不等于选择，即使只有一个候选也不能自动采用。确认才批量加入，取消丢弃临时变化；主窗已有行防止再次加入。

更换依据只查当前原采购行；采用后保留数量和说明并提示重核，取消不改变原依据。已有选择或输入时，切换补因须确认清空。候选空态只说明当前条件未命中，不宣称该来源没有历史依据；资格和数量口径见[补单所有者](../../api/src/modules/procurement/docs/purchase-orders.md#补单来源与独立物流)。

### 3.3 需求相关采购

相关采购从具体需求按需打开，只核对真实采购行及来源，不在需求总览预加载采购数或采购量。发起采购携带工单与需求定位，目标页重核；来源查看和办理入口各自按目标页权限提供。

### 3.4 到货物料选择

到货草稿只勾选本次采购物料，交接凭据与来料批次号选填，不填写实际数量。切换采购单须先确认放弃已选物料和输入。提交前重核采购主单与已选行的版本和登记资格；刷新不覆盖草稿。

### 3.5 金额草稿与下单后更正

金额输入、推算和手填覆盖直接遵守[金额契约](../../api/src/modules/procurement/docs/purchase-orders.md#明细采购单位单价)。已有草稿的派生预览不回填为手填输入；历史总额与新公式不同，也不能仅因此生成待保存更正。是否有修改按打开时的人工输入判断。

正式金额更正在采购单详情独立编辑，不由物流列表承担。主单内全部已修改行作为一次保存意图；状态或依据变化须重新打开核对，不只替换版本。普通列表刷新不重建这份金额草稿。

## 5. 到货目录与记录

采购到货按到货单服务端分页，展开读取整张到货的完整轻量物料，查询与统计口径见[到货查询](../../api/src/modules/procurement/docs/receipt-queries.md)。当前页展开只作用于该页到货；明确定位和人工选择优先，页外定位独立展示且不改变查询与分页总数。缓存只保留当前分页窗口及必要定位对象。来料的报告草稿与精确定位由[来料交互](incoming-inspection-adoption.md)维护。

到货查看、整单作废和仓库记录分别持有上下文；采购和来料各自持有查询与分页。本单物料检索只过滤索引，不清除当前明细或说明草稿。到货不呈现到货量、未入余量或线下退回完成量。

到货列表展示实际入库累计、报告记录数和最近处理说明；详情按物料在当前窗口查看入库明细、检验报告和处理说明，不提供入库、检验或补单的跨页办理快捷入口。检验汇总遵循 Quality 的[报告口径](../../api/src/modules/quality/docs/unified-inspection-model.md#事务与权限)，没有查看权限、尚未读取和读取失败分别呈现，不作为零记录；查看报告只读取持久内容并支持打印，不在到货详情登记或修订报告。

作废按专用整单预览确认，不以当前页或已展开明细代表范围。确认范围和限制由所有者规定，原到货及报告历史继续可查。

## 7. 实际入库与其他处理

实际入库与独立处理说明的契约见[到货所有者](../../api/src/modules/procurement/docs/receipts.md)；目标批次资格见 [Inventory 目标契约](../../api/src/modules/inventory/docs/public-contracts.md)。

候选选择和确认弹窗使用同一份本地草稿；分组及块内选择只覆盖本页命中项，并保留跨页已选。核对仅使用已选到货明细；加入新来源保留数量和目标，不能静默扩大或清空选择。各入库场景独立持有候选及草稿。

实际入库数量初值留空，只接受正整数，并须选择库存批次。其他处理从到货物料行或详情打开对应物料的说明页签，在页签内登记；说明草稿归该到货行，与入库草稿分开持有。刷新历史不覆盖说明输入，切换物料或关闭前保护未保存说明及未知提交结果。历史中已有的入库关联继续供追溯，新说明不从入库确认提交。

新批次默认逐行独立，只有明确选择才共用。拆分填写分出量并扣减原目标，保持本次合计；取消来源选择移除它的全部目标，删除单个目标只影响该行。编辑行使用本地 rowKey，target.clientKey 标识新批次组；两者不能混用。非法数量保留原文并阻止确认，不自动截断或回填。

提交前按真实到货明细与版本重核；依据变化时保留输入并阻止旧依据提交，人工刷新只采用同一来源的最新依据。未知结果仍提供原请求重试，不先按新候选重新提交。

历史按入库单组织，明确定位优先，刷新保留人工展开；页外定位单独显示，不计筛选总数。逐明细保留真实采购、供应商和到货来源，检验报告独立查看，不显示为入库采用依据。缺少来源投影时明确说明，不逐行猜补。

外购入库折叠摘要与确认提示保留多供应商信息；两处摘要的展示取舍仍见[待决定项](../../../docs/temp/todo.md)。逐明细证据不随摘要取舍变化。
