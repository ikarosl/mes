# 采购与入库的前端约束

本文维护代码和页面外观不容易解释的输入、候选、并发及跨页约束。业务规则的主要依据为 [采购订单](../../api/src/modules/procurement/docs/purchase-orders.md)、[到货与更正](../../api/src/modules/procurement/docs/receipts.md)、[整批定稿与执行授权](../../api/src/modules/procurement/docs/receipt-acceptance.md)；跨模块背景见[业务设计](../../../docs/procurement-inbound-design.md)。本文不另行定义数量公式、状态机或业务资格。

[来料交互](incoming-inspection-adoption.md)维护检验、定稿与拒收的专用约束；[管理端架构](architecture.md)、[路由与标签页](route-dialogs-and-tabs.md)、[HTTP 错误处理](http-error-handling.md)维护通用行为。未完成事项和验收状态以[路线图](../../../docs/roadmap.md)为准。

## 1. 当前交互边界

采购来源、供应商身份、检验事实和执行资格均来自所属模块。前端不得用展示摘要推断资格，尤其注意：

- 采购供应商属于主单；采购、到货和来料来源的供应商展示取对应采购主单，单张到货不再表达供应商集合。生产的 supplierHint 仅供采购参考，不能自动代选供应商；来料质检主单仍可跨采购和供应商组织工作。
- 采购可选择仍符合其他资格的停用精确版本，生产选版则有自己的启用要求。使用采购专用候选并显示状态，不能复用生产过滤条件。
- 到货前不指定内部库存批次；首次实际入库也可选择已有合资格批次。到货不持有单一内部库存批次；历史批次集合与逐笔目标来自真实入库明细。
- 外购输入保存在本地草稿；成品从有效授权直接确认入库，两个来源共用目标批次选择交互。

## 2. 页面与路由

路由、菜单和权限映射直接见 [router](../src/router/index.ts)、[AdminLayout](../src/views/AdminLayout.vue)；不在本文另列一套页面清单。页面只按查看权限控制整页，命令权限由后端逐接口校验，不要求页面内按钮做权限隐藏。

### 2.1 详情定位

- 采购定位使用 `purchaseOrderId`，定位具体采购行再附 `purchaseOrderLineId`；从需求发起草稿使用 `workOrderId+demandId`。从到货详情的办理入口转采购补单时，附 `supplementLineId+supplementReason+receiptLineId`；采购页须重新读取原单及具体依据后定位统一补单弹窗，不信任路由参数本身。退回历史只用 `purchaseOrderId+purchaseOrderLineId` 普通定位来源采购，不携带补单参数自动打开办理；来源列展示采购单号、采购固定行号及采购行 ID，不以到货行号冒充采购行号，无采购查看权限时仍保留这些只读标识。采购页滚动到目标行，外部定位时保留“当前定位”标记供对照。参数必须经服务端解析资格与归属，单独 demandId 不自动推定工单。
- 采购行与到货行在列表、详情、候选、历史和入库来源中分别以真实 `purchaseOrderLineId` 与 `receiptLineId` 识别，界面统一使用“采购行 ID”“到货行 ID”。已由列头或字段标签说明身份时，值仅显示数字；与单号或其他身份并列时保留明确类型，例如 `采购单号 · 采购行 ID {purchaseOrderLineId}` 与 `到货单号 · 到货行 ID {receiptLineId}`。不以主单 ID、列表序号或处理轮号替代，也不并列展示“第 N 行”和重复 ID。采购行的到货记录弹窗将“到货单号”和“到货行 ID”分别置于独立列，便于追溯沟通。物料只显示名称与完整精确版本，不重复拼接精确版本已包含的基础编码。采购固定行号、本次入库草稿序号及真实处理轮号仍表达各自含义，不以行 ID 替代。
- 到货定位使用 `receiptId`，可附 `receiptLineId`；来料检验使用 `receiptLineId`。从采购发起到货仍以 `purchaseOrderId` 打开登记，尚无到货的采购不插入工作列表，保存后按返回的真实到货 ID 定位。入库继续用 `inboundId`，外购显式附 `sourceType=purchased`；没有 sourceType 的既有定位仍按成品处理，再读取详情核实真实类型。
- 外购入库可由 `receiptLineId` 查询当前有效分配，不能把来源页携带的旧数量当授权。采购已结束不等于原到货不可继续办理。
- 更换定位目标先确认放弃未保存输入；取消保留原草稿和原定位。提交中或结果未知时阻止换单。离开页面仅使旧读取失效，不销毁缓存草稿。
- 关联补单查看沿用采购 ID 定位：从目标详情中按原采购行 ID、可选的到货明细 ID 及补因解析真实补单行，不能把原采购行 ID 当作目标行 ID。恰好匹配一行时定位该行；没有唯一匹配时仅展示目标主单并提示核对，不猜测首行。明确携带的目标行不存在时保留原有效定位并提示失败。
- 定位成功后展开目标主单，主单和具体行保留“当前定位”标记，并滚动到目标内容；成功查看的主单／行 ID 同步到当前路由，清除已消费的补单办理和需求建单入口参数，刷新或缓存标签返回不重开旧来源。清除定位同时移除标记、临时页外单据及路由定位参数。定位不改变原查询条件、页码、分页总数，也不以关键词模拟唯一查找；读取失败、关闭取消及迟到响应不能替换有效定位。
- 生产需求总览由 [MaterialDemandOverviewDialog](../src/views/production/components/MaterialDemandOverviewDialog.vue)承担，没有独立 `production-material-demands` 路由；同名 HTTP 资源不能当页面链接。

## 3. 供应商及采购选择

### 3.1 候选和跨页选择

供应商目录及名称约束见[供应商设计](../../api/src/modules/procurement/docs/suppliers.md)。普通采购在主单明确选择已有供应商 ID，草稿可更换，正式下单后冻结；补单继承原主单供应商并只读。不把自由文本当关系键、不隐式创建供应商或建立物料绑定；不存在时先维护目录。供应商编辑保留打开时的版本，重复名称失败保留输入；资料变化后阻止提交，须关闭并从最新列表重新选择，不能更新版本后覆盖他人修改。

按需采购先选择一个工单。候选由专用工单接口及需求分页接口提供，不能从第一页需求拼凑工单。需求分页按叶子计数，任务分组只是当前页投影；跨页选择用独立 demandId 集合保存，不因翻页、刷新或当前窗口缺少某项而判为失效，不提供全选或隐式全量读取。

顶部“添加需求”按当前草稿全部行的来源标记“已添加”并禁选，已有来源独立于本次跨页勾选集合；重新打开已保存草稿或选择框仍以当前来源识别。行级“关联需求”预选本行来源。采用前再次核对重复与提交锁定；采用失败保留选择和采购输入，不能静默新建重复行。

选中 ID 解析逐项返回当前资格及原因；失败保留草稿并禁止下单，不能默认合格或清空来源。在审更正等阻断由服务端判定。新采购候选过滤不能用于屏蔽已有采购的历史来源；草稿保存及正式下单分别重核资格。

切换工单会影响所有采购编辑行，即使当前没有勾选需求也须确认清空；取消切换保留原状态。收到外部定位参数执行同一守卫，不能静默带入其他工单的需求。独立备料不关联或伪造工单、任务、需求。

### 3.2 采购行与独立补单

选择后以物料及精确版本组织来源，同单只保留一条相同物料精确版本的行。采购量独立填写，不自动当成需求满足量或以需求剩余量封顶；向不同供应商采购须分别建单。

新增同物料精确版本的需求时，将来源去重加入既有行，保留已填采购量和金额，由人员重新核对；不复制相同身份的采购行或按需求拆成重复行。普通按需草稿可从关联需求条数进入编辑，supplierHint 逐需求保留；加载或提交锁定时不可更改来源，补单来源保持只读。

顶部统计采购明细行数和去重关联需求数；内部仍分别检查采购行数和来源映射条数，每单各不超过 100，新增来源前须核对两项限制，不能用去重 ID 数代替映射数。单行不重复关联同一需求，按需至少一条来源，备料来源为空。超过限制要求另单办理，不截断输入。

无税单价和含税单价均按本行采购单位手填；单价、税率、手填总额和预览结果均按字符串持有。输入及推算规则见[金额契约](../../api/src/modules/procurement/docs/purchase-orders.md#明细采购单位单价)，草稿与正式更正的交互约束见[金额编辑](#35-金额草稿与下单后更正)。

补单由原采购主单入口统一办理，先选超量补单或质量补发，再添加同原单的一条或多条补单明细。一次提交只生成一张补单主单，补因全单一致；两种补因都以原采购行与原到货明细为固定来源，每行选择一次真实到货并填写补购量与说明。供应商从原主单继承，精确版本和需求来源逐原行继承，工单保持原主单归属；原需求关闭不要求恢复。

补单主窗只持有已确认加入的明细及数量、金额、说明、整单备注，候选搜索和分页由一个并列挂载的双栏选择窗承担。目录点击仅定位原采购行，选择右侧具体到货才计为一条临时选择；每原行最多一份到货依据，可跨行、跨页保留，主窗已有行标明已添加并防止重复。临时选择不修改主窗草稿，明确确认后批量加入，取消全部丢弃本次临时变化；不能仅因当前窗口只有一个候选就自动采用。行快捷入口在明确补单类型后直接定位该行的到货选择，外部指定到货仍须读取并由人员确认。更换依据复用同一选择窗并限定当前采购行；确认后保留数量和说明、提示重新核对，取消保持原依据。已有选择或填写内容时切换补单类型须确认清空，取消保留原类型及草稿。

来源候选在服务端按到货单号、供应商批号及真实质量退回单号检索分页；窗口外已选项不能仅因翻页而失效。选择窗读取和创建前重核使用独立请求代际，关闭、失活、换目标拒绝迟到回写，失败保留输入。两种补因的候选资格遵守[采购订单](../../api/src/modules/procurement/docs/purchase-orders.md#补单来源与独立物流)。每条到货明细仅一项，不按处理轮或分配重复；候选及已选摘要直接显示真实到货单号与明细 ID，不选处置分配、不拼接任意单笔退回单号。选择窗常驻显示对应补因的资格提示，空态区分超量补购和质量补发的依据；搜索或定位无结果时明确限定为当前条件，不能据此断言该采购行不存在任何分配。采购来源固定为当前原行，补购量不设累计上限。

两类补因的候选及已选摘要共用[数量展示组件](../src/views/procurement/components/SupplementReceiptQuantities.vue)，统一展示“到货量”“当前可入库”“已入库”“待退回”“已退回”。五项均消费该次到货明细的整体处理数量，退回项包含全部原因；质量补发候选仍须具有质量依据，非质量退回数量只供核对，不授予候选资格。投影口径见[到货查询](../../api/src/modules/procurement/docs/receipt-queries.md#入库候选及正式分配)，不能按候选窗口相加或用单条分配代替。到货量用于核对实物登记，不是补购量；提示人员结合可入库、已入库及退回数量核对补购或约定补发量，不自动计算或按展示数量封顶。零量弱化，非零退回数量遵守[退回数量规范](visual-design.md#2-色彩规范)。

关联补单按状态分别显示“关联明细 N 条，补购量 Q 单位”，条数和补购量均统计同次到货、同补因下的补单明细，不代表整张多物料补单的数量，也不表示已补到货或仍有补购额度。

补单溯源、草稿固定来源及下单核对只展示原采购和原到货主单号、真实明细 ID，不保存或显示分配引用及其当前性。单号直接取采购详情的 `originReceiptNo`，不依赖逐行调用到货接口。到货查看权限只控制进一步查看的入口，不隐藏采购详情中已有的只读来源单号与 ID。关联补单查询与定位按原采购行、原到货明细及补因匹配，处置轮次变化不改变采购来源。

超量补单显示“已有到货补购”，只记录补购量及来源，不绑定仓库分配，不重复到货或质检。其自身不提供新到货或物流记录入口；从其详情继续补单时核对全部行的原采购单一致后转原单办理，不猜测首行来源。质量补单有自己的新到货并独立走完整仓库流程，自己的异常可继续作为补单来源；原货先退后补或先补后退均可。两种补单保存后来源固定，草稿普通编辑只改数量、金额与备注；原采购或原到货选错须取消草稿后重建。后续定稿、复检或实收更正不会要求选择新的分配依据，已有补单能否继续办理由所属命令重新核验。

创建前重读原采购行和所选到货候选，变化或读取失败时保留输入并停止本次提交，不静默替换范围。提交中禁止关闭，未知结果锁定第一次请求及幂等键，刷新和缓存返回不得拼成新请求；关闭、切换对象和关闭标签均保护本地草稿与未确认意图。普通草稿编辑继续保留打开时的版本，保存前核对最新单据，不能覆盖其他人的修改。

### 3.3 需求相关采购

需求总览每行通过“相关采购”打开独立弹窗，打开后读取关联行并提供手动刷新，缓存页返回不自动读取；不预读或展示关联采购单数，不展示采购数量。相关行按采购单、采购行 ID、供应商及状态识别，进一步追溯定位真实采购行，不混入到货、检验或入库进度，也不累计为生产满足量。“发起采购”由弹窗携带 `workOrderId+demandId` 定位采购入口，目标页仍重核需求资格。沿用现有分页查询契约；相关投影可由获准的生产页面消费，采购详情及发起入口按目标页面权限控制导航。

### 3.4 到货身份与数量输入

到货输入使用可收货采购主单的唯一供应商，逐行保留物料和精确版本，不提供行供应商编辑。只到部分行时允许未到行留空；同一采购行追加另一来料批次是新增独立输入，不从原行扣量，不自动维持总数。不同到货明细可共用合资格库存批次，同一明细分次入库也可选择不同目标。

同采购行的本次合计只计入将提交的实收输入；追加的空行属于草稿，不标成已到货批次。参考累计量按采购行展示一次，不能随拆行重复加总。

### 3.5 金额草稿与下单后更正

普通采购与补单均逐行持有两项手填单价、税率和可空手填总额；税率默认 13%，可按该行实际约定修改。补单两项单价和手填总额从空值开始，不复制原报价。采用已有需求来源、更改采购量或重读候选不覆盖已填单价、税率和手填总额；无覆盖时重新预览，有覆盖时保留手填值并展示自动推算参考。清空手填总额表示按无税单价与税率恢复推算，含税单价只保留记录、不参与推算；手填 0 仍是有效覆盖，未填写无税单价时没有自动总额，不能回填 0。

草稿预览调用共享 `calculatePurchaseLineAmount`，服务端结果仍是保存依据；预览不回写单价或冒充手填总额。读取既有草稿时，只有 `totalAmountSource=manual` 才将 `totalAmount` 带回手填输入，calculated 结果保持为派生预览。新公式预览与历史保存总额不一致时，读取和预览不回写持久值，也不能仅因这一差异自动产生待保存的更正行；变更判断继续按打开时的四项输入基线。非法十进制输入保留原文、就地提示并阻止提交，不截断、不用 Number 转换；含税单价同样校验。下单确认与采购详情区分保存结果及当前推算参考，最终落库遵守[金额契约](../../api/src/modules/procurement/docs/purchase-orders.md#明细采购单位单价)。

采购主单“查看/编辑”按真实状态进入草稿编辑或正式单据详情；金额和税率在该上下文核对，外部物流列表不承担金额编辑。草稿沿用完整编辑边界；已下单或已结束单据允许补填或更正两项单价、税率和手填总额，数量、供应商、物料身份及来源只读；已取消单据可查看，不可更正。四项金额输入分别保留，修改报价或税率不反算另一报价、不覆盖手填总额，清空手填总额才按当前输入恢复推算。

正式单据详情保留打开时的主单版本、完整行集合及行版本和计算基础；人员说明原因后，一次提交本单全部已修改行，不能逐行发送造成部分保存。四项金额输入按共享函数规范化后判断变更；单价保留前导零和尾零，其字符串变化即使未改变总额也属于有效更正，数据库税率尾零和派生预览则不产生伪草稿。提交行明确携带两项报价的字符串或 null，不因空报价省略字段；草稿字段仍沿用原可选契约。提交前重新读取核对；主单或行版本、状态、身份及计算基础变化时，保留输入并阻止沿用旧依据，须重新打开核对，不能仅替换版本。后端继续独立校验 update 权限及全部行资格。

更正草稿和写意图由独立 editor 持有，列表刷新、路由定位和缓存返回不替换冻结的办理依据。提交中及结果未知时锁定第一次请求和幂等键，关闭弹窗、切换目标及关闭标签遵守现有草稿与未知结果保护；成功后按返回采购 ID 定向刷新，不推算本地新版本。

## 4. 采购履约与结束

采购量、实收、允许入库和实际库存余额不是同一个数量。展示字段及算法使用采购所有者投影，不能跨物料相加表示完成进度，不能把放行差额标为少收，也不能用生产领用后的库存余额降低历史已入量。

采购明细与行状态操作确认只以累计到货、累计已入、当前待退、实际已退作为物流摘要，分别消费既有 `receivedQuantity`、`inboundQuantity`、`pendingReturnQuantity`、`returnedQuantity`；累计到货按该采购行自身有效实收统计；超量补单不适用物流摘要。当前待退是当前有效安排的未执行量，实际已退是历史执行事实，不能相互替代或用采购量相减推算。检验、放行和仓库办理的细项由到货办理页面承载，摘要不承担执行资格判断。

普通及质量采购行通过“到货记录”查看自身有效到货，每个到货明细一次，数量取当前有效修订；已结束及零累计行仍可查看。超量补单 quantities=null，隐藏物流列与自身到货记录入口，只保留补购量和来源。接口若直接查询超量行仍返回空页及累计量 0。弹窗单号、真实明细 ID 分列，按采购查看权限读取；进一步跳转仓储遵守目标页面权限。

到货记录的搜索与服务端分页只改变明细窗口，顶部累计到货始终取同一次响应的本行全量总计，不从当前页相加；搜索支持到货单号、明细 ID 和供应商批号。空结果与读取失败分开显示，失败不把旧数量或零量当作当前结果。关闭、换行、失活和销毁使旧读取失效；缓存返回保留展示，显式刷新只读取仍打开的目标及当前条件，不预读各采购行记录，也不改动采购状态或未保存业务草稿。

结束采购行只填写原因，不选择结束类型或用数量判断结束资格。进行中行可结束，已结束行可填写原因恢复；草稿行和已取消行没有结束／恢复入口。结束最后一条进行中行时，确认提示整单将显示“已结束”；仍有其他进行中行时提示整单保持“已下单”。已结束整单内恢复一行时，确认提示整单将同时回到“已下单”，其他行保持原状态。整单结束入口逐条列出本次剩余进行中行，填写同一原因批量结束，已结束行保留原记录。

取消入口直接使用详情 `canCancel`，不从行数量推算。草稿可取消，已下单采购须没有属于本单的自身到货记录；已取消整单及物料行不可恢复。新到货仍只允许进行中的采购行，已结束采购的原到货检验、入库、退回仍可有待办。

办理前重读当前单据及行版本、状态、计划量与身份，变化后保留原因并要求关闭后重新选择核对，不只替换版本；物流数量只作对照，不作为结束或恢复的确认资格。整单结束核对完整行集合；列表刷新不替换动作依据，未知结果继续重试原请求。结束、恢复及取消的原因、操作者和时间通过通用操作日志追溯。正式下单后供应商、身份、数量及原采购／原到货固定，两项单价、税率与手填总额按[金额更正](#35-金额草稿与下单后更正)独立办理，其他错误按所有者定义的取消／结束及重建流程处理。

### 采购单分块与状态操作

展开状态由 [usePurchaseOrderExpansion](../src/views/procurement/composables/usePurchaseOrderExpansion.ts) 所有。展示组件只消费已读数据，动作弹窗独立持有确认版本和输入；列表刷新不得替换动作依据。

首次普通进入采购页，在首个成功的列表响应后展开第一条主单，其余保持收起；带明确定位或办理入口时按指定目标处理，不再额外展开列表首条。该默认只应用一次，筛选、翻页、刷新及缓存返回均不重新覆盖人员调整的展开状态；首次读取失败仍可重试，空结果不猜测目标。

采购行以物料名称和完整精确版本识别，不重复展示精确版本已包含的基础编码；数量、来源与办理状态不得因内容收纳而丢失。表格适配遵守[统一视觉规范](visual-design.md#6-表格规范)。

行展开区仅承载真实需求来源及补单溯源，不重复物流摘要或到货方式。独立备料等没有需求来源的行不显示空来源表；真实生产来源保持可查。没有任何来源或补单溯源内容时不提供展开入口。

明细只在需要时读取，状态范围限当前页及一个外部定位单据，避免浏览历史积累无界缓存。展开读取按 ID 去重；收起、分页移除、失活和卸载取消旧读取并拒绝迟到回写，再次展开重新核验。来源使用已读详情，不额外逐行取数。

返回页面或手动刷新只重读已展开单据；写后复用最新详情并刷新列表，不重读无关单据。失败保留旧展示但禁用办理，提供单据级重试；操作前资格重读不能为减少请求而省略。外部定位单据不在当前页时作为独立定位项展示，不能把它算进当前筛选的分页总数。

## 5. 到货、实收更正与退回

累计量消费收货采购详情的 items[].quantities，不逐行请求；新到货只能选择 new_arrival 行。每条采购行统计自身到货，超量补购不分走数量，质量补单自己的到货不回计最初原单。累计量不含未提交输入，同采购行拆成多个批次不得重复累计。

本次到货当前有效修订的总量在只读摘要中显示为“到货量”，包含此前已入库、已退回的数量，不是采购计划量或当前库存余额；作废来源仅在历史核对中显示“作废前到货量”，不能将有效投影的零量当作原登记量。补单依据的数量对照遵守[采购行与独立补单](#32-采购行与独立补单)。到货办理页面继续展示“尚未入库或退回”，表示当前尚未实际入库或退回的数量，不能解释为待检量或已具备执行资格的数量。已执行数量显示为“已入库”“已退回”。库管定稿输入显示为“到货总量”，正式清单历史显示为“当时剩余数量”，处理轮历史继续标明轮开始时的剩余快照，三者不能混称；定稿交互见[来料核对](incoming-inspection-adoption.md#库管核对定稿)。

打开编辑器、显式刷新及提交前核对更新只读数量，保留实收、批号和说明。采购版本或资格变化要求重新选择核对；仅累计量变化时，若在提交前发现，也先提示核对并停止本次命令，再次确认才继续。计划及累计量只供对照，不按计划余量为实收输入设置 max。

新到货与同批计数更正使用不同事实身份，不能通过更正改变供应商、物料、批次或旧物流。更正输入“到货总量”，已处置量只读；旧剩余资格失效、零剩余办结及拒收后重新办理见[整批规则](../../api/src/modules/procurement/docs/receipt-acceptance.md)。这些后果需在确认时说明，不让用户把更正当补到货或登记损耗。

超量补单的每条原采购行选择一条真实到货，使用 `excess-receipt-candidates` 的独立分页权限，不遍历全部到货。质量补发的每条原采购行选择一条有质量待退或真实质量已退依据的到货明细，候选由采购单查看权限独立读取，不依赖到货页查看权限。定位到采购后重新核验每条原行及依据归属；[到货处理数量](#32-采购行与独立补单)仅供核对，创建补单草稿不恢复实物或授予入库资格。

展示上区分“授权入库／安排退回”与“已实际入库／已实际退回”。历史分配保存去向并不表示现在仍有执行资格；人工拒收和质检不合格均不等于交接完成。退回按具体有效待退分配一次确认全部余量，不提供分次退回输入。具体交互见[来料整批处理](incoming-inspection-adoption.md)。

到货作废只从整单入口办理，不提供逐行作废。分页目录和未加载内容不能作为整单范围依据，进入作废确认必须读取整单主单版本、完整明细及服务端 `voiding` 预览，逐条核对行版本、当前轮 ID／版本、状态和身份；提交前重新读取，主单版本、作废摘要、行集合或资格变化就保留原因并阻止沿用旧依据，不能只替换版本。请求携带打开时的主单 `version` 和完整行／轮次版本集合；成功结果须对应原到货单，版本须为原主单版本加一。作废摘要只消费原因、操作者和时间，不依赖独立作废记录 ID。未知结果冻结第一次请求及重试标识，刷新、切换明细或返回缓存页不能换成新意图。

确认界面说明：所有明细均须没有真实入库、真实退回，且没有未取消的关联补单；草稿、已下单和已结束补单均阻断，已取消补单历史不阻断，已检验或已定稿本身不阻断。打开作废弹窗后读取专用整单预览，确认资格使用服务端结果，不根据明细目录、当前页或前端数量推断。作废后整单和各行展示作废状态、原因、操作者及时间；登记、检验和正式清单保留追溯，未执行授权退出，采购状态保持不变。有效数量为零不表示原登记数量为零，作废前到货量消费服务端精确读取当前实收修订的 `registeredQuantity`，完整依据通过实收历史查看。作废详情不再展示更正、拒收、定稿、入库、退回或补单办理入口，历史入口仍保留。

采购到货工作列表按“采购主单分页 → 本单到货分页 → 单张到货完整轻量行”组织，两层默认各 10 条，total 分别表示采购单数和所属到货数；单张到货明确展开后才读取完整物料，最多 100 行，不增加第三层分页或逐行请求完整详情。父头部到货数和待定稿明细数使用服务端完整摘要，不能从当前子页或已加载行相加。

首次成功读取父页且没有明确定位时，只默认展开首张采购及其首张到货一次。筛选、翻页、刷新及之后展开采购不自动展开其他到货；“展开当前页采购单”只处理已取得的父页和各自当前到货目录，不递归读取全部子页或物料。

每层分别持有分页、展开、loading、错误和请求代际；收起采购主单时清除其下到货展开及读取状态，翻页、目标变化及失活使旧读取失效。子层缓存仅保留当前分页窗口与必要的精确定位对象，不随浏览历史累积。处置、定稿、作废和历史弹窗在页面级独立持有上下文，收起或翻页不销毁未提交草稿，也不替换其冻结的办理依据。

显式刷新及命令成功后重读父页、仍展开采购的当前到货页及仍展开到货的完整轻量行；页外定位仅在仍展开时定点刷新。缓存页返回保留展示与草稿，不自动发起整树读取。列表更新不替换详情、定稿及其他 editor 已冻结的来源和版本依据。

关键词与待定稿等条件只筛选采购父页，命中后显示真实父单的完整到货范围及单张到货完整物料，不在子层再次裁剪。筛选含义与同源要求由[分层查询](../../api/src/modules/procurement/docs/receipt-queries.md#采购到货分层查询)维护，前端不以本页过滤替代服务端检索。精确定位先解析真实来源，再读取必要父头及目标到货；页外对象独立显示，不扫描全部分页、不改变当前条件或 total。

[PurchaseReceiptOrderGroup](../src/views/procurement/components/PurchaseReceiptOrderGroup.vue) 只展示采购块及所属到货目录，单张到货通过 [ReceiptWorklistReceiptGroup](../src/views/procurement/components/ReceiptWorklistReceiptGroup.vue) 复用 ID／物料基础列、行高亮和插槽；供应商在采购／到货身份摘要中显示，供应商批号仍属于每条到货明细。采购与来料宿主分别拥有查询、分页、刷新和动作，展示组件不请求数据或决定资格。来料的分组草稿、定位和检查工作台见[来料交互](incoming-inspection-adoption.md#分组读取关联草稿与定位)，两页面不共享可变列表、候选或 editor 缓存。

到货详情按实际明细身份选择办理对象，本单物料检索只改变明细索引，不丢弃当前选择或子编辑器草稿。列表的到货单号与物料名称为静态身份信息，组头“查看到货单”打开整单详情；行内保留当前流程快捷入口、“历史”和“详情”，后两者准确选中该明细。列表中的办理入口定位到真实明细；进入更正、拒收、定稿等编辑器前重读详情并核对资格，不用列表快照直接提交。退回须选择具体当前有效分配，不因快捷入口跳过范围核对。当前可入与待退并存时，两种办理方向都须可见。

整单读取只取得主单和完整明细目录；当前行独立按需读取，切行清除旧行办理依据，不预读其他行详情。主单和当前行分别持有请求代际，关闭、换单、切行和失活拒绝迟到回写；刷新及命令成功后只重读主单与仍选中的行，读取失败不允许用旧内容继续办理。定稿与作废弹窗分别持有独立上下文，不能以工作台刷新替换其已冻结的草稿依据。端点及字段边界统一见[到货查询](../../api/src/modules/procurement/docs/receipt-queries.md#当前轮次与历史)。

当前阶段、下一步与原办理入口集中展示；“本轮处理流程”只说明当前轮的路径，不从历史放行或已定稿推断全流程完成。正常流程展示登记、检验、仓库确认及入库／退回；入库与退回可按分配并行，人工拒收直接安排退回，复检或更正回到当前轮核对，累计真实入退仍保留。仅已知剩余为零时标记处理完成，未知数量显示待核对。数量强调遵守[视觉规范](visual-design.md#2-色彩规范)；阻断、拒收和异常依据采用对应语义提示，指引不改变按钮资格或命令校验。

数量摘要明确区分实物累计与当前剩余去向；累计已入与当前可入之和不能标成剩余授权。当前办理量、差异和阻断保持可见，关键数字连同单位突出，零量可弱化但不能将未知值当零。短提示与历史入口直接显示，历史记录及其总数仅在打开对应分页时读取；低频操作收纳不改变资格或丢失入口。真实处置分配继续区分授权与执行，库存批次在入库追溯中展示。当前分配的说明不设常驻空列；非空说明按真实分配 ID 在表下直接显示完整内容，人工拒收原因不得因精简布局丢失。分配 ID 独立标识授权，来源采购在上下文保留，分配历史继续提供原始说明；分配说明与正式清单的核对／更正说明是不同字段，不能互相替代。

到货明细历史同时用于数据库排查，已有处理轮、检验、实收修订、正式清单、分配及库存事实 ID 必须保留明确标签与完整值，不因精简布局删除或藏入悬停提示。正式清单与其分配明细直接展示；检验与复核每页首条默认展开，仍可主动收起。关联标识可在同一单元格内分行，长值自然换行；弹窗随内容区拓宽，继续遵守路由弹窗挂载及正文溢出规则，不截断多条历史或长凭据。到货历史只供核对和追溯，可普通定位来源采购单，不提供补单等业务快捷入口。历史授权去向以文字配合蓝色入库、橙色退回及灰色待处理标签区分，只表达当时授权，不表示已执行或当前仍有效；关键数量保持清晰，异常依据单独提示，不以缩小字号隐藏追溯值。

## 6. 来料检验与复检

来料主页面按质检主单及完整到货分层读取；逐物料检查仍以真实到货行为单位。待检行的 `currentCase=null`，显式发起后才有 Quality case。当前摘要、检验工作台和历史精确定位的完整约束见[来料交互](incoming-inspection-adoption.md#整批状态与入口)。

检验覆盖同次到货的整批剩余实物，抽检样本不形成独立处置范围。数量输入、方法切换、差异／异常提示及库管定稿引用见[来料交互](incoming-inspection-adoption.md)，公式、超建议责任和同一检验重复引用的扣减规则见[整批定稿](../../api/src/modules/procurement/docs/receipt-acceptance.md)。前端不能把数量说明当解除质量阻断，也不能用样本不合格数直接填写实际报废／退回量。

## 7. 有效放行与实际入库

`usePurchaseInboundReleases` 独占候选窗口、跨页选择和数量草稿；`usePurchaseInbounds` 只读历史。一次外购物料确认可含不同供应商、采购及到货的有效分配，通过 [procurement-inbounds API](../src/api/procurement-inbounds.ts) 一次原子提交并生成一张入库单，不能循环单条 HTTP 冒充整单成功，也不能由前端自动拆成多供应商写入。业务选择见 [ADR-0018](../../../docs/adr/0018-purchase-inbound-multiple-suppliers.md)。

待入库列表按到货单组织当前页候选并默认展开，每张到货仅一张明细表和一组选择／核对入口，块内保持服务端返回的到货明细 ID／分配 ID 顺序，不按到货行号二次排序；供应商及其批号逐行显示，不按供应商二级分区，避免误示为独立办理边界。分页仍针对可入明细，块内选择只覆盖本页命中项，不能声称已选择整张到货单。块内核对保留已有数量和目标草稿；已选其他到货时入口明确说明加入已选后共同核对，不能静默扩大或清空选择。确认弹窗按实际已选到货分块，每行显示自身供应商；跨到货或多供应商确认用一行提示涉及的到货单数和供应商数。已入库记录按入库主单分块，头部供应商集合由明细汇聚，每行保留确认时供应商名称及真实来源。同物料不同来源仍各保留明细，分组不改变逐分配额度或目标批次选择。

提交前通过 allocationIds 批量重读全部已选分配；当前轮、依据或真实余量变化就保留输入并停止。明确重核可更新同一 allocation 的余量，但不丢弃已填数量；不能静默换分配或仅刷新版本后提交。正式分配行不拆分；本次执行可将同一分配拆为多条目标明细。

本次量默认当前有效余量，允许调小，按所属分配的服务端资格和额度校验。已结束采购仍可能有有效分配；有效超建议授权不在入库时再按质检建议拦截，避免前端否定已保存的责任依据。库存余额和最新一条检验都不能代替跨历次实际入库总量。

采购、成品及其他入库统一提供“新建批次”和“已有批次”。新建默认逐行独立，批次列直接提供共用本次新批次及恢复独立新建的操作，不自动合并同物料或成品的行。可共用目标仅来自当前确认操作（其他入库为当前草稿单）：物料必须是同一基础物料、精确版本及单位，成品必须是同一成品及单位，两种类型不能共批。界面用当前明细位置与共用行数辨认临时组，不显示 `clientKey` 或将临时组名当作正式批号；组内使用同一 `clientKey`，批号由 Inventory 确认时生成。移除一行或退出该组不改变其余成员的目标；唯一成员按独立新建显示。

三个入库入口共用 [InboundBatchModeSwitch](../src/views/warehouse/components/InboundBatchModeSwitch.vue) 和 [InboundNewBatchSelect](../src/views/warehouse/components/InboundNewBatchSelect.vue) 展示批次方式并传递选择事件；各场景分别持有已有批次候选、对象带出及草稿变更规则。

共批只改变库存目标，不合并来源、授权或质检。采购仍可跨供应商、采购及到货确认，成品一次仍限同一任务，计划内外来源分别保留；同一授权拆入多个目标时按授权合计核对余量。不同来源也可明确选择同一已有合资格批次，跨次操作只能选择已生成的批次，不提供事后合并库存批次。界面不收取手填批号；历史按执行明细显示实际目标，不从到货行推断。所有事实链引用采用当时真实依据，不用当前值替换历史。

已入库记录按服务端分页的入库单分块，每页仅首单默认展开，其余可按需展开；组头数量仅表示该入库单，直接使用列表返回的 `details`，不为每单追加详情请求。外购物料的确认人、时间、备注与逐行追溯直接在块内展示，不设置重复详情弹窗；成品详情继续承载列表未提供的当时批准产出依据。外购 `inboundId` 定位优先展开当前页命中项，不在当前页时只读取该目标并独立展示，不计入筛选分页总数；读取失败允许重试，取消定位使旧读取失效。

外购物料待入库与入库历史的采购、到货来源遵守[统一 ID 展示约定](#21-详情定位)，同时保留来源单号、真实行 ID 及采用的检验记录 ID。检验时间通过来源标识的悬停提示和检验详情查看，不逐行常驻。来源采购沿实际入库分配所属的到货明细解析，固定为该到货自身采购行。标识链接分别定位到货明细、采购行及采用检验对应的 case；后续复检或更正不得改变历史链接对象。再次进入同一来源仍可定位。缺少目标页面权限时保留来源文字；来源投影缺失时明确说明，不在前端逐行请求详情补齐或推算关系。

拆分须明确填写分出数量，并同步扣减原行，保持本次合计不变；移除某授权选择会移除其全部目标，移除一条目标仅影响该行。两类入库草稿的每条目标使用稳定本地 `rowKey` 绑定表格、字段错误及拆分／移除动作；它只属于 editor 状态，不进入确认请求或幂等内容。新建批次的 `target.clientKey` 属于目标批次契约，与本地行标识分别持有。数量输入保留空值、越界及非法原文，在字段旁报错并阻止确认，不自动截断或静默回填。逐授权在对应数量输入旁核对有效余量与入库后余量；单目标直接使用输入数量，多目标才补充跨目标合计，并在该授权的首条目标旁显示一次。合计按真实授权身份关联，不依赖目标行是否相邻，也不把不同物料的数量汇总成进度。确认弹窗不另列重复的目标预览或授权／目标数量统计，来源与目标批次直接在编辑明细核对。已有批次显示完整批号、身份与可用资格。

结果未知冻结原 body/key；失败后重读有效资格供明确核对，不自动取新范围或新键重入。缓存页返回保留原上下文；显式刷新及提交前核验不得替换原命令。

## 8. 状态与 HTTP 消费约定

端点与字段以 API wrapper 和[共享契约](../../../packages/contracts/README.md)为准，状态字典由[共享常量](../../../packages/constants/README.md)维护。消费时保留以下边界：

- 采购状态、整批轮次、Quality 办理、处置分配及实际执行分别表达事实。`open` 表示进行中，不能翻译成尚未到货；`superseded` 历史不重新累计资格，人工结束不能翻译成质检达标。
- 来料页面归 Quality，但命令由 Procurement 锁定到货后编排 Quality 公开能力；前端不能分别调用两模块模拟同一事务，也不能传“已合格”布尔值代替依据。
- 写入使用精确 DTO，列表及批量上限按公共契约；超过限制要求另单，不偷偷截断。API wrapper 只透传用例持有的幂等键。
- 采购创建／修改、补单、下单、取消、结束／恢复、金额批量更正及到货处置等已登记命令使用 Idempotency-Key；供应商维护和只读解析不启用。不能用 POST 方法判定幂等要求。签名包括路径参数、完整规范化 body 及版本，未知结果保留第一次实际发送的内容。
- 整批操作携带行版本与 roundId/roundVersion；实际执行额外引用 allocation、实收修订和 QC。人工拒收实际退回可以没有普通 QC/acceptance，但必须有真实当前拒收分配。
- 外购入库历史通过 `/production/purchase-inbounds` 只读查询；实际入库由采购放行确认入口办理，不提供自由选料直入或待确认外购单。

### 8.1 权限消费

采购到货归仓储目录，其整页和跨页入口使用仓储到货查看权限；保留 `/procurement/receipts` 路径不改变权限归属。供应商 options 可由获准的供应商、采购单或采购到货页面读取，质检页不单独请求该候选。采购物料／版本及需求候选只需要采购页查看权限，不附加主数据管理权限。

相关采购投影允许契约登记的采购／生产需求宿主读取，但跳转采购仍核验目标权限。Quality 读取只需其查看权限；共用入库页面、外购与成品入库候选及历史读取统一使用 `warehouse:inbound:view`，不附加质量或生产任务页面权限。入库确认等写操作继续独立鉴权，查看权限不授予写入能力。检验权限不授予更正实收、退回或入库能力，也不要求各角色必须由不同自然人承担；页面可见性不能替代后端鉴权。
