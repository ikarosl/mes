# 采购与入库的前端约束

本文维护代码和页面外观不容易解释的输入、候选、并发及跨页约束。业务规则的主要依据为 [采购订单](../../api/src/modules/procurement/docs/purchase-orders.md)、[到货与更正](../../api/src/modules/procurement/docs/receipts.md)、[整批定稿与执行授权](../../api/src/modules/procurement/docs/receipt-acceptance.md)；跨模块背景见[业务设计](../../../docs/procurement-inbound-design.md)。本文不另行定义数量公式、状态机或业务资格。

[来料交互](incoming-inspection-adoption.md)维护检验、定稿与拒收的专用约束；[管理端架构](architecture.md)、[路由与标签页](route-dialogs-and-tabs.md)、[HTTP 错误处理](http-error-handling.md)维护通用行为。未完成事项和验收状态以[路线图](../../../docs/roadmap.md)为准。

## 1. 当前交互边界

采购来源、供应商身份、检验事实和执行资格均来自所属模块。前端不得用展示摘要推断资格，尤其注意：

- 采购供应商属于行，主单的 `suppliers` 只是去重展示集合；生产的 supplierHint 仅供采购参考，不能自动代选供应商。
- 采购可选择仍符合其他资格的停用精确版本，生产选版则有自己的启用要求。使用采购专用候选并显示状态，不能复用生产过滤条件。
- 到货前不指定内部库存批次；首次实际入库也可选择已有合资格批次。到货不持有单一内部库存批次；历史批次集合与逐笔目标来自真实入库明细。
- 外购输入保存在本地草稿；成品从有效授权直接确认入库，两个来源共用目标批次选择交互。

## 2. 页面与路由

路由、菜单和权限映射直接见 [router](../src/router/index.ts)、[AdminLayout](../src/views/AdminLayout.vue)；不在本文另列一套页面清单。页面只按查看权限控制整页，命令权限由后端逐接口校验，不要求页面内按钮做权限隐藏。

### 2.1 详情定位

- 采购定位使用 `purchaseOrderId`，定位具体采购行再附 `purchaseOrderLineId`；从需求发起草稿使用 `workOrderId+demandId`。从到货详情的办理入口转采购补单时，附 `supplementLineId+supplementReason+receiptLineId`，质量补发再附 `allocationId`；采购页须重新读取原单及具体依据后定位统一补单弹窗，不信任路由参数本身。退回历史只用 `purchaseOrderId+purchaseOrderLineId` 普通定位来源采购，不携带补单参数自动打开办理；来源列展示采购单号、采购固定行号及采购行 ID，不以到货行号冒充采购行号，无采购查看权限时仍保留这些只读标识。采购页滚动到目标行，并以固定行号、采购行 ID 和“当前定位”标记供对照。参数必须经服务端解析资格与归属，单独 demandId 不自动推定工单。
- 到货定位使用 `receiptId`，可附 `receiptLineId`；来料检验使用 `receiptLineId`。入库继续用 `inboundId`，外购显式附 `sourceType=purchased`；没有 sourceType 的既有定位仍按成品处理，再读取详情核实真实类型。
- 外购入库可由 `receiptLineId` 查询当前有效分配，不能把来源页携带的旧数量当授权。采购已关闭不等于原到货不可继续办理。
- 更换定位目标先确认放弃未保存输入；取消保留原草稿和原定位。提交中或结果未知时阻止换单。离开页面仅使旧读取失效，不销毁缓存草稿。
- 生产需求总览由 [MaterialDemandOverviewDialog](../src/views/production/components/MaterialDemandOverviewDialog.vue)承担，没有独立 `production-material-demands` 路由；同名 HTTP 资源不能当页面链接。

## 3. 供应商及采购选择

### 3.1 候选和跨页选择

供应商目录及名称约束见[供应商设计](../../api/src/modules/procurement/docs/suppliers.md)。采购逐行明确选择已有供应商 ID，不把自由文本当关系键、不隐式创建供应商或建立物料绑定；不存在时先维护目录。供应商编辑保留打开时的版本，重复名称失败保留输入；资料变化后阻止提交，须关闭并从最新列表重新选择，不能更新版本后覆盖他人修改。

按需采购先选择一个工单。候选由专用工单接口及需求分页接口提供，不能从第一页需求拼凑工单。需求分页按叶子计数，任务分组只是当前页投影；跨页选择用独立 demandId 集合保存，不因翻页、刷新或当前窗口缺少某项而判为失效，不提供全选或隐式全量读取。

选中 ID 解析逐项返回当前资格及原因；失败保留草稿并禁止下单，不能默认合格或清空来源。在审更正等阻断由服务端判定。新采购候选过滤不能用于屏蔽已有采购的历史来源；草稿保存及正式下单分别重核资格。

切换工单会影响所有采购编辑行，即使当前没有勾选需求也须确认清空；取消切换保留原状态。收到外部定位参数执行同一守卫，不能静默带入其他工单的需求。独立备料不关联或伪造工单、任务、需求。

### 3.2 采购行与独立补单

选择后以物料及精确版本组织来源，但采购量独立填写，不自动当成需求满足量或以需求剩余量封顶。同物料／版本向不同供应商采购必须分别成行；同供应商重复行须人员明确归并并确认总量，不能静默相加。拆供应商行时新行须重新明确来源、供应商和数量，supplierHint 逐需求保留。

界面分别检查采购行数和来源映射条数，每单各不超过 100。相同 demandId 出现在不同供应商行时每处都占映射数，不能用去重 ID 数代替；单行不重复关联同一需求，按需至少一条来源，备料来源为空。超过限制要求另单办理，不截断输入。

补单由原采购主单入口统一办理，先选超量补单或质量补发，再从同一原单选择一条或多条原采购行；行快捷入口预选该行，仍可追加同原单其他行。一次提交只生成一张补单主单，补因全单一致，创建后类型与来源冻结；每行须独立选择一份具体到货或质量分配依据并填写补购量与说明。供应商、精确版本、工单和需求来源逐原行继承，不由主单供应商集合代选；原需求关闭不要求恢复。来源候选在服务端按到货单号、供应商批号及质量退回单号检索和分页，已选依据跨页保留，提交前逐条重核。质量补发同时可引用有效待退分配和真实已退历史，展示到货固定行号、待退／已退数量、退回单号、关联补单，以及到货登记来源和正式分配采购归属；两种采购归属不得混称。关联补单号按具体分配独立分页查看。人工拒收不能作为质量补发依据。补购量不按原需求／退回量设置累计上限，相关补单不能被解释成仍有可采购额度。

超量补单承接原到货，正式下单后由库管关联原到货清单，无需重复登记到货或质检。承接超量补单自身不产生新到货，不作为后续补单的办理原单；从其详情继续补单时，须核对全部行冻结的原采购单均相同且可定位，头部入口直达该原单办理。旧定位或直接打开统一弹窗时显示当前承接补单号、原采购单号及前往入口；来源缺失或多原单时提示核对，不猜测首行来源或展示空的可选行。质量补发产生新到货，须重新质检、形成清单并办理入库；其真实新到货仍可成为后续补单依据。原货实际退回独立办理，支持先补后退或先退后补。两类流程在补单弹窗内用常驻 `InlineHint` 随类型提示，不以创建草稿冒充实物处理。草稿编辑和正式下单均按新主单的全部行核对；编辑时逐行展示冻结依据，不把首行依据复用于其余行。

### 3.3 需求相关采购

相关采购按单 distinct 计数，关联行展示自己的采购量而非“本需求已采购量”，不累计为生产满足量。使用批量投影而非逐需求请求详情；相关行不混入到货、检验或入库进度，进一步追溯进入真实采购。相关投影可由获准的生产页面消费，跳转采购详情仍独立核验采购权限。

### 3.4 到货身份与数量输入

到货输入按可收货采购行保留供应商、物料和精确版本，不能先合并物料再手工拆供应商。只到部分行时允许未到行留空；同一采购行追加另一来料批次是新增独立输入，不从原行扣量，不自动维持总数。不同到货明细可共用合资格库存批次，同一明细分次入库也可选择不同目标。

同采购行的本次合计只计入将提交的实收输入；追加的空行属于草稿，不标成已到货批次。参考累计量按采购行展示一次，不能随拆行重复加总。

## 4. 采购履约与关闭

采购量、实收、允许入库和实际库存余额不是同一个数量。展示字段及算法使用采购所有者投影，不能跨物料相加表示完成进度，不能把放行差额标为少收，也不能用生产领用后的库存余额降低历史已入量。

关闭使用 `allowedCloseReasons`：优先采用当前成立的达标／质量退回处置完成依据，否则人工结束须留原因；无到货取消保持独立。关闭前重读当前行、数量和资格，变化后要求重新核对，不只替换版本。达标不自动关行，主单完成由后端按行汇总，终态没有恢复或人工完成整单命令。

采购终态只结束新增采购履约；原到货的检验、入库、退回仍可有待办。历史关闭证据与当前进度分开，后续更正引发差异时不改写旧依据。正式下单后供应商、身份、数量和来源冻结，错误按所有者定义的取消／结束及重建流程处理。

### 采购单分块与状态操作

展开状态由 [usePurchaseOrderExpansion](../src/views/procurement/composables/usePurchaseOrderExpansion.ts) 所有。展示组件只消费已读数据，动作弹窗独立持有确认版本和输入；列表刷新不得替换动作依据。

采购行以物料名称和完整精确版本合并识别，不重复展示精确版本已包含的基础编码。状态与行操作保持相邻可见，窄容器通过明细表自身横向滚动容纳其余字段，不用固定操作列遮住状态。采购行表仅在横向溢出时于顶部提供与底部双向同步的滚动条，展开依据后仍可从表头附近横移；尺寸变化及缓存页返回时重新核对可滚动范围，不联动外层主表或内嵌来源表，也不改变普通纵向滚动。单据展开区及行内履约、关闭依据均按所在表格的可视容器排版，不跟随所有列的总宽度撑大；长版本和依据允许换行，数量及来源不能仅因布局收紧被截断。

明细只在需要时读取，状态范围限当前页及一个外部定位单据，避免浏览历史积累无界缓存。展开读取按 ID 去重；收起、分页移除、失活和卸载取消旧读取并拒绝迟到回写，再次展开重新核验。来源和关闭证据使用已读详情，不额外逐行取数。

返回页面或手动刷新只重读已展开单据；写后复用最新详情并刷新列表，不重读无关单据。失败保留旧展示但禁用办理，提供单据级重试；操作前资格重读不能为减少请求而省略。外部定位单据不在当前页时作为独立定位项展示，不能把它算进当前筛选的分页总数。

## 5. 到货、实收更正与退回

累计量消费收货采购详情的 `items[].quantities`，不逐行请求。实收归属、历史已入及已退按所有者规则计算；承接补单的份额不能重复算给原单。累计量不含未提交输入，同一采购行追加多个批次也不能重复汇总其累计值。

打开、缓存页恢复、显式刷新及提交前核对更新只读数量，保留实收、批号和说明。采购版本或资格变化要求重新选择核对；仅累计量变化时，若在提交前发现，也先提示核对并停止本次命令，再次确认才继续。计划及累计量只供对照，不按计划余量为实收输入设置 max。

新到货与同批计数更正使用不同事实身份，不能通过更正改变供应商、物料、批次或旧物流。更正输入本次到货核实总量，已处置量只读；旧剩余资格失效、零剩余办结及拒收后重新办理见[整批规则](../../api/src/modules/procurement/docs/receipt-acceptance.md)。这些后果需在确认时说明，不让用户把更正当补到货或登记损耗。

超量补单的每条原采购行选择一条真实到货，使用 `excess-receipt-candidates` 的独立分页权限，不遍历全部到货。质量补发的每条原采购行选择一条质量待退或已退分配，候选由采购单查看权限独立读取，不依赖到货页查看权限。定位到采购后重新核验每条原行及依据归属；未处置量、待退量和已退量仅供核对，创建补单草稿不恢复实物或授予入库资格。

展示上区分“授权入库／安排退回”与“已实际入库／已实际退回”。历史分配保存去向并不表示现在仍有执行资格；人工拒收和质检不合格均不等于交接完成。退回按具体有效待退分配一次确认全部余量，不提供分次退回输入。具体交互见[来料整批处理](incoming-inspection-adoption.md)。

采购到货工作列表按到货明细服务端分页，按到货单组织当前页返回的明细并默认显示；组头只代表当前页，不表示已读齐整单。关键词在服务端检索到货单、采购单、供应商及物料名称、编码和精确版本，不以当前页过滤冒充全库检索，不为每条摘要追加详情请求。待定稿筛选作用于明细，不能将没有待定稿明细解释为整单已办完。

到货详情按实际明细身份选择办理对象，本单物料检索只改变明细索引，不丢弃当前选择或子编辑器草稿。列表的到货单号与物料名称为静态身份信息，组头“查看到货单”打开整单详情；行内保留当前流程快捷入口、“历史”和“详情”，使用统一文字按钮，后两者准确选中该明细，不再用中间菜单重复列出详情内已有操作。列表中的办理入口定位到真实明细；进入更正、拒收、定稿等编辑器前重读详情并核对资格，不用列表快照直接提交。退回须选择具体当前有效分配，不因快捷入口跳过范围核对。当前可入与待退并存时，两种办理方向都须可见。

数量摘要明确区分实物累计与当前剩余去向；累计已入与当前可入之和不能标成剩余授权。当前办理量、差异和阻断保持可见，关键数字连同单位突出，零量可弱化但不能将未知值当零。短提示与历史入口直接显示，详细历史按需读取；低频操作收纳不改变资格或丢失入口。真实处置分配继续区分授权与执行，库存批次在入库追溯中展示。当前分配的说明不设常驻空列；非空说明按真实分配 ID 在表下直接显示完整内容，人工拒收原因不得因精简布局丢失。分配 ID 与采购归属同格保留，分配历史继续提供原始说明；分配说明与正式清单的核对／更正说明是不同字段，不能互相替代。

到货明细历史同时用于数据库排查，已有处理轮、检验、实收修订、正式清单、分配及库存事实 ID 必须保留明确标签与完整值，不因精简布局删除或藏入悬停提示。正式清单与其分配明细直接展示；检验与复核每页首条默认展开，仍可主动收起。关联标识可在同一单元格内分行，长值自然换行；弹窗随内容区拓宽，继续遵守路由弹窗挂载及正文溢出规则，不截断多条历史或长凭据。到货历史只供核对和追溯，可普通定位来源采购单，不提供补单等业务快捷入口。历史授权去向以文字配合蓝色入库、橙色退回及灰色待处理标签区分，只表达当时授权，不表示已执行或当前仍有效；关键数量保持清晰，异常依据单独提示，不以缩小字号隐藏追溯值。

## 6. 来料检验与复检

待检来源使用真实 `roundId`、`taskKind=uninspected` 和 `case=null`，显式发起后才有 Quality case。仅打开表单不暂停实物；已发起后关闭表单也不撤销办理，必须让用户明确这一提交边界。

检验覆盖同次到货的整批剩余实物，抽检样本不形成独立处置范围。数量输入、方法切换、差异／异常提示及库管定稿引用见[来料交互](incoming-inspection-adoption.md)，公式、超建议责任和同一检验重复引用的扣减规则见[整批定稿](../../api/src/modules/procurement/docs/receipt-acceptance.md)。前端不能把数量说明当解除质量阻断，也不能用样本不合格数直接填写实际报废／退回量。

## 7. 有效放行与实际入库

`usePurchaseInboundReleases` 独占候选窗口、跨页选择和数量草稿；`usePurchaseInbounds` 只读历史。一次外购物料确认可含不同供应商、采购及到货的有效分配，通过 [procurement-inbounds API](../src/api/procurement-inbounds.ts) 一次原子提交并生成一张入库单，不能循环单条 HTTP 冒充整单成功，也不能由前端自动拆成多供应商写入。业务选择见 [ADR-0018](../../../docs/adr/0018-purchase-inbound-multiple-suppliers.md)。

待入库列表按到货单组织当前页候选并默认展开，每张到货仅一张明细表和一组选择／核对入口，块内按真实到货行号排序；供应商及其批号逐行显示，不再按供应商二级分区，避免误示为独立办理边界。分页仍针对可入明细，块内选择只覆盖本页命中项，不能声称已选择整张到货单。块内核对保留已有数量和目标草稿；已选其他到货时入口明确说明加入已选后共同核对，不能静默扩大或清空选择。确认弹窗按实际已选到货分块，每行显示自身供应商；跨到货或多供应商确认用一行提示涉及的到货单数和供应商数。已入库记录按入库主单分块，头部供应商集合由明细汇聚，每行保留确认时供应商名称及真实来源。同物料不同来源仍各保留明细，分组不改变逐分配额度或目标批次选择。

提交前通过 allocationIds 批量重读全部已选分配；当前轮、依据或真实余量变化就保留输入并停止。明确重核可更新同一 allocation 的余量，但不丢弃已填数量；不能静默换分配或仅刷新版本后提交。正式分配行不拆分；本次执行可将同一分配拆为多条目标明细。

本次量默认当前有效余量，允许调小，按所属分配的服务端资格和额度校验。已关闭采购仍可能有有效分配；有效超建议授权不在入库时再按质检建议拦截，避免前端否定已保存的责任依据。库存余额和最新一条检验都不能代替跨历次实际入库总量。

一期两类入库的每条目标明细只提供“新建批次”和“已有批次”：新建时每条目标使用独立 `clientKey`，批号由 Inventory 自动生成，界面不收取手填批号，也不提供复用本次新批次。不同来源可以明确选择同一已有合资格批次；需要归入刚创建的批次时，先完成该笔入库，再在后续操作中选择已有批次。同一授权拆入多个目标时按授权合计核对余量。历史按执行明细显示实际目标，不从到货行推断。所有事实链引用采用当时真实依据，不用当前值替换历史。

已入库记录按服务端分页的入库单分块，每页仅首单默认展开，其余可按需展开；组头数量仅表示该入库单，直接使用列表返回的 `details`，不为每单追加详情请求。外购物料的确认人、时间、备注与逐行追溯直接在块内展示，不再设置重复详情弹窗；成品详情继续承载列表未提供的当时批准产出依据。外购 `inboundId` 定位优先展开当前页命中项，不在当前页时只读取该目标并独立展示，不计入筛选分页总数；读取失败允许重试，取消定位使旧读取失效。

外购物料待入库与入库历史直接展示服务端提供的到货单号与固定行号、实际归属采购单，以及采用的检验记录 ID；历史每行在“采购归属与采用检验”中保留固定采购行号，补单承接时同时提示到货登记原采购单。检验时间通过来源标识的悬停提示和检验详情查看，不逐行常驻。采购归属沿实际入库所消费的正式分配解析，不能用到货登记原采购单替代。标识链接分别定位到货明细、采购行及采用检验对应的 case；后续复检或更正不得改变历史链接对象。到货与来料页面保留相同到货单号／行号和辅助明细 ID，再次进入同一来源仍可定位。缺少目标页面权限时保留来源文字；来源投影缺失时明确说明，不在前端逐行请求详情补齐或推算关系。

拆分须明确填写分出数量，并同步扣减原行，保持本次合计不变；移除某授权选择会移除其全部目标，移除一条目标仅影响该行。数量输入保留空值、越界及非法原文，在字段旁报错并阻止确认，不自动截断或静默回填。逐授权在对应数量输入旁核对有效余量与入库后余量；单目标直接使用输入数量，多目标才补充跨目标合计，并在该授权的首条目标旁显示一次。合计按真实授权身份关联，不依赖目标行是否相邻，也不把不同物料的数量汇总成进度。确认弹窗不另列重复的目标预览或授权／目标数量统计，来源与目标批次直接在编辑明细核对。已有批次显示完整批号、身份与可用资格。

结果未知冻结原 body/key；失败后重读有效资格供明确核对，不自动取新范围或新键重入。缓存页返回可刷新上下文，不得据此替换原命令。

## 8. 状态与 HTTP 消费约定

端点与字段以 API wrapper 和[共享契约](../../../packages/contracts/README.md)为准，状态字典由[共享常量](../../../packages/constants/README.md)维护。消费时保留以下边界：

- 采购状态、整批轮次、Quality 办理、处置分配及实际执行分别表达事实。`open` 表示进行中，不能翻译成尚未到货；`superseded` 历史不重新累计资格，人工结束不能翻译成质检达标。
- 来料页面归 Quality，但命令由 Procurement 锁定到货后编排 Quality 公开能力；前端不能分别调用两模块模拟同一事务，也不能传“已合格”布尔值代替依据。
- 写入使用精确 DTO，列表及批量上限按公共契约；超过限制要求另单，不偷偷截断。API wrapper 只透传用例持有的幂等键。
- 采购创建／修改、补单、下单、取消、关闭及到货处置等已登记命令使用 Idempotency-Key；供应商维护和只读解析不启用。不能用 POST 方法判定幂等要求。签名包括路径参数、完整规范化 body 及版本，未知结果保留第一次实际发送的内容。
- 整批操作携带行版本与 roundId/roundVersion；实际执行额外引用 allocation、实收修订和 QC。人工拒收实际退回可以没有普通 QC/acceptance，但必须有真实当前拒收分配。
- 外购旧 `/production/purchase-inbounds` 路径仅保留只读历史，不能因为可读取就恢复旧创建、确认或取消命令；不提供自由选料直入或待确认外购单。

### 8.1 权限消费

供应商 options 可由获准的供应商、采购单或采购到货页面读取，质检页不单独请求该候选。采购物料／版本及需求候选只需要采购页查看权限，不附加主数据管理权限。

相关采购投影允许契约登记的采购／生产需求宿主读取，但跳转采购仍核验目标权限。Quality 读取只需其查看权限；共用入库页面、外购与成品入库候选及历史读取统一使用 `warehouse:inbound:view`，不附加质量或生产任务页面权限。入库确认等写操作继续独立鉴权，查看权限不授予写入能力。检验权限不授予更正实收、退回或入库能力，也不要求各角色必须由不同自然人承担；页面可见性不能替代后端鉴权。
