# 采购与入库的前端约束

本文维护代码和页面外观不容易解释的输入、候选、并发及跨页约束。业务规则的主要依据为 [采购订单](../../api/src/modules/procurement/docs/purchase-orders.md)、[到货与更正](../../api/src/modules/procurement/docs/receipts.md)、[整批定稿与执行授权](../../api/src/modules/procurement/docs/receipt-acceptance.md)；跨模块背景见[业务设计](../../../docs/procurement-inbound-design.md)。本文不另行定义数量公式、状态机或业务资格。

[来料交互](incoming-inspection-adoption.md)维护检验、定稿与拒收的专用约束；[管理端架构](architecture.md)、[路由与标签页](route-dialogs-and-tabs.md)、[HTTP 错误处理](http-error-handling.md)维护通用行为。未完成事项和验收状态以[路线图](../../../docs/roadmap.md)为准。

## 1. 当前交互边界

采购来源、供应商身份、检验事实和执行资格均来自所属模块。前端不得用展示摘要推断资格，尤其注意：

- 采购供应商属于行，主单的 `suppliers` 只是去重展示集合；生产的 supplierHint 仅供采购参考，不能自动代选供应商。
- 采购可选择仍符合其他资格的停用精确版本，生产选版则有自己的启用要求。使用采购专用候选并显示状态，不能复用生产过滤条件。
- 到货前没有内部库存批次，首次实际入库才生成。到货投影的可空 batchId 不表示已确认的库存明细也允许空批次。
- 外购输入保存在本地草稿；成品入库仍使用自身待确认单和批准清单，不因复用入库页面改变业务语义。

## 2. 页面与路由

路由、菜单和权限映射直接见 [router](../src/router/index.ts)、[AdminLayout](../src/views/AdminLayout.vue)；不在本文另列一套页面清单。页面只按查看权限控制整页，命令权限由后端逐接口校验，不要求页面内按钮做权限隐藏。

### 2.1 详情定位

- 采购定位使用 `purchaseOrderId`；从需求发起草稿使用 `workOrderId+demandId`。参数必须经服务端解析资格与归属，单独 demandId 不自动推定工单。
- 到货定位使用 `receiptId`，可附 `receiptLineId`；来料检验使用 `receiptLineId`。入库继续用 `inboundId`，外购显式附 `sourceType=purchased`；没有 sourceType 的既有定位仍按成品处理，再读取详情核实真实类型。
- 外购入库可由 `receiptLineId` 查询当前有效分配，不能把来源页携带的旧数量当授权。采购已关闭不等于原到货不可继续办理。
- 更换定位目标先确认放弃未保存输入；取消保留原草稿和原定位。提交中或结果未知时阻止换单。离开页面仅使旧读取失效，不销毁缓存草稿。
- 生产需求总览由 [MaterialDemandOverviewDialog](../src/views/production/components/MaterialDemandOverviewDialog.vue)承担，没有独立 `production-material-demands` 路由；同名 HTTP 资源不能当页面链接。

## 3. 供应商及采购选择

### 3.1 候选和跨页选择

供应商目录及名称约束见[供应商设计](../../api/src/modules/procurement/docs/suppliers.md)。采购逐行明确选择已有供应商 ID，不把自由文本当关系键、不隐式创建供应商或建立物料绑定；不存在时先维护目录。供应商编辑保留打开时的版本，重复名称失败保留输入；资料变化后阻止提交，须关闭并从最新列表重新选择，不能更新版本后覆盖他人修改。

按需采购先选择一个工单。候选由专用工单接口及需求分页接口提供，不能从第一页需求拼凑工单。需求分页按叶子计数，任务分组只是当前页投影；跨页选择用独立 demandId 集合保存，不因翻页、刷新或当前窗口缺少某项而判为失效，不提供全选或隐式全量读取。

选中 ID 解析逐项返回当前资格及原因；失败保留草稿并禁止下单，不能默认合格或清空来源。在审更正等阻断由服务端判定。新采购候选过滤不能用于屏蔽已有采购的历史来源；草稿保存及正式下单分别重核资格。

切换工单会影响所有采购编辑行，即使当前没有勾选需求也须确认清空；取消切换保留原状态。收到外部定位参数执行同一守卫，不能静默带入其他工单的需求。独立备料不关联或伪造工单、任务、需求。

### 3.2 采购行与独立补单

选择后以物料及精确版本组织来源，但采购量独立填写，不自动当成需求满足量或以需求剩余量封顶。同物料／版本向不同供应商采购必须分别成行；同供应商重复行须人员明确归并并确认总量，不能静默相加。拆供应商行时新行须重新明确来源、供应商和数量，supplierHint 逐需求保留。

界面分别检查采购行数和来源映射条数，每单各不超过 100。相同 demandId 出现在不同供应商行时每处都占映射数，不能用去重 ID 数代替；单行不重复关联同一需求，按需至少一条来源，备料来源为空。超过限制要求另单办理，不截断输入。

补单沿普通草稿和下单生命周期，固定原采购行供应商、精确版本、工单和所选原行来源；原需求关闭不要求恢复。质量补发引用真实质量待退分配或已退历史，保留供应商约定，可以先补后退；人工拒收不能作为质量补发依据。补购量不按原需求／退回量设置累计上限，相关补单按原采购行精确分页，供人员核对，不能把有关联解释成仍有可采购额度。

### 3.3 需求相关采购

相关采购按单 distinct 计数，关联行展示自己的采购量而非“本需求已采购量”，不累计为生产满足量。使用批量投影而非逐需求请求详情；相关行不混入到货、检验或入库进度，进一步追溯进入真实采购。相关投影可由获准的生产页面消费，跳转采购详情仍独立核验采购权限。

### 3.4 到货身份与数量输入

到货输入按可收货采购行保留供应商、物料和精确版本，不能先合并物料再手工拆供应商。只到部分行时允许未到行留空；同一采购行追加另一来料批次是新增独立输入，不从原行扣量，不自动维持总数。不同明细形成独立库存批次，同一明细分次入库沿用批次。

## 4. 采购履约与关闭

采购量、实收、允许入库和实际库存余额不是同一个数量。展示字段及算法使用采购所有者投影，不能跨物料相加表示完成进度，不能把放行差额标为少收，也不能用生产领用后的库存余额降低历史已入量。

关闭使用 `allowedCloseReasons`：优先采用当前成立的达标／质量退回处置完成依据，否则人工结束须留原因；无到货取消保持独立。关闭前重读当前行、数量和资格，变化后要求重新核对，不只替换版本。达标不自动关行，主单完成由后端按行汇总，终态没有恢复或人工完成整单命令。

采购终态只结束新增采购履约；原到货的检验、入库、退回仍可有待办。历史关闭证据与当前进度分开，后续更正引发差异时不改写旧依据。正式下单后供应商、身份、数量和来源冻结，错误按所有者定义的取消／结束及重建流程处理。

### 采购单分块与状态操作

展开状态由 [usePurchaseOrderExpansion](../src/views/procurement/composables/usePurchaseOrderExpansion.ts) 所有。展示组件只消费已读数据，动作弹窗独立持有确认版本和输入；列表刷新不得替换动作依据。

明细只在需要时读取，状态范围限当前页及一个外部定位单据，避免浏览历史积累无界缓存。展开读取按 ID 去重；收起、分页移除、失活和卸载取消旧读取并拒绝迟到回写，再次展开重新核验。来源和关闭证据使用已读详情，不额外逐行取数。

返回页面或手动刷新只重读已展开单据；写后复用最新详情并刷新列表，不重读无关单据。失败保留旧展示但禁用办理，提供单据级重试；操作前资格重读不能为减少请求而省略。外部定位单据不在当前页时作为独立定位项展示，不能把它算进当前筛选的分页总数。

## 5. 到货、实收更正与退回

累计量消费收货采购详情的 `items[].quantities`，不逐行请求。实收归属、历史已入及已退按所有者规则计算；承接补单的份额不能重复算给原单。累计量不含未提交输入，同一采购行追加多个批次也不能重复汇总其累计值。

打开、缓存页恢复、显式刷新及提交前核对更新只读数量，保留实收、批号和说明。采购版本或资格变化要求重新选择核对；仅累计量变化时，若在提交前发现，也先提示核对并停止本次命令，再次确认才继续。计划及累计量只供对照，不按计划余量为实收输入设置 max。

新到货与同批计数更正使用不同事实身份，不能通过更正改变供应商、物料、批次或旧物流。更正输入本次到货核实总量，已处置量只读；旧剩余资格失效、零剩余办结及拒收后重新办理见[整批规则](../../api/src/modules/procurement/docs/receipt-acceptance.md)。这些后果需在确认时说明，不让用户把更正当补到货或登记损耗。

超量补单选择原采购行的真实到货，使用 `excess-receipt-candidates` 的独立分页权限，不遍历全部到货。定位到采购后重新核验归属；补单正式下单后由原到货定稿关联，不重复登记到货／质检。未处置量是参考，创建补单草稿不恢复实物或授予入库资格。

展示上区分“授权入库／安排退回”与“已实际入库／已实际退回”。历史分配保存去向并不表示现在仍有执行资格；人工拒收和质检不合格均不等于交接完成。退回按具体有效待退分配一次确认全部余量，不提供分次退回输入。具体交互见[来料整批处理](incoming-inspection-adoption.md)。

## 6. 来料检验与复检

待检来源使用真实 `roundId`、`taskKind=uninspected` 和 `case=null`，显式发起后才有 Quality case。仅打开表单不暂停实物；已发起后关闭表单也不撤销办理，必须让用户明确这一提交边界。

检验覆盖同次到货的整批剩余实物，抽检样本不形成独立处置范围。数量输入、方法切换、差异／异常提示及库管定稿引用见[来料交互](incoming-inspection-adoption.md)，公式、超建议责任和同一检验重复引用的扣减规则见[整批定稿](../../api/src/modules/procurement/docs/receipt-acceptance.md)。前端不能把数量说明当解除质量阻断，也不能用样本不合格数直接填写实际报废／退回量。

## 7. 有效放行与实际入库

`usePurchaseInboundReleases` 独占候选窗口、跨页选择和数量草稿；`usePurchaseInbounds` 只读历史。一次确认只含同供应商的有效分配，可以跨采购及到货，通过 [procurement-inbounds API](../src/api/procurement-inbounds.ts) 一次原子提交，不能循环单条 HTTP 冒充整单成功，也不能由前端自动拆成多供应商写入。

提交前通过 allocationIds 批量重读全部已选分配；当前轮、依据或真实余量变化就保留输入并停止。明确重核可更新同一 allocation 的余量，但不丢弃已填数量；不能静默换分配或仅刷新版本后提交。部分入库不拆新子行。

本次量默认当前有效余量，允许调小，按所属分配的服务端资格和额度校验。已关闭采购仍可能有有效分配；有效超建议授权不在入库时再按质检建议拦截，避免前端否定已保存的责任依据。库存余额和最新一条检验都不能代替跨历次实际入库总量。

首次入库前 batchId/batchCode 为空，显示尚未生成并禁止手填；成功后使用服务器批号，同次到货后续复用。所有事实链引用采用当时真实依据，不用当前值替换历史。

结果未知冻结原 body/key；失败后重读有效资格供明确核对，不自动取新范围或新键重入。缓存页返回可刷新上下文，不得据此替换原命令。

## 8. 状态与 HTTP 消费约定

端点与字段以 API wrapper 和[共享契约](../../../packages/contracts/README.md)为准，状态字典由[共享常量](../../../packages/constants/README.md)维护。消费时保留以下边界：

- 采购状态、整批轮次、Quality 办理、处置分配及实际执行分别表达事实。`open` 表示进行中，不能翻译成尚未到货；`superseded` 历史不重新累计资格，人工结束不能翻译成质检达标。
- 来料页面归 Quality，但命令由 Procurement 锁定到货后编排 Quality 公开能力；前端不能分别调用两模块模拟同一事务，也不能传“已合格”布尔值代替依据。
- 写入使用精确 DTO，列表及批量上限按公共契约；超过限制要求另单，不偷偷截断。API wrapper 只透传用例持有的幂等键。
- 采购创建／修改、补单、下单、取消、关闭及到货处置等已登记命令使用 Idempotency-Key；供应商维护和只读解析不启用。不能用 POST 方法判定幂等要求。签名包括路径参数、完整规范化 body 及版本，未知结果保留第一次实际发送的内容。
- 整批操作携带行版本与 roundId/roundVersion；实际执行额外引用 allocation、实收修订和 QC。人工拒收实际退回可以没有普通 QC/acceptance，但必须有真实当前拒收分配。
- 外购旧 `/production/purchase-inbounds` 路径仅保留只读历史，不能因为可读取就恢复旧创建、确认或取消命令；不提供自由选料直入或待确认外购单。

### 8.1 权限消费

供应商 options 可由获准的供应商、采购单或采购到货页面读取，质检页不单独请求该候选。采购物料／版本及需求候选只需要采购页查看权限，不附加主数据管理权限。

相关采购投影允许契约登记的采购／生产需求宿主读取，但跳转采购仍核验目标权限。Quality 读取只需其查看权限；外购入库沿既有 inbounds 权限，不附加质量或生产任务页面权限。检验权限不授予更正实收、退回或入库能力，也不要求各角色必须由不同自然人承担；页面可见性不能替代后端鉴权。

## 9. 状态所有权

通用列表、候选、详情、草稿及写意图归属遵守[管理端架构](architecture.md)。来料和成品各自持有 editor，不因共用入库页混用资格、数量或命令；已选需求和资格解析独立于分页窗口。采购展开状态的特别限制见[分块与操作](#采购单分块与状态操作)。
