# 来料检验与定稿交互

办理身份、状态及数量由 [Procurement 整批定稿](../../api/src/modules/procurement/docs/receipt-acceptance.md)维护，分组关系由 [Quality](../../api/src/modules/quality/docs/incoming-inspection-orders.md)维护，读取范围由[到货查询](../../api/src/modules/procurement/docs/receipt-queries.md)维护。本文只补充输入和草稿边界；通用保护见[管理端架构](architecture.md)。

## 整批状态与入口

检查工作台连续承接明确发起、复检和结果填写。提交开始后的业务事实不会因关闭表单撤销；开始确认须说明这一边界，不能让打开或关闭表单看起来会暂停或恢复实物。

检查工作台与到货处置分别持有草稿；检查只读自身来源契约。需要更正实收或仓库办理时前往到货页面，不在检查表单内暗中提交另一业务动作。

## 分组读取、关联草稿与定位

主单与到货的展开、人工选择及缓存遵守[到货层次交互](procurement-inbound.md#5-到货实收更正与退回)。

关联窗口的备注编辑与关系调整分开提交。主单入口固定目标主单；到货入口固定整张到货。关联目录、候选及临时选择分别保留，核对清单只表示本次增量：撤销草稿项不等于解除已存关系。跨页选择按真实到货 ID 保留，不以可见物料行代表整张到货。

分组草稿与检查草稿独立，移组、折叠或翻页不清空检查输入。关联变更的身份和版本依据由 [Quality 关系命令](../../api/src/modules/quality/docs/incoming-inspection-orders.md#关系命令与版本)规定；现场标签风险须在关联确认时提示，纯备注修改无需该提示。

历史按到货行与 case ID 定位，先解析当前归属；页外目标按[详情定位](procurement-inbound.md#21-详情定位)独立读取。移组后调整背景归属，保持已开的工作台及草稿；未分组来源仍可直接查看。

## 来料检验表单

合格、不合格数与结论初始留空；切换方式清空数量及结论。与[成品质检](finished-inspections.md#输入与证据)不同，修改数量保留已选结论，但无效数量仍阻止提交。

在途检验的“送检数量”使用该次发起快照；只有来源、轮次和实收依据一致时才用当前入退数量解释该范围。没有在途检验时改称当前“剩余实物”，不把两种时点拼成一个算式。依据不完整时提示核对，零与缺失分开显示。

本轮发起原因只取同轮 Quality case，不用到货处理轮原因或沿用的历史检验原因补位。历史明确标识实际来源轮；精确 case 定位失败不回退到当前或最近记录，查看历史不更换正在填写的目标。

## 库管核对定稿

用户填写“本批到货总量”，初值为当前记录，包含已入、已退及剩余实物；命令的 `confirmedQuantity` 则是扣除已入、已退后的本轮剩余量。两者必须明确区分，历史按原命令含义显示“当时剩余数量”。无效输入保留原文并阻止确认，不自动修正总量或显示有效负余量。

有效总量与记录不同时，提示本次将更正到货量；已记录累计不随草稿变化，也不预演采购累计或计划差额。建议、默认拆分、超建议责任和重复引用扣减直接遵守[所有者规则](../../api/src/modules/procurement/docs/receipt-acceptance.md#数量与建议)，不在此维护另一份算法。

定稿草稿只从专用定稿上下文初始化和重核；首次初始化与纯分配更正按契约区分。检验凭据可收纳，当前引用、关键数量和非空例外依据仍须可见。分配说明与整份清单的核对／更正说明独立，不能互相补位。

## 人工拒收与实际执行

拒收、撤销及实际退回的确认须说明[整批规则](../../api/src/modules/procurement/docs/receipt-acceptance.md)规定的真实影响，避免把授权待退理解为已交接、把撤销拒收理解为恢复原授权。目标批次及入库草稿见[采购入库交互](procurement-inbound.md#7-有效放行与实际入库)。
