# 来料整批检验、定稿与入库交互

整批状态、数量算法和执行资格由[Procurement 整批定稿](../../api/src/modules/procurement/docs/receipt-acceptance.md)维护；跨模块决定见 [ADR-0015](../../../docs/adr/0015-unified-quality-quantity-semantics.md)。本文保留输入、证据和误操作边界，不重复业务流程图或公式。来料与成品使用各自契约，成品检查事实和定稿提示见[成品专题](finished-inspections.md)。

## 整批状态与入口

同次到货的 receipt_line 是整批办理身份；同采购行再次到货是另一明细，不可与同批计数更正混淆。round 表达办理阶段，allocation 表达正式去向及实际执行；样本不是独立处置范围。

列表的分组外壳、基础列及读取生命周期共用[采购专题的工作列表约定](procurement-inbound.md#5-到货实收更正与退回)。列表按到货明细服务端分页，每条到货行仅一项；采购单、到货单分组只组织当前页，不改变分页总数，也不意味着已读齐整张采购单。页面只提供一个“当前阶段”筛选，默认及重置均为“全部”，从 `RECEIPT_LINE_STAGES` 排除 `voided` 并使用共享文案提供选项，通过 `stage` 在服务端计数和分页前精确匹配；已作废到货不进入当前工作列表，历史由真实到货行或 case 精确入口查阅，不提供历史 case 办理状态或“历史轮次”筛选。列表只展示当前轮、当前在途办理或当前明确采用的检验摘要，不读取、展开或回退到历史记录；没有当前检验时明确说明，不能以最近历史结果代替。来源轮虽已替代，但检验被当前轮明确引用时标为“当前采用 · 沿用此前检验”，并使用服务端真实来源轮号。具体办理资格仍从详情重新读取，不为列表摘要逐行追加详情请求。

来料检验列表、到货列表及详情的阶段标签共用 `receiptLineStageLabel/Type/Effect`，来料列表直接消费服务端 `stage`，本页统计和下一步提示沿用该阶段，不在前端重新派生筛选结果。标签为“本批已处理完”时使用 success/light，“人工拒收”使用 danger/plain，其余使用当前轮状态的共享文案及配色。阶段的派生顺序及精确匹配范围由[到货查询](../../api/src/modules/procurement/docs/receipt-queries.md#检验列表)维护，不以原申报量、检验来源轮或历史结论推算。

精确打开已作废到货时，工作台展示作废原因、操作者和时间，检验记录仅供追溯，不提供新发起或填写结果入口。已打开的旧检验表单在重新核对时发现作废，保留本地输入并阻止旧依据提交；整单作废确认及原登记历史展示遵守[采购专题](procurement-inbound.md#5-到货实收更正与退回)。

首次及复检都先明确发起，办理覆盖全部未处置实物，样本数不能变成部分办理量。确认发起后剩余实物暂停、旧分配失去执行资格；关闭结果表单不撤销此事实。提示必须说明提交边界，不能让用户认为打开表单已暂停、关闭即恢复。

实收更正只填写本次核实总量、原因及同批确认，已入／已退只读，按服务端结果预览剩余量。确认中说明旧资格失效、回待检或零剩余办结；已拒收批次也不恢复旧拒收效力。此入口不登记新到货或损耗，普通更正不提交 ownership。

## 来料检验表单

合格／不合格数初始留空，全检与抽检的检查数量按各自契约派生，不以申报量封顶。切换方式清空数量及结论；两项数量填写且检查数量有效后才能选择放行结论。修改数量保留已选结论，但数量无效或结论未选时不能提交。来料质检不填写整批 `coveredQuantity`；成品质检同样不填写，不影响库管在 Procurement 定稿核实 C。来料不提供零量核实或实际剔除量。

填写结论时只显示检验对象身份、当前状态及本次送检范围，不重复展示仓库授权或历史库存批次。在途检验的“仓库送检数量”取本次 case 发起时的申报快照，只展示一次，不替换为后续实时剩余量；没有在途检验时，以“未入库或退回”展示当前剩余范围。已有入库或退回时补充累计事实，明确送检数量已扣除这两部分，避免把原到货总量误填为本次检查量。实际检查数在数量输入下标为“检查总数”或“样本总数”，与送检快照区分；全检数量差异直接突出，抽检只记录样本，简短提示不折叠。检验中是正常办理阶段，待复检或不放行的真实阻断仍须明确显示。

当前检验的原因取同一处理轮所属 Quality case 的发起原因，复检和检验更正分别标为“复检原因”“更正原因”；首次检验、没有同轮 case 或原因为空时显示 `-`，不使用到货处理轮原因或沿用的历史检验原因补位。

历史保留检验事实、结论、时间及凭据，不将“完成检查”或历史“曾放行”显示成当前可继续；不合格不自动填入实际退回／报废。明确放行仍须库管定稿，质量阻断不能用数量说明解除。

来料列表与详情的到货明细标识遵守[采购专题的统一 ID 展示约定](procurement-inbound.md#21-详情定位)，处理轮号不充当到货明细身份。本次检验摘要不展示处理轮号；其他追溯展示只取真实轮号，检验来源轮不称为“第 N 次检验”。列表有当前结果时显示该 case 的真实检验记录 ID 和结论；记录 ID 链接按对应 caseId 精确打开详情的检验历史，不因读取期间当前采用关系变化而换成另一条记录。普通详情入口只按 receiptLineId 打开本次检验。只有到货明细 ID 的入口也须读到到货单号、真实明细 ID 和采购单号；关闭后再次点击同一来源可以重新打开。无目标页面权限时保留来源文字。

来料详情沿用成品质检的工作台结构：到货、采购单、物料版本、实际供应商和供应商批号组成身份摘要，下设“本次检验／检验历史”页签，标题与固定 footer 保持可见，仅正文滚动。本次检验展示当前轮、剩余实物、当前采用的检查事实及凭据；发起首次检验、整批复检／更正与检查结果录入只由同一工作台连续办理；到货处置弹窗只承载实收更正、人工拒收／撤销及实际退回，不保留另一份质检表单或质检摘要模式。质检与到货处置分别使用各自的来源入口，共用到货行命令能力及幂等意图，编辑中的数量和轮次依据保持冻结；放弃填写只清除本地草稿，不撤销已发起的检验。

检验历史在首次进入页签时读取，按办理记录独立服务端分页，不另开历史 Dialog，也不预读到货处置的七类历史。按 caseId 定位时读取该单条办理及其真实来源轮号，自动展开指定记录，标清检验记录 ID、时间和当时事实；指定记录不存在、读取失败或不属于该到货行时显示定位错误，不回退到最新或当前采用记录，可重试或退出定位查看全部分页历史。没有当前轮信息时不推断记录属于本轮或历史轮；只有当前引用关系已知时才标记当前采用。切换页签保留检验草稿与历史分页，历史不挤占当前填写区。

详情不展示处置分配、核实总量、累计已入／已退和仓库执行，也不提供入库办理；录入中仅在确有已入／已退时提示实际检验剩余范围。底部“查看到货”继续核验目标页面权限，仓库定稿及实收更正由到货页面办理。

详情、检验发起后的连续录入及提交前核对统一使用专用质检来源契约，不请求完整到货详情。契约仅包含来源身份、当前版本／轮次、实物范围、当前在途及明确采用的检验与其来源轮号，不预读分配、入退明细、正式清单或历史统计。真实入退汇总用于计算剩余范围，并仅在录入表单已有实际处置时补充范围提示；不在详情重复陈列。查询边界由[到货查询](../../api/src/modules/procurement/docs/receipt-queries.md)维护。

## 库管核对定稿

editor 保留当前 round、行版本及有效检验 ID，只引用本轮显式关联或服务端明确继承的结果，不提供任选历史最高值。上方摘要分别展示已记录的核实总量、已入、已退和未处置量，检验依据保留检查事实；核实剩余量输入下常驻普通 `InlineHint`，集中展示唯一的建议可入计算式并强调结果，不重复展示实物剩余算式。本次草稿核实剩余量及复核到货总量另标清楚，编辑草稿不改写已记录实物账。全检建议逐项展示同一检验的已入、质量已退、其他已退及检查事实；中间值为负时标出原值再说明按零取值。抽检建议仍沿所有者规则展示，不把实物剩余当成建议量。首次默认草稿不重复预填同检验已实际质量退回的部分；建议及重复引用扣减均以[整批定稿所有者公式](../../api/src/modules/procurement/docs/receipt-acceptance.md#数量与建议)为准。无有效建议或草稿可入超建议时保留简短的实际数量计算提示及必填异常／超建议依据，不以整段警告把建议量称为实物剩余。

- 总量变化／全检不一致提示核对说明；抽检样本少于整批是正常情形，不能报整批差异。样本或不合格数超过核实量时不显示负建议或有效建议，要求异常依据。
- 超建议可入须明确确认依据，不能改原质检事实来消除差异；分配合计须匹配核实量，质量未放行不开放数量例外。
- 定稿草稿只从到货行详情初始化：首次按原采购行剩余计划和检验建议带出分配；从 `ownershipSources` 保留补单的正剩余归属并提示核对去向，不能因复检清空或恢复一次性承接资格。纯分配更正带入详情中当前分配的实际未处置份额。详情持有数量、轮次及版本依据，候选搜索不生成或重置草稿。
- 采购归属按采购单号远程搜索，仅返回前 10 条匹配；有更多匹配时提示继续输入关键词，不提供翻页。已选项通过 `includeIds → resolved` 独立核验，不能因搜索未命中或未进入前 10 条判为失效。打开弹窗、展开下拉、缓存页恢复及提交前重新核验候选，也可在弹窗内刷新新下单的补单；搜索与刷新只更新候选，不覆盖已填去向、数量或说明。候选实际失效／读取失败保留草稿并阻止确认，读取失败可原位重试；计数更正影响采购份额时须显式核对并留依据。
- 已全部实际入库／退回、未处置量为零时，正式清单不能再次定稿。已定稿且仍有检验依据的明细保留禁用的更正入口并解释原因；真实同批总量漏计可走更正实收，新增剩余须重新检验和定稿，原已入／已退事实保持不变。
- 补单先正式下单再承接真实到货，不再登记到货或质检；尚未落实部分保留待处理。数量例子沿[所有者文档](../../api/src/modules/procurement/docs/receipt-acceptance.md)读取。

历史展示当时轮次、检验、修订、采购分配及确认依据，不用当前值覆盖原证据，也不把历史授权当作当前执行资格。

## 人工拒收与实际执行

人工拒收数量为全部未处置实物且只读，原因必填，无需伪造 QC／正式清单。它只授权待退，不表示交接完成；旧检查或入库迟到提交应显示状态冲突，不能自动接到新轮。

撤销拒收只在当前拒收且仍有未处置量时提供，原因必填；确认说明回新轮待检、不恢复旧可入。全部已退、已入库退货、部分人工拒收均不能伪装成此操作。拒收时若既有补单归属总量与剩余不一致，依据 ownershipSources 展示各归属，人员显式填写匹配剩余的数量。

分配显示“授权去向”和“执行状态”两个维度，不能因全部入库／退回就改写原 disposition；旧轮未执行授权标失效。入库可按同一 allocation 分次，退回按具体待退分配一次确认全部余量，不创建父子范围。当前已核准例外授权不再按 G/F 拦截；旧 ID 失效不能静默换新 ID。供应商、批号及入库草稿边界见[采购专题](procurement-inbound.md)。

## 生命周期与权限

当前依据和历史窗口各自持有读取状态与请求代际，历史只在对应页签读取；关闭、换目标、页签退出历史或页面失活使旧读取失效。返回缓存页刷新仍打开的当前依据，并按已加载的历史页签定向刷新，保留草稿、分页和精确定位。Quality 查询不附加采购／生产页面权限，跨页目标独立鉴权。工作台关闭、标签关闭和同页定位保护同一份输入与未知结果；提交中禁止关闭，未知结果锁定原请求并保留原样重试入口，查看历史或刷新不会生成新意图。

提交前重读 roundId/roundVersion、行版本及检验依据，变化或失败保留输入并停止。409 不自动换版本重试；未知结果仅按第一次 body/key 重试。通用代际及取消规则见[管理端架构](architecture.md)。待实现及验收状态统一见[路线图](../../../docs/roadmap.md)，不将文档清理视为验收。
