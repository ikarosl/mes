# 员工工作台与工序追踪

流转、异常与终检事实由 [Production](../../api/src/modules/production/docs/database/execution-traceability-quality.md) 维护，任务开始和结束见[任务生命周期](../../api/src/modules/production/docs/database/production-termination.md)。人员目录与账号分离，身份及分组由 [Identity](../../api/src/modules/identity/README.md) 维护；通用读取、草稿和未知结果保护遵守[前端架构](architecture.md)。

## 输入与现场身份

工作台的任务和本站工序决定本次扫码目标，登记人员必须人工选择。人员分组只缩小选择范围；切换分组保留已选人员身份，末站默认展示质检组。扫码枪和手输共用追踪码输入与提交入口；工作台扫码执行到站和交接，追踪页追踪码筛选只查询。

建卡、异常登记和最终处理沿用明确选择的现场人员；终检另选质检人员。异常影响量按该问题涉及的实物数量填写，返修成功和本次新增报废分别据实填写，显式的零与尚未填写分开处理。关联已报废时选择本盘其他问题的新增报废记录，由现场人员判断是否为同一实物；引用数量用于本问题的数量核对，不重复扣减盘量。

批量追踪卡终检展示当前剩余盘量并据此一次确认产出；研发任务无追踪卡，最终可用产出仍留空，须据实填写并区分零与尚未填写。最终确认前的盘量更正在原卡上办理，标签补打沿用原码。

## 跨页定位与详情归属

任务页的工序入口统一进入 `/production/tracking?batchId=...`；工作台、追踪卡和报工历史使用同一份卡详情展示。追踪页可用 `cardId` 精确定位卡，`stepRecordId` 定位站点，`view=history` 定位报工历史。定位只在新目标到来时消费，缓存返回不重复刷新或重开详情。

建卡、随盘异常、处理、盘量更正与终检各自冻结提交对象和版本；浏览其他卡不改写正在填写的对象。未知结果保留原提交内容与请求标识，重试仍使用原意图；确认放弃前须先核对相关事实。标签预览和补打只读取当前卡快照，已打印纸张不会随盘量更正更新。

成品入库分类仅查询成品库存批次的入库记录，定位使用 `inventoryBatchId`，办理入口仍在终检。库存明细到该分类携带真实库存批次；从记录查看生产来源进入同一工序追踪页。
