# 员工工作台与工序追踪

流转、异常与终检事实由 [Production](../../api/src/modules/production/docs/database/execution-traceability-quality.md) 维护，任务开始和结束见[任务生命周期](../../api/src/modules/production/docs/database/production-termination.md)。人员目录与账号分离，人员身份由 [Identity](../../api/src/modules/identity/README.md) 维护；通用读取、草稿和未知结果保护遵守[前端架构](architecture.md)。

## 输入与现场身份

工作台的任务和本站工序决定本次扫码目标，登记人员必须人工选择。扫码枪和手输共用追踪码输入与提交入口；工作台扫码执行到站和交接，追踪页追踪码筛选只查询。

建卡、异常登记、最终处理和终检沿用工作台明确选择的现场人员；没有已选人员时须人工选择。异常影响量按该问题涉及的实物数量填写，返修成功和本次新增报废分别据实填写，显式的零与尚未填写分开处理。关联已报废时选择本盘其他问题的新增报废记录，由现场人员判断是否为同一实物；引用数量用于本问题的数量核对，不重复扣减盘量。

工作台并列提供现场单盘建卡和批量预生成。单盘成功后保留本任务刚使用的盘量作为下一盘默认；切换任务恢复初始值。批量填写本次分盘总量与标准每盘数量，预览完整盘、尾盘及合计，不自动套用任务计划剩余量。生成结果中的卡号与范围以服务端返回为准；打印失败从本批结果或追踪卡管理选择原卡补打，不重新建卡。

批量追踪卡终检展示当前剩余盘量并据此一次确认产出；研发任务无追踪卡，最终可用产出仍留空，须据实填写并区分零与尚未填写。最终确认前的盘量更正在原卡上办理，标签补打沿用原码。

## 跨页定位与详情归属

任务页的工序入口统一进入 `/production/tracking?batchId=...`；工作台、追踪卡和报工历史使用同一份卡详情展示。追踪页可用 `cardId` 精确定位卡，`stepRecordId` 定位站点，`view=history` 定位报工历史。定位只在新目标到来时消费，缓存返回不重复刷新或重开详情。

建卡、随盘异常、处理、盘量更正与终检各自冻结提交对象和版本；浏览其他卡不改写正在填写的对象。批量生成冻结任务、人员和两项数量，整批沿用一个提交意图。未知结果保留原提交内容与请求标识，重试仍使用原意图；确认放弃前须先核对相关事实。

标签仅打印 Code128 条形码及完整卡号，不包含任务标题、盘量或人员等信息，更正盘量无需更换标签。批量打印冻结本次选择的卡号，预览中可全选或选取部分；追踪卡管理的选择只属于当前列表页，翻页或刷新时清除。预览不随其他卡浏览或列表刷新替换打印对象。

任务中的产出与入库入口展示同任务产出来源、有效数量及入库归属；勾选的是整笔待入库产出，新建目标按本次选择共用，已有目标限定本任务。切换任务须清除未保存选择；未知结果沿用冻结的产出 ID、目标和请求标识。成品入库分类查询实际库存批次的入库记录，定位使用 `inventoryBatchId`；从记录查看生产来源进入同一工序追踪页。
