# 员工工作台与工序追踪

流转、异常与终检事实由 [Production](../../api/src/modules/production/docs/database/execution-traceability-quality.md) 维护，任务开始和结束见[任务生命周期](../../api/src/modules/production/docs/database/production-termination.md)。人员目录与账号分离，人员身份由 [Identity](../../api/src/modules/identity/README.md) 维护；通用读取、草稿和未知结果保护遵守[前端架构](architecture.md)。

## 输入与现场身份

工作台的任务和本站工序决定本次扫码目标，登记人员必须人工选择。扫码枪和手输共用追踪码输入与提交入口；输入完成失焦或提交时，前端调用前后端共享的归一化函数，将完整短码还原为完整卡号，不在逐字符输入中途改写。工作台扫码执行到站和交接，追踪页追踪码筛选只查询；完整规范卡号精确定位单卡，普通关键词片段保留模糊查询。

建卡、异常登记、最终处理和终检沿用工作台明确选择的现场人员；没有已选人员时须人工选择。异常登记的关联工序初始留空，现场明确有关联时再选择；关联不表示已确定异常原因。异常描述按关联工序远程搜索历史标签，可多选或逐条新增；搜索和切换工序保留已选文本与尚未添加的输入，未指定工序时查询通用历史描述。提交时分别传递每枚标签并归属最终选择的关联工序，展示用的拼接文本不作为新标签；尚未添加的输入须先添加或清空，关闭时按未保存输入保护。异常数量初始为 1，须按该问题涉及的实物数量核对填写，上报时可以留空处置，也可以同时登记处理结果。

同一卡可以多次登记异常，可登记量按当前盘量扣除未处理异常数量计算，最终由 Production 在卡锁内校验。上报与后续处理共用一张表单。处理已有异常时锁定原工序、异常数量和标签，登记人员填写本次处理人员。选择“部分返修、部分报废”时只填写本次报废数量，其余数量表示已返修完成；切换处置保留报废输入，实际提交仅采用当前选择的结果，处理说明按该结果生成。尚未填写不能视为零。

普通处理表单不再办理关联此前报废，历史关联事实保留只读。已知涉及此前报废的旧异常须核对实物与原记录后通过保留的历史结算接口办理；超过当前盘量的异常在普通表单阻断，但数量未超限也不能证明历史实物互不重叠。此关联属于最终数量结算，不是可在处理后补填的备注；数量规则由 Production 所有者维护。

工作台并列提供现场单盘建卡和批量预生成。单盘成功后保留本任务刚使用的盘量作为下一盘默认；切换任务恢复初始值。批量填写本次分盘总量与标准每盘数量，预览完整盘、尾盘及合计，不自动套用任务计划剩余量。生成结果中的卡号与范围以服务端返回为准；打印失败从本批结果或追踪卡管理选择原卡补打，不重新建卡。

批量追踪卡终检展示当前剩余盘量并据此一次确认产出；研发任务无追踪卡，最终可用产出仍留空，须据实填写并区分零与尚未填写。最终确认前的盘量更正在原卡上办理，标签补打沿用原码。

## 跨页定位与详情归属

任务页的工序入口统一进入 `/production/tracking?batchId=...`；工作台、追踪卡和报工历史使用同一份卡详情展示。追踪页可用 `cardId` 精确定位卡，`stepRecordId` 定位站点，`view=history` 定位报工历史。定位只在新目标到来时消费，缓存返回不重复刷新或重开详情。

建卡、随盘异常、处理、盘量更正与终检各自冻结提交对象和版本；浏览其他卡不改写正在填写的对象。批量生成冻结任务、人员和两项数量，整批沿用一个提交意图。未知结果保留原提交内容与请求标识，重试仍使用原意图；确认放弃前须先核对相关事实。

标签仅打印 Code128 条形码及完整卡号，条纹编码使用[任务内卡号规则](../../api/src/modules/production/docs/database/execution-traceability-quality.md#任务内卡号)定义的短码，下方文字保留服务端返回的完整卡号；扫码与手输均由服务端定位原卡。不包含任务标题、盘量或人员等信息，更正盘量无需更换标签。批量打印冻结本次选择的卡号，预览中可全选或选取部分；追踪卡管理的选择只属于当前列表页，翻页或刷新时清除。预览不随其他卡浏览或列表刷新替换打印对象。

追踪卡通过[公共打印代理](../../../packages/printing/README.md)连接操作电脑的 C-Lodop 服务，单盘建卡并到站和批量预生成在服务端确认成功后静默提交标签；批量打印不改变未到站状态。打印设置归本机浏览器及站点，跨工作台和追踪页共用，只保存打印机名称、纸张毫米尺寸与份数；默认 60 × 40 mm、每卡一份，不保存业务载荷或凭据。打印机必须显式选择，不回退到系统默认设备。SVG 预览用于核对条码内容，原生打印按纸张尺寸排列并可能换行；实际纸面布局与扫码效果须用目标设备验收。

常规生成入口在首次建卡前检查设置与代理可用性；已有未知建卡结果仍优先沿原请求恢复，不因打印机故障阻断事实核对。业务成功与打印提交分别呈现，打印失败不回滚建卡或再次生成编号；保留原卡供补打。代理确认只表示打印命令已提交，不能证明实际出纸；回执超时须先核对打印队列和实物，再人工决定补打，不自动重发。保存设置也不自动恢复建卡或补打。

Vite 开发模式的单盘与批量入口另提供仅生成操作，跳过打印机检查、打印占用与自动打印，供开发调试使用；生产构建不提供此入口。该操作仍调用原业务命令，单盘仍登记首站到站，批量仍只预生成；打印选择随本次提交冻结，未知结果重试沿用原选择。

任务中的产出与入库入口展示同任务产出来源、有效数量及入库归属；勾选的是整笔待入库产出，新建目标按本次选择共用，已有目标限定本任务。切换任务须清除未保存选择；未知结果沿用冻结的产出 ID、目标和请求标识。成品单号打开真实入库主单，身份与旧地址处理见[路由规范](route-dialogs-and-tabs.md#3-联动流程)；从入库明细查看生产来源进入同一工序追踪页。
