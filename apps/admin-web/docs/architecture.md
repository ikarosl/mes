# 管理端前端架构规范

本文维护前端状态所有权、候选生命周期、刷新和竞态规则。显示见[视觉设计](visual-design.md)，接入见[路由与标签页](route-dialogs-and-tabs.md)，协议与错误见[HTTP 错误处理](http-error-handling.md)及[公共 API 规范](../../../docs/api-conventions.md)。业务规则沿专题链接读取所有者文档，不在此维护另一份状态机。

## 1. 分层与状态所有权

页面组合列表、候选和 editor；API wrapper 只转换协议，展示组件不请求数据或编排写入。列表查询／分页、候选、ID 绑定详情、编辑草稿和写意图分别持有状态，不用一个 `loadData()` 刷新一切。

候选读取状态由消费方局部持有；同一路由内确需共享相同契约、参数和有效性的读取时，由最近共同消费者持有。跨路由不共享可变候选状态，不引入全局缓存、TTL 或失效传播。ID 绑定详情始终由对应 editor 持有，不因使用相同接口而共享。

使用 `useXxxList/Options/Editor` 区分职责，`loadXxx/refreshXxx` 按资源命名。通用组件当前由 `src/components` 所有；出现第二个独立前端消费者且 API 稳定后才评审提取 workspace UI 包。

管理端的业务日历日期以 `YYYY-MM-DD` 原样处理，不因浏览器时区平移。API 时刻必须有 `Z` 或显式偏移，展示统一换算为北京时间；日期时间控件以北京墙上时间显示和编辑，提交时明确转为 `+08:00`。日志范围筛选、通知、审批、详情和打印遵守同一边界，不依赖浏览器本地时区。公共转换位于 `@company/utils`，管理端 `src/utils/date.ts` 只处理空值和控件适配。

## 2. 草稿与关键详情

区分尚未加载、合法空结果和加载失败；只有契约允许的空结果才能开始空白编辑。失败不能转换为可保存的空明细覆盖服务端。完整明细要求逐页读齐时，任一页失败都不能提交部分集合。

刷新候选或上下文不得覆盖输入。草稿保存开始编辑时的对象、版本及核对令牌；远端变化应保留草稿并阻止旧依据提交，用户确认重新加载才替换。只更新版本号后提交旧 body 会掩盖并发冲突。

## 3. 读取竞态与取消

读请求写入成功、错误、loading 前均校验请求代际和当前对象身份。关闭、切换目标、失活或销毁使旧读取失效；取消不提示业务失败、不重试，并结束其加载状态。AbortSignal 仅减少无效请求，不能替代身份守卫；不为业务写命令注入读取取消信号。

列表和详情可分别使用 [useLatestReadRequest](../src/composables/requests/useLatestReadRequest.ts)。只提示当前有效请求的错误；写后仅刷新仍选中且仍激活的原对象，不强制切回旧目标。处于失活或关键详情加载中不得基于旧详情提交。

## 4. 选择组件与候选契约

### 4.1 存量 options 设计：停止使用与维护

自建 options 设计属于存量遗留：禁止新增消费方、维护、扩展或增强该方案。范围是 [useRefreshableOptions](../src/composables/options/useRefreshableOptions.ts)、[composables/options](../src/composables/options/) 下现有资源封装、模块内以它为基础的 [useWorkOrderOptions](../src/views/production/composables/useWorkOrderOptions.ts)／[useProcessStepOptions](../src/views/product/composables/useProcessStepOptions.ts)，以及 [buildLiveOptions/hasUnavailableSelection](../src/utils/live-options.ts) 配套的已选值合并、缺项判断与激活／下拉展开自动刷新接入。存量页面尚有依赖，随消费方逐步替换后再移除，不能直接删除使现有页面失效；迁移状态见[路线图](../../../docs/roadmap.md#选择组件与刷新策略存量替换)。

存量工具每次 `refresh()` 都发新请求，不合并在途请求，也没有全局候选缓存；请求代际保护最后一次响应，失败保留本实例上次成功快照并局部提示，消费方另查状态，不能将 await 返回当作成功。部分存量封装使用远程关键词及 `includeIds`，停用范围包括这些封装，不仅限于“全量下拉”。

停用范围不包括 Element Plus 的 `options` 属性、普通候选数组、共享静态枚举、[RemoteSearchSelect](../src/components/RemoteSearchSelect.vue)，或读取取消与请求代际保护。后端 `/options` 端点本身也不在停用范围，契约仍由[公共 API 规范](../../../docs/api-conventions.md#5-列表选项与批量操作)及模块所有者维护。

### 4.2 选择组件标准

| 候选性质 | 接入方式 |
| --- | --- |
| 稳定状态、类型等静态枚举 | 直接使用 `@company/constants`，不发候选请求 |
| 持续增长或难以本地定位的业务候选 | 使用服务端远程搜索，按契约采用分页或有限窗口；已选项单独解析 |
| 明确小规模、有界的动态候选 | 消费方局部加载并提供显式刷新，读取触发按已批准场景确定 |

新增或替换选择组件遵守以上方式，不接入旧 options 工具，也不续建通用候选缓存或已选值合并框架。选择展示与业务资格分开，后端命令仍独立校验权限、状态、选版及当前可选资格。

### 4.3 已选值、失败与草稿

业务筛选不改写原始读取结果。加载状态与候选数组分开；列表、候选或编辑详情的单独失败不能使整个页面互相失效。候选请求由消费方接管局部错误，避免后台刷新触发全局 403 跳转；不静默吞掉有效请求的失败。

**完整候选集缺失**才可认定已选项失效：保留原 ID 并显示“已失效”，阻止保存。分页、搜索或窗口候选未包含选中项不表示失效，须以 includeIds 或已选 ID 解析核验。第一次读取失败不可把空数组当可用结果；高风险操作按自身契约要求最新核验成功。

[RemoteSearchSelect](../src/components/RemoteSearchSelect.vue) 复用 Element Plus 的远程输入能力，统一有限搜索结果、空态、失败重试和已选名称兜底；组件只接收展示数据并发出事件，不内置请求或业务资格。候选窗口、已选解析和取消由消费方的读取逻辑持有，草稿初始化依据由详情提供，不能依赖一次搜索结果拼齐。迁移保留已选身份、必要草稿和旧响应保护，不用 `hasUnavailableSelection` 对搜索窗口缺项直接判失效。

## 5. 写意图与错误

[useIdempotentIntent](../src/composables/idempotency/useIdempotentIntent.ts) 由当前 editor 持有；API wrapper 不生成键。首次正式提交才生成加密随机 UUID，同时锁定首次 body、路径／查询参数、版本和令牌；前端稳定签名只判断内容变化，不替代服务端指纹。`intentType` 不是 scope 版本，不发送 `Idempotency-Scope` 或 `X-Api-Version`。

结果未知保留原键和原请求，阻止修改后静默换键；损坏结果和超过首次尝试 12 小时的意图须先核对业务结果。关闭／换对象／关闭标签前明确处理未保存输入和放弃本地重试标识的风险，提交中禁止关闭；`submitting` 防并发提交与幂等恢复状态分别控制。

当前意图仅驻留内存：KeepAlive 可以保留，硬刷新不能恢复。会话变化销毁旧意图，不把明文业务载荷或仅一个键写入 sessionStorage 冒充可恢复提交。完整恢复与清除条件见 [API 幂等契约](../../api/docs/idempotency.md#9-前端键生命周期)，自动重试和错误提示见 [HTTP 规则](http-error-handling.md#4-基础请求与重试)。scope 不兼容调整遵守[开发重置](../../api/docs/idempotency.md#13-scope-版本与开发重置)。

## 6. 生命周期与定向刷新

所有路由页面首次进入时读取初始数据；切回 KeepAlive 缓存页面只恢复当前展示、分页、展开状态和草稿，不自动刷新列表、候选、详情或办理上下文。需要更新时使用页面或弹窗的刷新／查询入口。筛选、翻页、明确打开对象、处理新的路由定位、提交前核验及写入成功后的定向刷新继续按业务触发，不依赖激活生命周期。

`onActivated` 可以恢复读取资格和 DOM 观察器，或处理尚未消费的新定位；同一已消费定位不能因切回页面重新读取或重开已关闭弹窗。失活继续取消无效读取，成功、失败及 finally 均须检查请求代际。首访读取被中断时，返回保留可操作的刷新／重试入口，不将未完成读取当作合法空结果。

- 初次读取只注册一次。使用 [usePageInitialLoad](../src/composables/requests/usePageInitialLoad.ts) 或所属资源的挂载／目标初始化入口，避免首访重复请求。
- 手动刷新保留输入、已选身份及未确认写意图；确认写成功后只刷新受影响资源，不替换已打开动作弹窗的冻结依据。缓存数据不证明当前办理资格，提交前核验及服务端版本校验继续有效。
- 同一任务刷新保留展示至新数据到达，切换任务先清空。报工刷新失败清空旧操作依据并阻止写入；只读追溯可保留旧展示但必须标出失败。读取取消不能伪装成功或遗留永久 loading。
- 多个展开项的读取遵守[共享 HTTP 并发约束](http-error-handling.md#4-基础请求与重试)，请求所有者继续负责取消及过期响应隔离；不使用时间节流丢弃不同资源请求。

任务只读详情与独立工序管理弹窗在打开时读取，之后通过明确入口手动刷新；工序编辑器不因下拉展开刷新候选。负责人及 SOP 等候选在筛选展开、创建／编辑表单打开或对应选择框展开时按所属场景读取。旧 options 方案的替换仍由[存量替换](../../../docs/roadmap.md#选择组件与刷新策略存量替换)独立推进。

成品目录每行对应独立成品记录，名称相同也不按名称或分类合并。列表、搜索、筛选、分页和总数直接消费成品分页接口，不把分组分页在浏览器内铺平，也不提供分组视图。新增与编辑均面向单个成品，名称不受同名记录限制，分类继续遵守 BOM 锁定约束。

物料目录保留基础物料与版本层级。分页列表只读取基础物料摘要和版本数，初次进入及查询、重置、翻页时全部收起；明确展开后才挂载该组版本面板，逐组独立加载、失败与重试，合法空明细与加载失败分开展示。版本管理明细包含启用和停用版本，不使用仅返回启用版本的业务候选接口。逐行展开与“收起全部／展开所有”同步同一状态，批量控制仅作用于当前页。

同页刷新及写入成功先更新摘要列表，再只刷新仍展开的版本明细；折叠项不预取。切换目录 Tab 及缓存返回保留仍在结果内的展开选择，包括全部收起；缓存返回同时保留已读明细。显式刷新取得新摘要后，才刷新仍展开的明细。折叠、离开物料 Tab、查询目标变化、页面失活和销毁使对应读取取消并失效；重开可重新读取最新版本，不共享全局缓存。当前有效的明细失败在所属组提供重试，不触发全局跳转。摘要读取失败保留旧列表及展开选择，旧请求不得回写或报错。展开控制只在物料目录显示。

生产追溯的工单导航按工单独立展开／收起，默认全部展开。折叠只隐藏所属批次入口，不触发读取、不清空当前批次选择或改变右侧详情；同工单刷新及缓存返回保留折叠选择，新出现的工单默认展开，移出当前查询或分页结果的工单清理其折叠记录。工单号、产品与批次数在收起时仍保留，折叠按钮支持键盘操作并同步展开状态。

## 7. 权限消费

页面权限控制菜单、路由和整页；前端按钮可见性不代替后端命令鉴权。权限目录、页面宿主及权限归属由 [Identity 权限目录](../../api/src/modules/identity/docs/database.md#14-permissions)维护。候选端点的 any-of 权限应覆盖契约登记的所有合法宿主页，每个页面的最小查看角色均能读取所需候选，不额外要求无关主数据管理权限。候选失败局部处理；这不代表放宽服务端安全边界。端点与消费权限矩阵以 API 契约及元数据为准，不在本文复制目录。

生产任务页与生产报工记录页分别消费各自的查看权限；报工记录菜单、路由及工序专检到报工记录的跳转统一按目标路由准入。报工记录页内的历史、专检、执行核对、产出与收尾共享读取以 [Production 接口矩阵](../../api/src/modules/production/docs/database/execution-traceability-quality.md#http-读取权限与消费者)为准，不要求额外取得任务页面权限；动作仍由后端逐接口鉴权。

角色权限配置按服务端 `parentId` 构建目录，不用固定层数判定模块、宿主或动作。任意节点均可查看自身及后代详情，包括首页、通配权限等独立根节点；接口元数据为空不表示该节点只是分组。勾选父节点是同时选中本级和全部下级的批量操作；勾选子节点会显式补选其各级祖先自身权限，不扩选祖先的其他分支。加载已有分配、重置及保存时同样补齐已选后代的祖先，保存每个实际选中的权限 ID。父节点用半选状态表示当前集合不完整，半选不排除该节点自身权限的提交。取消节点会移除其自身及全部后代，保留祖先自身权限；撤销祖先权限须取消该祖先及其分支。界面明确说明目录层级不表示后端授权继承，服务端仍逐项鉴权。

跨页面快捷入口按目标页面查看权限渲染：纯跳转按钮无权限时不渲染；承载单号、行号、批次号或检验记录 ID 的链接无权限时保留相同的普通文本。使用 [useRouteAccess](../src/composables/useRouteAccess.ts) 读取目标路由的 `meta.permission` 并调用认证 Store，避免重复维护 any-of 权限集合；既有单权限入口可直接使用 `auth.can`。跨页面能力以弹窗打开时同样检查所需查看权限；不能因宿主页可见就推定其他页面能力可用。路由守卫和后端独立鉴权继续兜底。审批页面准入不等于具体审批记录可见，实例范围继续由后端裁定；这不要求对页面内业务命令按钮进行细粒度权限隐藏。

## 8. 业务编辑中的特殊边界

### 审批、BOM 与通知

业务责任和访问范围见 [Approval](../../api/src/modules/approval/README.md)、[Product](../../api/src/modules/product/README.md)及 [Notification](../../api/src/modules/notification/README.md)。前端须避免以下误导：

- 流程配置读取场景给出的业务人员来源和最终节点要求，不硬编码工单字段或某张工单人员。切换分派类型清空无关值，排序／删除后重新校验最终节点；发布当前修改过的草稿。配置只存来源规则，人员送审时确定。
- 详情区分节点候选、送审确定人员和实际决定者；不把角色候选变为逐人任务。以服务端 `canApprove/canWithdraw` 及 `currentStepId + version` 提交；失败后刷新当前详情／列表，已失权限则清空并关闭，旧请求不得影响新目标。
- 成品列表刷新时按成品 ID 同步已开 BOM 和详情的状态与版本；远端变化不能覆盖脏草稿。BOM 未保存不能送审，在审／已批准的只读约束由最新服务端状态决定。成品启停确认同时显示名称与完整编码，避免同名成品误操作；审批中禁用编辑和启停入口。
- 通知纯文本展示，结构化 target 经集中映射跳转，不执行通知内 HTML／URL，也不从事件名推断权限。仅预览不标已读；点击正文仅保存已读，详情入口按目标页面权限显示。点击详情先核对页面权限并保存已读，成功后再次核对权限再跳转，失败保留未读；无目标页面权限仍保留正文及标已读功能。后端仍判断记录访问资格，目标失去访问资格不回滚已读。
- 铃铛列表每页 10 条，打开／显式刷新取列表，每 30 秒只刷新未读数；退出／会话变化清除计时器、数据及旧读取资格。当前没有全读、推送或跨标签列表同步承诺。

受审内容由 `ApprovalSubjectEvidence` 统一装配 BOM、需求更正和结案的纯展示组件，只消费快照及显示引用；流程、处理记录与决定事件仍由审批详情容器负责。[开发演示页](../src/views/approval/demo/README.md)复用同一证据展示和详情弹窗，使用独立 mock 数据及内存状态，不调用业务 API。其路由仅在开发环境注册，不进入业务菜单或正式构建。

审批验收情景保留在 [README](../README.md#审批交互与验收场景)，不把实现接入当作已通过。

### 生产任务概览与工序管理

成品目录不配置产品默认工艺路线。新建批量任务须由人员逐次选择路线后才能保存，不自动取产品关联或候选首项；切换工单清空路线与工序预览，候选迟到或刷新不得补选路线。选择路线后才读取对应工序预览。研发任务不选择路线；编辑既有任务只读展示其冻结的路线编码与版本，不用当前路线候选覆盖历史，也不因历史路线停用阻止编辑其他允许修改的字段。业务资格由 [Product](../../api/src/modules/product/README.md) 与 [Production 批次文档](../../api/src/modules/production/docs/database/work-orders-and-batches.md)维护。

任务详情只读，任务操作由列表入口进入独立弹窗。批量任务的工序管理保留派工、改派、撤回派工及参考文件设置，不并入生产报工记录页，研发任务不显示该入口；子编辑器与工序管理弹窗并列挂载。当前阶段的常用动作优先显示，物料及低频动作收在更多菜单，入口收纳不改变服务端办理资格。

任务概览展示业务身份和实际人员姓名，不展示技术版本号或人员 ID；工艺路线及其版本归入详情。批准产出与各工序报工量、实际入库量分开，尚无批准清单不能显示为零；任务数量只展示计划和批准产出，不从任何工序报工量推算。开工物料快照是历史依据，不表示当前齐套情况；阶段提示不将分配或出库当作开工前置条件。

列表摘要、任务概览、工序管理和历史开工记录分别读取；接口边界由 [Production 批次文档](../../api/src/modules/production/docs/database/work-orders-and-batches.md)维护。开工记录首次展开时加载，说明与物料快照共用历史查询，同任务收起再展开可复用已加载记录，手动刷新重新读取。关闭、换任务或页面失活取消过期读取，返回缓存页不自动刷新。

工序管理的工序、人员和参考文件候选分别读取并局部报错；文件列表需要逐页读取完整后才可用，任一页失败不以部分列表推断失效。任务编辑先读取概览并保留开窗时的版本，工序编辑保留开窗时的工序及版本；手动刷新不自动换版本提交旧输入，发生冲突后先核对当前事实并明确采用新依据。当前派工和参考文件命令没有幂等重放能力，未知结果先核对，不自动重试或伪造幂等键。关闭、换任务或关闭标签时保护草稿与未知结果，提交中禁止关闭。

### 生产需求、收尾与库存

任务页与执行页复用管理员开工交互：读取当前配置与缺料预览，配置前提不足时展示服务端阻断原因；研发无需 BOM 的提示不能暗示无需手工需求。缺料仅提示且说明必填；提交携带预览版本，未知结果保留原请求与幂等键。任务开始与工序开始分开，普通工序按钮消费服务端资格。物料可分次办理，不展示短批授权入口，也不从执行阶段推断“物料操作已完成”。

收尾未批准、无在审时显示“撤回结束”，预览服务端给出的恢复阶段并填写原因；不提供任意状态选择。恢复后统一刷新任务、物料、工序及收尾资格，历史根存在不代表仍可办理产出或检验。操作保护现有草稿与未知请求；已发生的收尾事项不自动恢复。历史行动可展示任务进入／撤回，但逐项处理不提供任务操作项。

业务依据见[任务需求](../../api/src/modules/production/docs/database/demand-allocation-and-outbound.md)、[逐项收尾](../../api/src/modules/production/docs/database/production-termination.md)和 [Inventory](../../api/src/modules/inventory/README.md)。本文只保留编辑或显示时容易混淆的边界：

- 需求追溯与更正编辑分开：只读追溯沿真实替代关系展示完整链，所选记录和最新记录在对应行标识，顶部不重复堆叠相同身份与汇总；不用 ID 大小推断先后。历史数量逐记录展示，不将旧剩余与新需求累计。更正入口明确定位最新需求，并重新读取服务端资格；错误、刷新要求和不可更正原因始终保留。人工追加原因注明来源单和创建时间，保留原始填写内容，不将历史备注当作系统操作提示。编辑器区分目标总量、新剩余量和整条替代链已领量，逐项说明阻断，不能把未分配说成未领完。审批详情继续展示提交时的冻结证据，不以当前追溯覆盖旧快照。
- 初始需求配置的搜索及未选版筛选只改变展示，不能清除已选版本或采购提示；退出未确认修改须保护草稿。选版进度不代替最终提交资格。需求总览与物料分配按服务端提供的完整 `generationGroupKey` 在前端组装动作分块，默认全部展开，支持逐块及全部展开／收起。同一任务刷新保留既有块的折叠选择，新增块默认展开；重新打开或切换任务恢复默认。折叠仅隐藏需求表，块头保留身份、生成时间和条数，不触发读取或清除已选需求、分配输入及子编辑器草稿。同一来源单的原始生成与更正生成分别展示，不能按来源单号合并，也不解析分组键推导业务信息。块头区分动作、来源单号和本次生成时间，替代关系使用接口明确提供的需求关联。原始 ID 明确显示为 `id:{id}`；“未领”读取需求事实剩余量，终态标为历史余量；未分配缺口仅作为活动需求的分配信息，采购关系不计入已领量。来源说明保留人工原文，生成时间独立按北京时间格式化，不从说明文本或单号提取时间。采购关联交互见[采购前端约束](procurement-inbound.md#33-需求相关采购)。
- 需求总览、变更追溯及更正编辑打开时读取，随后由手动刷新或本页写入成功定向刷新；缓存页返回不自动读取。关闭、换目标或页面失活使在途读取失效，旧响应不得回写。更正编辑刷新保留输入并分开新预览与提交依据，依据变化须明确采用，不能替换版本后自动重发；关闭父窗口、换需求与关闭标签均保护子编辑器草稿和未知请求。更正中的行仍展示实际缺口，不因暂不可办理删除事实。
- 服务端保存的补料方案 `draft` 已是业务记录；重开先展示真实已存版本、数量及对应任务冻结版本，明确进入编辑后才能修改，不能用空表单覆盖。批量补料消费候选中的 `lockedMaterialVariantId/lockedMaterialVariantCode`；新行由人员显式选择冻结版本，其他启用版本不可选，冻结版本停用时阻断，不自动换版。旧草稿版本失效、不一致或原需求退出候选时仍保留原值并显示原因，所有已选行均有效才能暂存；候选核验失败或复核有无效行时禁止首次最终确认。结果未知只重试原请求和原幂等键，不能因当前候选变化阻止原请求重放。人工追加的物料、版本、数量仍由人员明确选择。
- 新增任务的工单额度刷新失败保留输入并阻止提交，重核新额度不覆盖本次计划数量。工单号和任务批次号由服务端产生，界面不收取手填编号；未知创建结果不得因改表单自动另建。
- 收尾核对响应先验证结构及任务归属；JSON `null` 才表示无逐项收尾记录，须结合结束记录决定开始表单或只读结束快照。缺字段不是空记录；只读加载可关闭，写入中不可关闭。按钮“提前结束”只打开表单，确认开始命令才停止生产。
- 收尾事项各自保留备注。快捷处理逐项发送、每项刷新版本，失败即停，既有成功不回滚；未知结果只重试原项，不自动继续整组。依赖顺序以服务端阻断为准，不能并行发送制造部分成功后仍称整组完成。
- 产出与收尾编辑器分别持有草稿；审批中只读，驳回／撤回不撤销已发生的物料处理。损坏实核、质检引用和成品入库的额外约束见[成品专题](finished-inspections.md)。
- 物料供需每行是 `materialVariantId`，需求来源读取必须同时传该行 `itemId + materialVariantId`，不能用基础物料合计替代精确版本。库存批次按物料与成品分为独立页签，各自保留筛选、分页及列表，查询始终通过服务端 `itemKind` 限定身份，不提供混合身份筛选；切离页签立即使旧读取失效。物料批次展示名称与详细版本编码，成品批次展示名称与成品编码；成品不展示预留／可分配列，库存状态根据账面可用量判断。供应方、来源工单和任务缺失不得直接解释为多来源，须结合实际入库明细区分未记录、无关联、部分关联与多个来源。批次深链接先读取详情，再按详情身份选择页签；来源单据只在目标页面支持真实入库单 ID 定位且具备查看权限时提供跳转。
- 退料说明长期可见、含警示标识：“退料不会产生或恢复需求”；不提供保留给原任务的策略。来源文字使用服务端 `sourceLabel/sourceDocumentNo`，不能根据缺少入库单号猜为期初库存。
- 展示区分执行报工、批准产出与实际入库；`finalOutput=null` 是尚无批准清单，批准零量正常显示零。历史／更正草稿不重复汇总，已终止任务释放计划额度不抹去其有效批准产出。

报废补产的显示只消费服务端投影：固定路线首工序起点不可伪装为可选；材料补料与产品补产数量分开，禁止用物料合计或 BOM 换算替代产品量。执行记录、员工任务及报工弹窗保留计划投入和授权摘要；三处的上限说明统一使用“报工上限 = 计划 + 已报废补产”，后者只消费已满足生效条件的授权，有值的待生效授权另列“待生效报废补产”，生效条件可通过提示查看。来源工序、建议路径和激活条件应可见，未履约授权不能计入统一上限。相邻工序数量差异只提示，补料生效不自动重开工序；已完成工序新增报工须先重新开工。不得逐工序请求或自行遍历报废记录重算。

执行记录的生产批次栏持有输入草稿与已应用筛选；点击查询或按 Enter 才应用去除首尾空白的关键字并回第一页，重置清除筛选并回第一页。翻页和手动刷新使用已应用筛选，按批次号、工单号或产品搜索；每页固定 10 条，使用服务端分页，显示总数及当前页，不使用虚拟列表或下载全量。

本人工序列表的筛选草稿与已应用条件分别持有；状态复用共享可见状态集合与名称，默认全部，单号使用文本输入而不读取动态候选。查询或 Enter 才应用筛选，重置清空筛选；两者回第一页并保留每页条数，翻页和手动刷新沿用已应用条件。查询、重置和翻页先保护报工草稿及未确认写意图，取消确认不改变生效条件或分页，失活使等待中的导航和读取失效；手动刷新保留编辑器快照。结果缩小导致页码越界时读取最后有效页，全空时归第一页，失败清除旧操作依据并保留筛选以便重试。列表消费服务端固定顺序，不按开完工状态重新排列；启用状态筛选时明确提示状态变化可移出结果，筛选空态与未分配工序分开表述。筛选、顺序及数据范围由 [Production 执行查询](../../api/src/modules/production/docs/database/execution-traceability-quality.md#执行查询与分页)维护。

查询、重置、翻页和切换批次先保护现有报工草稿及批量写意图；取消确认不能改变生效筛选、页码或任务，失活或目标变化使等待中的导航失效。列表读取期间阻止开启新的写入编辑器；空结果清除当前读依据，失败清除旧列表、详情及完工检查并提供重试，同时保留已有草稿和目标 ID。重试成功重新读取当前详情。手动刷新保留目标，分页窗口缺项时按目标 ID 核验，不能自动换任务；总数缩小使当前页越界时读取最后有效页，读取失败归第一页，不让分页组件的自动页码校正触发额外查询。

执行记录收纳次要信息时，任务身份、完成进度、主要完工结果或阻断和完工入口仍可见；审批冻结和未知提交结果不得隐藏。工序支持多道展开，初次取得当前任务时优先展开第一道执行中工序，否则展开首道；同任务刷新、全部收起和缓存返回均保留人员选择，切换任务再初始化。收起的工序仍保留身份、状态、负责人以及正常、已报废、处理中和剩余额度摘要，上限组成和有值待生效报废补产继续提示；收起不改变服务端业务资格。

工序正文首次展开才挂载报工表并读取，后续收起保留表实例及分页，暂停并失效在途读取，再展开刷新当前页。“全部展开／全部收起”仅控制当前任务的工序正文，沿用单道展开的读取与保留规则，不改变工序内部数量核对、异常处理分组等局部展开选择，也不扫描历史分页。折叠不清除跨工序已选报工、编辑草稿或未知写意图；异常面板只隐藏摘要入口，已打开的异常过程及处理 Dialog 与正文并列保留。折叠只收纳展示，不隐含提交、放弃或追加选择。

执行记录与本人工序列表的工序摘要采用各自授权接口同一快照的额度分类，显示正常、已报废、处理中和剩余可报。不显示直接已报／上限及百分比，也不在主摘要显示累计直接异常或历次异常。分类展示须同时满足服务端可信标记、非负安全整数和包含终止残量的数量守恒，不合并外部返工读取、汇总报工分页或补差额；上限为零正常显示零值，未知分类显示待核对并保留原因，执行记录保留真实报废明细入口。员工列表复用纯展示数量摘要和上限组成，正常来源直接展示“直接正常 + 返工正常”，保留既有记录与纠错入口，不为展示新增管理端读取或搬入未接通的详情动作。已终止未恢复有值时独立展示，不归正常、报废或处理中。执行记录的处理中有值时可展开同快照的待审核、待返工和返工中明细及真实来源报工引用，零量弱化提示无待处理异常；已终止处置和已取消返工仍保留真实记录。执行记录正文仅保留直接正常与返工恢复的正常来源，前道正常数量及与前道的差值收进“数量核对”，首道不显示不适用核对；不展示建议正常目标及目标差值。局部展开同任务刷新和缓存返回保留，换任务清空。

报废详情使用独立只读 Dialog，实际报废非零或分类待核对时均可打开。列表按当前批次及工序授权分页，默认 10 条并可选择 20、50 条；切页大小回首页，读取越界只修正当前窗口，失败清除旧列表并保留重试。展示真实事实、来源报工及异常处置、说明、记录人和时间，以及实际存在的补产授权与补料关联；仅有事实 ID 时明确标注，不伪造业务单号。来源报工打开与报废 Dialog 并列的报工追溯，关闭来源详情可继续原报废上下文。关闭、换任务、切目标、失活和销毁失效旧读取，缓存返回保留展示，明确刷新时只读取仍打开的目标；不按角色名称硬编码入口。

普通正常及异常新增共同消费服务端报工资格和剩余额度；额度为零或工序已完成时禁用入口并显示具体原因，已完成工序须先重新开工。既有记录纠错不要求重开，已批准结束任务的管理员纯正常历史补录继续使用独立历史资格，未批准收尾须先撤回结束再补报，不能成为执行期间绕过完工状态的入口。任务的工序管理与生产追溯仍保留各自的直接已报进度，返工恢复不重复计入直接报工；比例及额度分布都不代表自动完工或质量放行。当前负责人不覆盖历史报工人，状态履历读取 Production 专有事实；批准时数量与当前数量分开展示。员工页直接展示普通工序列表，不保留本人返工 Tab 或专用返工请求；普通报工、状态动作、SOP、分页和记录纠错仍按本人工序资格办理。返工办理和详细追溯集中在管理端异常处置流程，批准时来源工序负责人仅作快照展示，不暗示该员工承担返修；具体权限由 Production 所有者规则维护。

报工弹窗从开窗冻结的同一授权工序快照展示额度分类、正常来源及上限组成；不重复展示直接已报、百分比、建议目标或异常发生历史。管理员消费执行投影，员工消费既有本人任务投影，不额外请求管理端数据或跨读取混算；未知分类照实显示待核对及原因。摘要使用纯展示组件，详细报废和处理入口留在记录页，分类不纳入写依据判定或幂等请求；刷新后不能把最新分类与旧冻结额度拼接。本次最多来自冻结余额及共享单次上限；未确认结果、关键依据失效和历史补录的必要提示继续可见。

正常与异常报工及正常数量更正持有原始文本草稿，输入、失焦、上下文刷新及缓存恢复均不自动截断到额度、取整或改成零。必填、正整数、共享单次报工上限与剩余额度错误在字段处显示，非法输入禁止提交，处理器再次核验后才转换为数值载荷；Enter 不能原生提交导致整页导航。关键依据变化保留输入并阻止旧依据提交，未知结果锁定原数量、版本和请求供安全重试，不按新额度改写原意图。

普通正常报工更正只提供一个正常数量输入和必填原因，明确填写替代记录的完整数量；零量取消使用全量冲销，不自动改为冲销意图。弹窗按冻结快照展示原量、更正后数量及额度影响，不提供正常／异常转换或异常来源输入。普通异常仅走待处置整笔驳回重报；返工完成一次提交正常与再次异常，系统分别生成非零结果事实，各自展示真实完成报工引用，均不提供普通更正、冲销或驳回入口。返工完成草稿与首次完整请求由页面级编辑器保留，只有确认成功后关闭；同任务读取失败、工序折叠或面板卸载不能丢失未知结果的原始数量、版本及备注。新提交检查当前办理资格，旧请求仅按原载荷和原键重放；关闭、换任务或离开页面须明确处理未保存草稿及未知结果。

工序状态提供正常开始、完成、重新开工及只读状态历史，不提供状态历史更正或撤销误开工；历史已有更正动作仍原样展示，不以移除入口删除或重写履历。

返工结果的对外名称统一为“返工正常／返工异常”，正常来源摘要、报工记录、返工办理和追溯引用共用该命名。报工历史分页加载，只读分类消费服务端 `sourceKind`，不能根据正向事实类型、数量或说明文字推断返工来源。冲销、被冲销原单、更正替代、来源异常和返工结果均消费服务端真实单号引用；仅有事实 ID 时不能伪造业务编号。展示数量的正负号不改变 API 绝对数量、写命令载荷或累计投影。报工详情同时包含记录与处理过程。依赖使记录只读时保留具体原因与统一详情入口，不重复堆放不可办理的更正／冲销按钮。

执行记录的工序正文仅保留异常处理过程的待办数、记录数和“查看 / 处理”入口，明细在独立弹窗内展示，任务及工序身份明确。摘要与弹窗复用同一分组和待办判定，待审核或待开始／进行中的返工各按一组待办计数，不能用请求中的操作数量替代。异常过程按真实来源处置或返工分组；弹窗内待审核或未完成返工默认展开，已完成处理默认收纳并保留处置、返工和恢复正常／再次异常数量摘要。异常过程弹窗与审核、报废补料、返工完成及来源详情弹窗并列挂载；关闭过程查看不清除办理草稿或展开选择。批准报废只表示处置决定，不能显示为返工或补料已完成。同任务刷新保留人员明确选择的展开状态，切换任务清空。所有宿主的报工业务来源、结果引用和“查看详情”统一打开包含记录与处理过程的授权单条报工详情；本页与分页外采用相同入口，详情内引用继续切换同一查看目标，不自动展开、滚动或高亮背景工序，也不逐页扫齐历史。只读查看关闭、切换目标、失活或销毁时失效读取，返回缓存页保留展示，明确刷新时只读取仍打开的目标。相关详情与父弹窗并列挂载，边界见[路由规范](route-dialogs-and-tabs.md#1-挂载边界)。

同任务跨工序批量冲销保留明确选中的 ID；工序工具栏显示已选条数及工序数，未选择时弱化提示并禁用预览。选择清单通过独立页面级 Dialog 逐条查看、移除、清空或刷新依据，关闭清单不清除选择，切换任务先沿用导航保护。预览各工序净量及逐条阻断原因，修改选择后重新预览，一次提交原子结果；未知结果锁定选择及原始请求，在工具栏保留醒目的核对入口。同任务读取失败即使清空详情，仍保留该入口和原请求，核对及重试不能要求重新选择或生成新键。清单和批量办理 Dialog 与滚动区并列挂载，不因吸顶、折叠或详情消失而丢弃已有意图。阶段资格和原因消费服务端投影，后端仍独立鉴权；完整规则见 [Production 执行专题](../../api/src/modules/production/docs/database/execution-traceability-quality.md#cp-01-报工整改边界)，待验收见[整改清单](../../../docs/roadmap.md#cp-01报工数量解耦与管理员批量冲销整改)。

## 9. 验证重点

重点验证：首次进入不重复读取同一资源；缓存页面及其弹窗返回不自动刷新，工序编辑器展开下拉不自动刷新候选；远程窗口缺项不误判已选项失效；旧目标成功／失败／finally 不回写；失败保留草稿但阻止无依据提交；跨页读取状态独立；最小页面角色能读所需候选；未知结果不产生新键。
