# 管理端前端架构规范

本文维护前端状态所有权、候选、刷新及并发边界。显示见[视觉规范](visual-design.md)，路由和弹窗见[接入规范](route-dialogs-and-tabs.md)，协议见[公共 API 规范](../../../docs/api-conventions.md)。业务资格、状态机和数量规则由各 API 模块所有。

## 1. 分层与状态所有权

页面组合列表、路由定位和编辑器；API wrapper 只转换协议，展示组件只接收数据和事件。列表查询／分页、候选、ID 绑定详情、编辑草稿和写意图分别持有，不用一次全量刷新替代各自生命周期。

候选由消费方局部持有；同一路由内契约、参数及有效性相同的读取，可由最近共同消费者共享。跨路由不共享可变候选，不建设全局缓存、TTL 或失效传播。ID 绑定详情始终归相应编辑器，不能仅因接口相同而共享。

业务文件按一起变化的能力组织在 `src/views/<业务>`；模块内共享放所属模块 `shared`。Production 与 Template 的跨业务复用通过各自 `public.ts`，路由装配直接引用页面入口。通用状态与生命周期归 `src/composables`，纯计算与格式化归 `src/utils`。组件只有出现第二个独立前端消费者、API 稳定后，才评审提取 workspace UI 包；目录拆分遵守[编码规范](../../../docs/coding-standards.md)。

日期与时刻遵守[公共时间契约](../../../docs/api-conventions.md)。控件按北京时间编辑，不依赖浏览器本地时区；共享转换归 `@company/utils`，应用只适配空值和控件。

## 2. 草稿与关键详情

区分尚未加载、合法空结果和加载失败；只有契约允许的空结果才能开始空白编辑。失败不能变成可保存的空明细。要求读齐完整集合时，任一页失败都不能提交部分集合。

刷新候选或上下文不得覆盖输入。草稿保存开始编辑时的对象、版本及核对令牌；远端变化应保留草稿并阻止旧依据提交，用户确认重新加载才替换。只更新版本号后提交旧内容会掩盖并发冲突。

## 3. 读取竞态与取消

成功、错误和 loading 更新都须校验请求代际及当前对象。关闭、换目标、失活或销毁使旧读取失效；AbortSignal 只能减少无效请求，不能替代身份守卫。取消的传输含义见 [request](../../../packages/request/README.md)。业务写命令不使用读取取消信号，不因页面失活自动取消。

列表和详情可分别使用 [useLatestReadRequest](../src/composables/requests/useLatestReadRequest.ts)。只提示当前有效请求的错误；写后仅刷新仍选中、仍激活的原对象，不强制切回旧目标。失活或关键详情加载中不能基于旧详情提交。

## 4. 选择组件与候选契约

### 4.1 存量 options 设计：停止使用与维护

旧 [useRefreshableOptions](../src/composables/options/useRefreshableOptions.ts)、其资源封装及 [live-options](../src/utils/live-options.ts) 停止新增消费、维护和扩展，包括基于它们的已选值合并、缺项判断及激活／下拉自动刷新。现有依赖随消费方替换后再移除，不能直接删除使页面失效；范围与进度见[路线图](../../../docs/roadmap.md#选择组件与刷新策略存量替换)。

此限制不针对 Element Plus 的 `options` 属性、普通数组、静态枚举、[RemoteSearchSelect](../src/components/RemoteSearchSelect.vue) 或后端 `/options` 契约。

### 4.2 选择组件标准

| 候选性质 | 接入方式 |
| --- | --- |
| 稳定状态、类型等静态枚举 | 直接消费共享常量 |
| 持续增长或难以本地定位的业务候选 | 服务端远程搜索，采用契约声明的分页或有限窗口，已选项单独解析 |
| 明确小规模、有界的动态候选 | 局部加载并提供显式刷新，触发时机按已批准场景确定 |

完整集合、窗口和已选 ID 解析的服务端含义见[候选契约](../../../docs/api-conventions.md#51-候选完备性与增长迁移)。选择显示不能替代命令资格。

### 4.3 已选值、失败与草稿

加载状态与候选数组分开，单个列表、候选或详情失败不得使整页互相失效。候选由消费方处理局部错误，避免刷新失败触发全局 403 跳转；不静默吞掉有效请求失败。

只有完整候选集缺失才能将已选项标为失效，仍保留原 ID 和名称供修正；窗口缺项须另行解析。第一次读取失败不能把空数组当有效结果，业务筛选不能改写原始结果或丢弃已选身份。

远程选择组件只负责输入和展示；搜索窗口、已选解析及读取取消由消费方持有，草稿由详情初始化，不依赖一次搜索拼齐。

## 5. 写意图与错误

[useIdempotentIntent](../src/composables/idempotency/useIdempotentIntent.ts) 由当前编辑器持有，API wrapper 只透传键。首次正式提交生成加密随机 UUID，并冻结完整 body、路径／查询参数、版本和核对令牌；本地签名只判断输入变化，不能替代服务端指纹。

确认成功或契约明确无副作用的业务失败才结束意图。结果未知时保留原键和完整请求，恢复入口不能被新候选或余量挡住，也不能改输入后静默换键。客户端恢复窗口从首次尝试起算，时长遵守 [API 保留期](../../api/docs/idempotency.md#5-数据库记录与保留期)；结果损坏或超窗须先核对业务结果。提交状态与未知状态分别控制。

意图只驻留内存及 KeepAlive，硬刷新无法恢复，会话变化销毁旧意图；不把明文业务载荷或仅一个键写入浏览器存储冒充恢复能力。关闭保护按[标签与弹窗规范](route-dialogs-and-tabs.md#3-联动流程)接入，重试及提示见 [HTTP 规则](http-error-handling.md)。

## 6. 生命周期与定向刷新

路由页面首次进入读取初始数据；返回 KeepAlive 缓存只恢复展示、分页、展开及草稿，不自动刷新列表、候选、详情或办理依据。筛选、翻页、明确打开对象、新路由定位、提交前核验和写后刷新按各自业务触发。

`onActivated` 仅恢复读取资格、DOM 观察器或处理未消费定位；不能因返回而重读已消费定位或重开已关闭弹窗。首访读取被中断时，保留刷新／重试入口，不当作合法空结果。

初次读取只注册一次，可使用 [usePageInitialLoad](../src/composables/requests/usePageInitialLoad.ts)。手动刷新保留输入与意图，写后只刷新受影响资源，不替换已开编辑器的冻结依据。只读旧数据可保留但须标明失败，失效依据不能继续写入；缓存存在不证明当前办理资格。

## 7. 权限消费

页面查看权限控制菜单、路由和整页，不要求页面内操作按钮按细粒度权限隐藏；每个后端接口仍须独立鉴权。权限目录由 [Identity](../../api/src/modules/identity/docs/database.md#14-permissions)维护。

角色权限树按服务端 `parentId` 构建，不假定固定层级。勾选父节点选择自身与全部后代；勾选子节点补选各级祖先自身，不扩展其他分支。加载、重置、保存同样补齐祖先；半选仍提交节点自身权限。取消节点移除自身和后代，保留祖先自身。界面须说明这只是批量选择，不表示后端授权继承。

跨页快捷操作无目标查看权限时不显示；单号等身份链接改为同内容的普通文本。优先使用 [useRouteAccess](../src/composables/useRouteAccess.ts) 读取路由声明，不另维护权限集合；弹窗形式的跨页能力同样核验目标权限。

## 8. 业务编辑中的特殊边界

### 审批、BOM 与通知

业务规则分别见 [Approval](../../api/src/modules/approval/README.md)、[Product](../../api/src/modules/product/README.md)和 [Notification](../../api/src/modules/notification/README.md)。前端额外保留以下边界：

- 流程配置切换分派类型时清除无关草稿；发布使用当前修改，不误发旧保存内容。业务来源和最终节点要求读取场景配置，不硬编码某张工单人员。
- 成品列表刷新按 ID 同步已开 BOM 的状态；不覆盖脏草稿，状态失效时阻止旧依据保存。
- 通知预览、正文标已读与详情导航分开。进入详情先核对页面权限、保存已读，再次核对权限后跳转；成功已读不因目标无权访问回滚，无目标权限仍可阅读和标已读。
- 通知列表按需读取，后台轮询只更新未读数；退出或会话变化清除轮询、数据及旧读取资格，不承诺推送或跨标签列表同步。

审批证据使用业务快照的纯展示组件，处理记录和决定仍由审批详情容器持有；[开发演示页](../src/views/approval/demo/README.md)说明本地模拟边界。
