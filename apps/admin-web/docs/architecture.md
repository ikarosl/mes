# 管理端前端架构规范

本文维护前端状态所有权、候选生命周期、刷新和竞态规则。显示见[视觉设计](visual-design.md)，接入见[路由与标签页](route-dialogs-and-tabs.md)，协议与错误见[HTTP 错误处理](http-error-handling.md)及[公共 API 规范](../../../docs/api-conventions.md)。业务规则沿专题链接读取所有者文档，不在此维护另一份状态机。

## 1. 分层与状态所有权

页面组合列表、候选和 editor；API wrapper 只转换协议，展示组件不请求数据或编排写入。列表查询／分页、候选、ID 绑定详情、编辑草稿和写意图分别持有状态，不用一个 `loadData()` 刷新一切。

同一缓存路由内，契约、参数及有效性相同的候选由最近共同消费者持有一份实例；只有一个消费者则留在局部。跨路由复用 composable 工厂，各自创建实例，不引入全局缓存、TTL 或失效传播。ID 绑定详情始终由对应 editor 持有，不因使用相同接口而共享。

使用 `useXxxList/Options/Editor` 区分职责，`loadXxx/refreshXxx` 按资源命名。通用组件当前由 `src/components` 所有；出现第二个独立前端消费者且 API 稳定后才评审提取 workspace UI 包。

管理端的业务日历日期以 `YYYY-MM-DD` 原样处理，不因浏览器时区平移。API 时刻必须有 `Z` 或显式偏移，展示统一换算为北京时间；日期时间控件以北京墙上时间显示和编辑，提交时明确转为 `+08:00`。日志范围筛选、通知、审批、详情和打印遵守同一边界，不依赖浏览器本地时区。公共转换位于 `@company/utils`，管理端 `src/utils/date.ts` 只处理空值和控件适配。

## 2. 草稿与关键详情

区分尚未加载、合法空结果和加载失败；只有契约允许的空结果才能开始空白编辑。失败不能转换为可保存的空明细覆盖服务端。完整明细要求逐页读齐时，任一页失败都不能提交部分集合。

刷新候选或上下文不得覆盖输入。草稿保存开始编辑时的对象、版本及核对令牌；远端变化应保留草稿并阻止旧依据提交，用户确认重新加载才替换。只更新版本号后提交旧 body 会掩盖并发冲突。

## 3. 读取竞态与取消

读请求写入成功、错误、loading 前均校验请求代际和当前对象身份。关闭、切换目标、失活或销毁使旧读取失效；取消不提示业务失败、不重试，并结束其加载状态。AbortSignal 仅减少无效请求，不能替代身份守卫；不为业务写命令注入读取取消信号。

列表和详情可分别使用 [useLatestReadRequest](../src/composables/requests/useLatestReadRequest.ts)。只提示当前有效请求的错误；写后仅刷新仍选中且仍激活的原对象，不强制切回旧目标。处于失活或关键详情加载中不得基于旧详情提交。

## 4. 候选刷新契约

### 4.1 局部候选实例

[useRefreshableOptions](../src/composables/options/useRefreshableOptions.ts) 的每次 `refresh()` 都发新请求，不合并在途请求；最后请求生效，旧成功、错误和收尾不能回写。最新刷新失败保留本实例上次成功快照并提示；新实例没有兜底缓存。刷新方法自行处理错误、不向调用方抛出，消费方必须检查加载状态，不能将 await 返回当作成功。

### 4.2 选择与失效

业务筛选在消费侧 computed 完成，不改写原始候选。`idle/loading/ready/error` 与候选数组分开；列表、候选或编辑详情的单独失败不能使整个页面互相失效。候选请求由所有者接管局部错误，避免后台刷新触发全局 403 跳转；不静默吞掉有效请求的失败。

**完整候选集缺失**才可认定已选项失效：保留原 ID 并显示“已失效”，阻止保存。分页、搜索或窗口候选未包含选中项不表示失效，须以 includeIds 或已选 ID 解析核验。第一次读取失败不可把空数组当可用结果；高风险操作按自身契约要求最新核验成功。

[RemoteSearchSelect](../src/components/RemoteSearchSelect.vue) 复用 Element Plus 的远程输入能力，统一有限搜索结果、空态、失败重试和已选名称兜底；组件只接收展示数据并发出事件，不内置请求或业务资格。候选窗口、已选解析和取消仍由消费侧 options composable 持有，草稿初始化依据由详情提供，不能依赖一次搜索结果拼齐。

## 5. 写意图与错误

[useIdempotentIntent](../src/composables/idempotency/useIdempotentIntent.ts) 由当前 editor 持有；API wrapper 不生成键。首次正式提交才生成加密随机 UUID，同时锁定首次 body、路径／查询参数、版本和令牌；前端稳定签名只判断内容变化，不替代服务端指纹。`intentType` 不是 scope 版本，不发送 `Idempotency-Scope` 或 `X-Api-Version`。

结果未知保留原键和原请求，阻止修改后静默换键；损坏结果和超过首次尝试 12 小时的意图须先核对业务结果。关闭／换对象／关闭标签前明确处理未保存输入和放弃本地重试标识的风险，提交中禁止关闭；`submitting` 防并发提交与幂等恢复状态分别控制。

当前意图仅驻留内存：KeepAlive 可以保留，硬刷新不能恢复。会话变化销毁旧意图，不把明文业务载荷或仅一个键写入 sessionStorage 冒充可恢复提交。完整恢复与清除条件见 [API 幂等契约](../../api/docs/idempotency.md#9-前端键生命周期)，自动重试和错误提示见 [HTTP 规则](http-error-handling.md#4-基础请求与重试)。scope 不兼容调整遵守[开发重置](../../api/docs/idempotency.md#13-scope-版本与开发重置)。

## 6. 生命周期与定向刷新

- 谁持有候选实例，谁注册激活刷新。页面候选用 `onActivated`，包含首次挂载；不再同时 `onMounted` 请求。正式列表和关键详情可在 `onMounted` 加载。
- 弹窗自持候选在打开、仍打开时再激活、对应下拉展开时刷新；页面下发候选的弹窗用 props／事件消费，不重复注册生命周期。打开可并发刷新必要资源，下拉仅刷新该资源。
- 写成功只刷新受影响列表和详情；列表刷新不替换已打开动作弹窗的确认依据。未知写结果不会因刷新上下文而成为新意图。
- 报工与追溯使用 [usePageActivationRefresh](../src/composables/requests/usePageActivationRefresh.ts)：首访一次，后续激活延迟 150ms，手动操作立即读取，离开取消调度和读取。不要将该延迟扩为路由延迟或禁用 KeepAlive。
- 同一任务刷新保留展示至新数据到达，切换任务先清空。报工刷新失败清空旧操作依据并阻止写入；只读追溯可保留旧展示但必须标出失败。懒加载不能改变这一区别。

## 7. 权限消费

页面权限控制菜单、路由和整页；前端按钮可见性不代替后端命令鉴权。候选端点的 any-of 权限应覆盖契约登记的所有合法宿主页，每个页面的最小查看角色均能读取所需候选，不额外要求无关主数据管理权限。候选失败局部处理；这不代表放宽服务端安全边界。端点与消费权限矩阵以 API 契约及元数据为准，不在本文复制目录。

跨页面快捷入口按目标页面查看权限渲染：纯跳转按钮无权限时不渲染；承载单号、行号、批次号或检验记录 ID 的链接无权限时保留相同的普通文本。使用 [useRouteAccess](../src/composables/useRouteAccess.ts) 读取目标路由的 `meta.permission` 并调用认证 Store，避免重复维护 any-of 权限集合；既有单权限入口可直接使用 `auth.can`。跨页面能力以弹窗打开时同样检查所需查看权限；不能因宿主页可见就推定其他页面能力可用。路由守卫和后端独立鉴权继续兜底。审批页面准入不等于具体审批记录可见，实例范围继续由后端裁定；这不要求对页面内业务命令按钮进行细粒度权限隐藏。

## 8. 业务编辑中的特殊边界

### 审批、BOM 与通知

业务责任和访问范围见 [Approval](../../api/src/modules/approval/README.md)、[Product](../../api/src/modules/product/README.md)及 [Notification](../../api/src/modules/notification/README.md)。前端须避免以下误导：

- 流程配置读取场景给出的业务人员来源和最终节点要求，不硬编码工单字段或某张工单人员。切换分派类型清空无关值，排序／删除后重新校验最终节点；发布当前修改过的草稿。配置只存来源规则，人员送审时确定。
- 详情区分节点候选、送审确定人员和实际决定者；不把角色候选变为逐人任务。以服务端 `canApprove/canWithdraw` 及 `currentStepId + version` 提交；失败后刷新当前详情／列表，已失权限则清空并关闭，旧请求不得影响新目标。
- 产品列表激活刷新时按产品 ID 同步已开 BOM 的状态与版本；远端变化不能覆盖脏草稿。BOM 未保存不能送审，在审／已批准的只读约束由最新服务端状态决定。
- 通知纯文本展示，结构化 target 经集中映射跳转，不执行通知内 HTML／URL，也不从事件名推断权限。仅预览不标已读；点击正文仅保存已读，详情入口按目标页面权限显示。点击详情先核对页面权限并保存已读，成功后再次核对权限再跳转，失败保留未读；无目标页面权限仍保留正文及标已读功能。后端仍判断记录访问资格，目标失去访问资格不回滚已读。
- 铃铛列表每页 10 条，打开／显式刷新取列表，每 30 秒只刷新未读数；退出／会话变化清除计时器、数据及旧读取资格。当前没有全读、推送或跨标签列表同步承诺。

受审内容由 `ApprovalSubjectEvidence` 统一装配 BOM、需求更正和结案的纯展示组件，只消费快照及显示引用；流程、处理记录与决定事件仍由审批详情容器负责。[开发演示页](../src/views/approval/demo/README.md)复用同一证据展示和详情弹窗，使用独立 mock 数据及内存状态，不调用业务 API。其路由仅在开发环境注册，不进入业务菜单或正式构建。

审批验收情景保留在 [README](../README.md#审批交互与验收场景)，不把实现接入当作已通过。

### 生产需求、收尾与库存

任务页与执行页复用管理员开工交互：读取当前配置与缺料预览，配置前提不足时展示服务端阻断原因；研发无需 BOM 的提示不能暗示无需手工需求。缺料仅提示且说明必填；提交携带预览版本，未知结果保留原请求与幂等键。任务开始与工序开始分开，普通工序按钮消费服务端资格。物料可分次办理，不展示短批授权入口，也不从执行阶段推断“物料操作已完成”。

收尾未批准、无在审时显示“撤回结束”，预览服务端给出的恢复阶段并填写原因；不提供任意状态选择。恢复后统一刷新任务、物料、工序及收尾资格，历史根存在不代表仍可办理产出或检验。操作保护现有草稿与未知请求；已发生的收尾事项不自动恢复。历史行动可展示任务进入／撤回，但逐项处理不提供任务操作项。

业务依据见[任务需求](../../api/src/modules/production/docs/database/demand-allocation-and-outbound.md)、[逐项收尾](../../api/src/modules/production/docs/database/production-termination.md)和 [Inventory](../../api/src/modules/inventory/README.md)。本文只保留编辑或显示时容易混淆的边界：

- 需求更正明确区分目标总量、新剩余量和整条替代链已领量；阻断说明逐项显示具体原因，不能把未分配说成未领完。更正中的行仍可显示活动缺口，不能因暂不可办理而删除事实。
- 初始需求配置的搜索及未选版筛选只改变展示，不能清除已选版本或采购提示；退出未确认修改须保护草稿。选版进度不代替最终提交资格。需求总览的“未领”读取需求事实剩余量，终态标为历史余量；未分配缺口仅作为活动需求的分配信息，采购关系不计入已领量。同任务刷新保留折叠状态，切换任务再初始化。
- 服务端保存的补料方案 `draft` 已是业务记录；重开先展示完整 BOM 版本及数量，明确进入编辑后才能修改，不能用空表单覆盖。人工追加的物料、版本、数量由人员明确选择。
- 新增任务的工单额度刷新失败保留输入并阻止提交，重核新额度不覆盖本次计划数量。工单号和任务批次号由服务端产生，界面不收取手填编号；未知创建结果不得因改表单自动另建。
- 收尾核对响应先验证结构及任务归属；JSON `null` 才表示无逐项收尾记录，须结合结束记录决定开始表单或只读结束快照。缺字段不是空记录；只读加载可关闭，写入中不可关闭。按钮“提前结束”只打开表单，确认开始命令才停止生产。
- 收尾事项各自保留备注。快捷处理逐项发送、每项刷新版本，失败即停，既有成功不回滚；未知结果只重试原项，不自动继续整组。依赖顺序以服务端阻断为准，不能并行发送制造部分成功后仍称整组完成。
- 产出与收尾编辑器分别持有草稿；审批中只读，驳回／撤回不撤销已发生的物料处理。损坏实核、质检引用和成品入库的额外约束见[成品专题](finished-inspections.md)。
- 物料供需每行是 `materialVariantId`，需求来源读取必须同时传该行 `itemId + materialVariantId`，不能用基础物料合计替代精确版本。成品的预留／可分配为“不适用”，不能因这些字段为零显示无库存。
- 退料说明长期可见、含警示标识：“退料不会产生或恢复需求”；不提供保留给原任务的策略。来源文字使用服务端 `sourceLabel/sourceDocumentNo`，不能根据缺少入库单号猜为期初库存。
- 展示区分执行报工、批准产出与实际入库；`finalOutput=null` 是尚无批准清单，批准零量正常显示零。历史／更正草稿不重复汇总，已终止任务释放计划额度不抹去其有效批准产出。

报废补产的显示只消费服务端投影：固定路线首工序起点不可伪装为可选；材料补料与产品补产数量分开，禁止用物料合计或 BOM 换算替代产品量。执行记录、员工任务及报工弹窗保留计划投入和授权摘要；三处的上限说明统一使用“报工上限 = 计划 + 已报废补产”，后者只消费已满足生效条件的授权，有值的待生效授权另列“待生效报废补产”，生效条件可通过提示查看。来源工序、建议路径和激活条件应可见，未履约授权不能计入统一上限。相邻工序数量差异只提示，补料生效不自动重开工序；已完成工序新增报工须先重新开工。不得逐工序请求或自行遍历报废记录重算。

执行记录的生产批次栏持有输入草稿与已应用筛选；点击查询或按 Enter 才应用去除首尾空白的关键字并回第一页，重置清除筛选并回第一页。表单阻止原生提交，Enter 只触发一次查询。翻页、刷新及标签激活使用已应用筛选，按批次号、工单号或产品搜索；每页固定 10 条，使用服务端分页，显示总数及当前页，不使用虚拟列表或下载全量。标题、搜索和分页固定，只有批次项独立滚动。

查询、重置、翻页和切换批次先保护现有报工草稿及批量写意图；取消确认不能改变生效筛选、页码或任务，失活或目标变化使等待中的导航失效。列表读取期间阻止开启新的写入编辑器；空结果清除当前读依据，失败清除旧列表、详情及完工检查并提供重试，同时保留已有草稿和目标 ID。重试成功重新读取当前详情。激活刷新保留目标，分页窗口缺项时按目标 ID 核验，不能自动换任务；总数缩小使当前页越界时读取最后有效页，读取失败归第一页，不让分页组件的自动页码校正触发额外查询。

执行记录将任务摘要与执行完工检查放在同一概览区，次要任务信息和完整检查可展开；任务身份及完成进度、主要完工结果或阻断和完工入口不随局部收纳隐藏。工序工具栏合并全部展开／收起与批量冲销，随右侧详情滚动到顶部后吸顶，任务概览随内容滚走；审批冻结和未知提交结果不放入可收纳正文。工具栏仅在当前详情滚动区定位，不遮挡批次侧栏，也不能越过页面级 Dialog 遮罩。工序支持多道展开，初次取得当前任务时优先展开第一道执行中工序，否则展开首道；同任务刷新、全部收起和缓存返回均保留人员选择，切换任务再初始化。收起的工序仍保留身份、状态、负责人以及正常、已报废、处理中和剩余额度摘要，上限组成和有值待生效报废补产继续提示；收起不改变服务端业务资格。

工序正文首次展开才挂载报工表并读取，后续收起保留表实例及分页，暂停并失效在途读取，再展开刷新当前页。“全部展开／全部收起”仅控制当前任务的工序正文，沿用单道展开的读取与保留规则，不改变工序内部数量核对、异常处理分组等局部展开选择，也不扫描历史分页。折叠不清除跨工序已选报工、编辑草稿或未知写意图；异常面板只隐藏分组正文，已打开的处理 Dialog 与正文并列保留。折叠只收纳展示，不隐含提交、放弃或追加选择。

执行记录与本人工序列表的工序摘要采用各自授权接口同一快照的额度分类展示分段条，不再显示直接已报／上限及百分比，也不在主摘要显示累计直接异常或历次异常。正常、已报废、处理中、已终止未恢复和剩余额度的分段只转换可信分类为视觉宽度，不合并外部返工读取、汇总报工分页或补差额；上限为零不绘制比例，分类不可解释时隐藏分段条，未知量显示待核对并保留原因，执行记录保留真实报废明细入口。员工列表复用纯展示数量摘要和上限组成，正常来源直接展示“直接正常 + 返工正常”，保留既有记录与纠错入口，不为展示新增管理端读取或搬入未接通的详情动作。已终止未恢复有值时独立展示，不归正常、报废或处理中。执行记录的处理中有值时可展开同快照的待审核、待返工和返工中明细及真实来源报工引用，零量弱化提示无待处理异常；已终止处置和已取消返工仍保留真实记录。执行记录正文仅保留直接正常与返工恢复的正常来源，前道正常数量及与前道的差值收进“数量核对”，首道不显示不适用核对；不再展示建议正常目标及目标差值。局部展开同任务刷新和缓存返回保留，换任务清空。

报废详情使用独立只读 Dialog，实际报废非零或分类待核对时均可打开。列表按当前批次及工序授权分页，默认 10 条并可选择 20、50 条；切页大小回首页，读取越界只修正当前窗口，失败清除旧列表并保留重试。展示真实事实、来源报工及异常处置、说明、记录人和时间，以及实际存在的补产授权与补料关联；仅有事实 ID 时明确标注，不伪造业务单号。来源报工打开与报废 Dialog 并列的报工追溯，关闭来源详情可继续原报废上下文。关闭、换任务、切目标、失活和销毁失效旧读取，缓存返回只刷新仍打开的目标；不按角色名称硬编码入口。

普通正常及异常新增共同消费服务端报工资格和剩余额度；额度为零或工序已完成时禁用入口并显示具体原因，已完成工序须先重新开工。既有记录纠错不要求重开，已批准结束任务的管理员纯正常历史补录继续使用独立历史资格，未批准收尾须先撤回结束再补报，不能成为执行期间绕过完工状态的入口。生产任务详情与生产追溯仍保留各自的直接已报进度，返工恢复不重复计入直接报工；比例及额度分布都不代表自动完工或质量放行。当前负责人不覆盖历史报工人，状态履历读取 Production 专有事实；批准时数量与当前数量分开展示。员工页直接展示普通工序列表，不保留本人返工 Tab 或专用返工请求；普通报工、状态动作、SOP、分页和记录纠错仍按本人工序资格办理。返工办理和详细追溯集中在管理端异常处置流程，批准时来源工序负责人仅作快照展示，不暗示该员工承担返修；具体权限由 Production 所有者规则维护。

报工弹窗从开窗冻结的同一授权工序快照展示正常、已报废、处理中和剩余额度、正常来源及上限组成；不再重复直接已报、百分比、建议目标或异常发生历史。管理员消费执行投影，员工消费既有本人任务投影，不额外请求管理端数据或跨读取混算；未知分类照实显示待核对及原因。摘要使用纯展示组件，详细报废和处理入口留在记录页，分类不纳入写依据判定或幂等请求；刷新后不能把最新分类与旧冻结额度拼接。本次最多紧邻数量输入，来自冻结余额及共享单次上限；未确认结果、关键依据失效和历史补录的必要提示继续可见。

正常与异常报工及正常数量更正持有原始文本草稿，输入、失焦、上下文刷新及缓存恢复均不自动截断到额度、取整或改成零。必填、正整数、共享单次报工上限与剩余额度错误在字段处显示，非法输入禁止提交，处理器再次核验后才转换为数值载荷；Enter 不能原生提交导致整页导航。关键依据变化保留输入并阻止旧依据提交，未知结果锁定原数量、版本和请求供安全重试，不按新额度改写原意图。

普通正常报工更正只提供一个正常数量输入和必填原因，明确填写替代记录的完整数量；零量取消使用全量冲销，不自动改为冲销意图。弹窗按冻结快照展示原量、更正后数量及额度影响，不提供正常／异常转换或异常来源输入。普通异常仅走待处置整笔驳回重报；返工完成一次提交正常与再次异常，系统分别生成非零结果事实，各自展示真实完成报工引用，均不提供普通更正、冲销或驳回入口。返工完成草稿与首次完整请求由页面级编辑器保留，只有确认成功后关闭；同任务读取失败、工序折叠或面板卸载不能丢失未知结果的原始数量、版本及备注。新提交检查当前办理资格，旧请求仅按原载荷和原键重放；关闭、换任务或离开页面须明确处理未保存草稿及未知结果。

工序状态提供正常开始、完成、重新开工及只读状态历史，不提供状态历史更正或撤销误开工；历史已有更正动作仍原样展示，不以移除入口删除或重写履历。

返工结果的对外名称统一为“返工正常／返工异常”，正常来源摘要、报工记录、返工办理和追溯引用共用该命名。报工历史分页加载，只读分类消费服务端 `sourceKind`，不能根据正向事实类型、数量或说明文字推断返工来源。冲销、被冲销原单、更正替代、来源异常和返工结果均消费服务端真实单号引用；仅有事实 ID 时不能伪造业务编号。展示数量的正负号不改变 API 绝对数量、写命令载荷或累计投影。依赖使记录只读时保留具体原因与查看处理过程入口，不重复堆放不可办理的更正／冲销按钮。

异常过程按来源报工分组；待审核或未完成返工默认展开，已完成处理默认收纳并保留处置、返工和恢复正常／再次异常数量摘要。批准报废只表示处置决定，不能显示为返工或补料已完成。同任务刷新保留人员明确选择的展开状态，切换任务清空。所有宿主的报工业务来源、结果引用和查看处理过程统一打开授权单条报工详情；本页与分页外采用相同入口，详情内引用继续切换同一查看目标，不自动展开、滚动或高亮背景工序，也不逐页扫齐历史。只读查看关闭、切换目标、失活或销毁时失效读取，返回缓存页只刷新仍打开的目标。相关详情与父弹窗并列挂载，边界见[路由规范](route-dialogs-and-tabs.md#1-挂载边界)。

同任务跨工序批量冲销保留明确选中的 ID；工序工具栏显示已选条数及工序数，未选择时弱化提示并禁用预览。选择清单通过独立页面级 Dialog 逐条查看、移除、清空或刷新依据，关闭清单不清除选择，切换任务先沿用导航保护。预览各工序净量及逐条阻断原因，修改选择后重新预览，一次提交原子结果；未知结果锁定选择及原始请求，在工具栏保留醒目的核对入口。同任务读取失败即使清空详情，仍保留该入口和原请求，核对及重试不能要求重新选择或生成新键。清单和批量办理 Dialog 与滚动区并列挂载，不因吸顶、折叠或详情消失而丢弃已有意图。阶段资格和原因消费服务端投影，后端仍独立鉴权；完整规则见 [Production 执行专题](../../api/src/modules/production/docs/database/execution-traceability-quality.md#cp-01-报工整改边界)，待验收见[整改清单](../../../docs/roadmap.md#cp-01报工数量解耦与管理员批量冲销整改)。

## 9. 验证重点

按[测试策略](../../../docs/testing-strategy.md)规定阶段验证：首次进入无重复候选请求；下拉只刷新自身；旧目标成功／失败／finally 不回写；失败保留草稿但阻止无依据提交；跨页实例独立；最小页面角色能读所需候选；未知结果不产生新键。验证状态集中在[路线图](../../../docs/roadmap.md)。
