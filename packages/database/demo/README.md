# 演示数据

本目录保存可重复加载的开发/演示样例数据，与 `seed` 中的运行基础数据严格分离。以下样例和准备命令用于人工核对；加载、数据准备或数量核对成功不代表用户验收或正式测试通过，剩余验收见[路线图](../../../docs/roadmap.md)。

需要在基础样例之上通过业务 API 准备采购金额、到货分页或来料质检分组场景时，使用[场景数据工具](../../../tools/demo/README.md)；工具不由本目录的 seed 运行器执行。

当前数据集包含：

- System：生产操作工、生产管理员、仓管、采购员和质检员五类职责角色及下表账号；
- 现场人员：[`003-personnel-demo.sql`](003-personnel-demo.sql) 补缺三名现场人员，独立于登录账号；不覆盖已有人员信息。保留字段的存储值不影响候选与登记资格，见 [Identity 人员目录](../../../apps/api/src/modules/identity/docs/database.md#110-personnel)。
- 人员候选：[`002-user-candidate-demo.sql`](002-user-candidate-demo.sql) 分别为尚无配置的工单负责人、任务负责人场景关联演示生产管理员角色；不进入 system seed 或 `db:init`。
- 仓储入口验收：`other-inbound-001`、`other-outbound-001` 只拥有首页及各自其他入库／出库的查看和办理权限，不授予外购／成品入库或生产领料权限；密码仍取 `DEMO_USER_PASSWORD`。
- Product：三个同名不同编码成品、两个同名基础物料 `m1.077.012` / `m1.077.013`、六个大小版本、仅关联基础物料的 BOM，以及可在创建批量任务时手动选择的独立工艺路线；
- 库存选择器样例：`demo-stock-multi` 含两个启用版本和一个停用版本；`demo-stock-meter` 与其同名、编码及单位不同；另含停用物料、只有停用版本的物料，以及启用／停用的两个同名成品。主数据只补缺，不覆盖已有状态或编辑。
- 入库归批样例：[`012-inbound-grouping-demo.sql`](012-inbound-grouping-demo.sql) 只补“演示共批供应商甲／乙”两条供应商主数据；采购实际收货及成品最终确认仍须通过业务流程准备，不在种子中伪造。
- 表格模板：[`015-business-template-demo.sql`](015-business-template-demo.sql) 补充规格参数、来料检验、独立交接事项、空行表格及停用样例，仅按系统内唯一名称补缺，不覆盖已有内容、版本或启停／删除状态；不依赖产品或物料样例。改名后重跑会补回原名样例。
- 采购跟进样例：[`013-purchase-order-status-demo.sql`](013-purchase-order-status-demo.sql) 提供草稿取消、三行结束／恢复、无到货整单取消三张独立备料采购单；只补缺失标记，不覆盖已办理状态，不生成到货、质检、正式分配或库存事实。
- Production：一张批量工单与一张研发工单，编号按[统一业务编号](../../../apps/api/docs/business-numbering.md)的工单类型分配；`demo-mass-001` / `demo-research-001` 放入外部订单号作为重复加载时的补缺标记。均为草稿，不自动下达、选版本、生成需求或库存流水。

两个“微带”物料位于“半成品 → 微带电路”分类，均为外购；分类名称不表示开放自产半成品链路。任务选版和研发提需按[任务规则](../../../apps/api/src/modules/production/docs/database/work-orders-and-batches.md)办理。

`admin` 账号不在演示数据中，仍由 `pnpm db:bootstrap-admin` 通过环境变量初始化。演示账号共用的密码不会写入 SQL，执行时由 `DEMO_USER_PASSWORD` 生成 bcrypt 哈希。

| 账号                           | 角色编码              | 验收职责                                                                               |
| ------------------------------ | --------------------- | -------------------------------------------------------------------------------------- |
| `operator-001`、`operator-002` | `operator`            | 扫码到站、随盘异常登记与处理                                                           |
| `production-001`               | `production`          | 产品资料、工单与任务、追踪卡工作台、用料分配、最终产出及需求更正审批；模板与库存仅查看 |
| `warehouse-001`                | `warehouse`           | 采购到货及作废、独立来料报告、实际收货、库存查询、出入库、退料、领料损耗和盘点                         |
| `procurement-001`              | `procurement`         | 供应商和采购单，不办理到货、质检或库存记账                                             |
| `quality-001`                  | `quality`             | 来料分组与独立进料检验报告、随盘异常和最终产出确认                               |
| `other-inbound-001`            | `demo-other-inbound`  | 仅办理其他入库                                                                         |
| `other-outbound-001`           | `demo-other-outbound` | 仅办理其他出库                                                                         |

完整初始化与演示数据加载：

```powershell
corepack pnpm db:init
$env:ALLOW_DEMO_SEED='1'
$env:DEMO_USER_PASSWORD='<至少 6 位的演示密码>'
corepack pnpm db:seed:demo
```

System 演示账号和权限按业务编码幂等更新，授权清单在 SQL 中显式列码，不使用权限前缀匹配。生产管理员的仓储授权只有 `warehouse:inventory:view`；出入库确认等库存操作由仓管办理。脚本整体覆盖上述角色的权限和上述账号的角色，包括已有同码 `quality` 角色，不保留手工调整后的配置。

工单负责人、任务负责人配置分别只补缺，初始均关联 `production` 演示角色，`production-001` 是合格样例；其他职责账号可用于核对不合格候选。重跑保留已有配置及版本，包括手工清空和软删除；角色／账号本身仍按上段恢复。恢复初始配置须重建开发库后加载 demo。候选资格与历史人员规则见 [Identity](../../../apps/api/src/modules/identity/docs/user-candidates.md)，本 SQL 不生成生产、库存、审批或业务操作日志。

Product 主数据、Procurement 供应商与 Production 草稿工单只补缺失样例，可以重复执行；不会覆盖已有样例的业务编辑、待审或已批准 BOM、已启用路线步骤或已下达工单。已有同名编码记录的停用/删除状态也不自动恢复。供应商名称作为补缺标识，手工改名后再次加载会补回原名称，不修改已改名记录。它不会进入 `db:init`、生产部署或 CI 自动执行链路。不得在生产数据库启用此门禁。

库存样例供人工核对两级选料、成品无版本、按单位汇总及仅其他单权限的入口。种子不生成出入库单、库存批次或流水；已有批次、共享新批次及出库场景须从其他入库界面保存草稿并确认后再办理，库存事实仍由 Inventory 命令产生。

工单样例与通用日计数在种子运行器的同一事务中写入，前缀读取共享映射；重复加载不再取号。初始计划日期为加载日及其后第七日。样例的外部订单号承担演示标记，修改后再次加载会视为样例缺失；它不是正式工单编号，也不用于推算序列。

结构迁移若要求空业务库，先按[迁移安全](../docs/migration-safety.md)完成重建和系统初始化，再显式加载 demo；样例加载不能绕过迁移守卫。

演示路线为装配、粘接、终检三站，按卡逐站扫码，末站选择启用现场人员显式确认并按剩余盘量形成产出；研发仍手填实际产出。办理方式见[执行规则](../../../apps/api/src/modules/production/docs/database/execution-traceability-quality.md)。

追踪卡完整场景通过[场景工具](../../../tools/demo/README.md#追踪卡工作台样例)经业务 API 准备，包含影响 3 件按返修 1 件与新增报废 2 件结算、重叠异常引用相同报废而不重扣、未结阻止流转、整盘报废、剩余量入库、独立改量和作废历史。SQL种子本身不生成执行、质量结论或库存事实。

## 规格书的人工验收准备

SQL demo 不伪造对象存储 locator，成品和精确版本初始规格书可以为空。加载 demo 后，通过成品编辑和精确物料版本的规格书入口上传真实文件，再核对下载、替换及并发冲突；在审成品仍遵守冻结规则。规格书的必填、文件类型与关联规则由 [Product](../../../apps/api/src/modules/product/docs/product-rules.md#成品与精确物料版本规格书)所有。

## 采购跟进状态的人工验收准备

完成 `db:init` 并显式加载 demo 后，可按采购备注中的标记定位以下样例，编号按统一业务编号的采购订单类型分配，不依赖固定业务 ID。

| 备注标记                        | 初始状态           | 人工验收用途                                                                                     |
| ------------------------------- | ------------------ | ------------------------------------------------------------------------------------------------ |
| `[demo-purchase-state-draft]`   | 草稿，三行         | 填原因直接取消；或先编辑并确认下单                                                               |
| `[demo-purchase-state-ordered]` | 已下单，三行进行中 | 逐行结束、最后一行使主单结束、恢复任一行使主单恢复、整单结束；核对主行状态及通用操作日志中的原因 |
| `[demo-purchase-state-cancel]`  | 已下单，三行进行中 | 无到货整单取消；也可先结束部分行再取消，核对已取消不可恢复及通用操作日志中的原因                 |

每张样例单只有一个主单供应商：草稿与结束／恢复样例为演示共批供应商甲，取消样例为乙。三行依次使用 `demo-stock-multi-v1-A` 10 根、`demo-stock-multi-v1-B` 15 根及 `demo-stock-meter-v1-A` 5 米，保持同单精确物料版本唯一。首行两项采购单位单价含超 JavaScript 安全精度的普通十进制字符串及尾零，税率为 13，新建样例总额按[金额契约](../../../apps/api/src/modules/procurement/docs/purchase-orders.md#明细采购单位单价)以含税单价乘采购量推算并标为 calculated；两项报价均保留。其他行无价格且总额／来源为空，供核对精度、空值及正式单金额更正。演示种子只补缺失样例，不回写既有总额。

样例只提供采购跟进场景，不包含实际到货。重新加载 demo 不恢复已取消／已结束的样例，也不覆盖采购编辑；标记位于备注开头，手动移除标记后再次加载会按缺失样例补建。需要再次验证可新建独立备料单。

## 采购金额补填与更正的人工验收准备

显式加载 demo 后，可使用采购跟进样例或另建独立备料采购，通过业务入口准备草稿、已下单、已结束和已取消状态；不直接改业务表或生成到货、库存事实。分别填写只有含税单价、只有无税单价、两价并存、手填总额为零、长十进制及舍入边界等输入，再核对补填／清空单价、修改税率和清空手填总额后的金额与来源。

正式单通过“查看/编辑”填写原因进行单行或多行更正，并在操作日志核对前后值。字段、优先级、精度及更正资格以[采购金额契约](../../../apps/api/src/modules/procurement/docs/purchase-orders.md#明细采购单位单价)为准；正式测试缺口仍由[路线图](../../../docs/roadmap.md)维护。

## 仓库简化场景的人工验收准备

[016-warehouse-chamber-demo.sql](016-warehouse-chamber-demo.sql)只补腔体物料、精确版本及分类。实际采购、到货、独立报告和库存通过[场景工具](../../../tools/demo/README.md)的 prepare-warehouse-simplification-demo.mjs 准备，不由 SQL seed 伪造。

样例覆盖采购20、全检21合格与1不合格、免费赠送后实际入21；额外付费先补单、先入21后补报告；在到货行独立登记其他处理而不调用入库接口；未检查未入库的质量补发约定；保留一张待人工办理到货；跨供应商4与6共入一个新库存批次。检查记录不提供放行门槛，补单不会重复增加原到货库存，处理说明不表示线下执行完成。

仓管演示账号同时具备独立检查与分组权限，便于兼岗验收；采购员仍只办理采购。真实职责配置由用户决定，演示授权不扩大后端接口权限。具体场景标记、重复执行及中断边界见工具说明。

### 共用本次新批次

跨供应商共批样例保留逐来源明细；同精确版本及单位可明确共用本次新批次，不同版本不能加入相同组。其他入库仍可用 demo-stock-multi 两版本核对，成品按追踪卡终检一次确认，不复用采购流程。

### 到货作废及历史

人工另建未实际入库且没有非取消补单依赖的到货，登记报告或其他处理说明后仍可作废。作废后历史报告和说明保留，后续收货、检查和新补单拒绝；已有实际入库或有效补单阻断作废。采购状态继续独立人工跟进。并发及失败回滚的正式覆盖等待测试阶段。

### 到货查询与来源关联

到货目录直接按到货单分页，展开读取整张到货的完整物料明细；采购单号只作为来源及筛选信息，检验分组不合并报告来源。核对同一采购下多次到货分别出现、物料关键词只命中对应到货、跨页已选、精确报告定位、历史来源及无质检时入库。100行边界、深页与迟到响应仍须在正式测试阶段恢复覆盖。

## BOM 审批演示

演示成品的 BOM 默认 `draft`，不生成审批配置、申请或批准记录。生产管理员演示角色具备审批查看和处理权限；管理员可在审批流程配置页选择“生产管理员 → 系统管理员”两级，使用 `production-001` 和 `.env` 初始化的管理员分别处理。流程配置权限仍由系统管理员管理，演示操作工不获得审批资格。

重建库后先 `pnpm db:init`，再显式运行 `ALLOW_DEMO_SEED=1 DEMO_USER_PASSWORD='<演示密码>' pnpm db:seed:demo`。工单仍是草稿；批量工单下达后，须先在产品页提交 BOM 并完成审批，才能创建批量任务；研发任务不要求 BOM 审批。

重复加载 demo 仅补缺失的草稿 BOM，锁成品聚合根并递增实际变更的 version；待审、已批准和软删除成品不会因此变动。不写入 `products.default_route_id`，工艺路线由创建任务的人员选择。System 演示账号与授权仍按本脚本重置，不用于保留用户手工调整后的角色分配。
